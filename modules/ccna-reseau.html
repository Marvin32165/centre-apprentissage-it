Ce que tu sauras faire à la fin

  • Configurer un routeur ou un switch Cisco de zéro : nom, mots de passe hachés, SSH v2 seul, sauvegarde.
  • Créer des VLAN, des ports access (avec VLAN voix) et des trunks propres, puis router entre VLAN par sous-interfaces ou SVI.
  • Distribuer le DHCP par VLAN ou le relayer, et suivre un plan VLSM avec ses conventions.
  • Faire tourner OSPF, désigner la racine spanning tree, agréger deux liens en EtherChannel et doubler la passerelle avec HSRP.
  • Sortir sur Internet en PAT, publier un serveur, filtrer avec des ACL standard et étendues.
  • Prouver chaque étape avec la commande show qui convient, et lire ce qu'elle répond quand ça ne marche pas.

Prérequis : Réseau : les bases et Subnetting. Le module Dépannage réseau aide beaucoup pour l'exercice final.

01

Le labo et l'IOS en main

Tout le module suit la topologie de l'exercice final du cours : un faux fournisseur d'accès, deux routeurs de bordure redondants, deux switchs de cœur et deux switchs d'accès, sur le plan 10.2.0.0/16. On la construit dans Packet Tracer, brique par brique, chapitre par chapitre.

R-EDGE1203.0.113.2/30Routeur de bordure principal : router-on-a-stick, HSRP actif, NAT, OSPF

Les réflexes qui font gagner du temps

  • ? liste ce qui est possible à cet endroit ; Tab complète ; les commandes s'abrègent tant qu'elles restent uniques (conf t, sh ip int br).
  • do show … lance un show sans quitter le mode configuration.
  • Ctrl+Z ou end revient en mode privilégié ; exit remonte d'un niveau.
  • no devant une commande l'annule (no shutdown, no ip address).
  • Deux configurations : la running-config (en mémoire vive, active) et la startup-config (en NVRAM, rechargée au démarrage). Sans copy running-config startup-config (ou write), tout est perdu au redémarrage.

À toi de taper

Depuis le mode configuration d'interface, affiche le résumé des interfaces sans quitter ce mode.

Voir la solution

do show ip interface brief (abrégé do sh ip int br). Sans do, l'IOS refuse : show n'existe pas en mode configuration.

À retenir

Quatre modes (>, #, (config)#, (config-if)#), ? et Tab pour s'orienter, do pour un show en configuration, et write avant de partir : la running-config ne survit pas à un redémarrage.

02

Configuration de base et SSH

Chaque équipement reçoit la même séquence de départ : un nom, des mots de passe chiffrés, une bannière, des lignes d'accès verrouillées, puis SSH à la place de Telnet. C'est la première chose qu'on vérifie à un examen pratique.

Cisco IOS — séquence de base (tout équipement)
enable
configure terminal
 hostname R-EDGE1
 no ip domain-lookup                  ! une faute de frappe ne lance plus de recherche DNS
 banner motd # Acces restreint - R-EDGE1 #
 enable secret <mot-de-passe>         ! mot de passe du mode privilégié, haché
 service password-encryption          ! masque les mots de passe restés en clair (type 7)
 security passwords min-length 10
 username admin privilege 15 secret <mot-de-passe>
 line console 0
  login local                         ! authentification par le compte local
  exec-timeout 5 0                    ! déconnexion après 5 min d'inactivité
Cisco IOS — SSH version 2, sans Telnet
ip domain-name ccna.lab               ! nécessaire pour générer les clés
crypto key generate rsa modulus 2048
ip ssh version 2
line vty 0 15
 login local
 transport input ssh                  ! refuse Telnet
end
write

Piège

service password-encryption ne chiffre pas vraiment : le type 7 se décode en une seconde avec des outils en ligne. Il évite seulement la lecture par-dessus l'épaule. Ce qui protège, c'est secret (haché) au lieu de password.

Vérifier

SSH est-il actif, et qui est connecté ?

Cisco IOS
R-EDGE1# show ip ssh
R-EDGE1# show users

Sortie attendue

SSH Enabled - version 2.0
Authentication methods:publickey,keyboard-interactive,password
Authentication timeout: 120 secs; Authentication retries: 3

SSH Disabled : il manque le nom de domaine ou la clé RSA (crypto key generate rsa). La connexion est refusée alors que SSH est actif : vérifier login local et le compte username sur les lignes VTY.

À toi de taper

Écris la commande qui n'autorise que SSH sur les lignes VTY (tu es déjà dans line vty 0 15).

Voir la solution

transport input ssh. Sans cette ligne, Telnet reste accepté et les identifiants circulent en clair.

À retenir

Nom, enable secret, compte local en secret, bannière, exec-timeout, SSH v2 avec clé 2048 bits et transport input ssh : la base de tout équipement, avant même le premier VLAN.

03

VLAN, ports access et trunks

Les VLAN découpent les switchs en réseaux séparés (le principe est expliqué dans Réseau : les bases). Sur Cisco, il faut les créer, ranger chaque port d'accès dans le sien, et monter des trunks propres entre équipements.

Cisco IOS — SW1 : VLAN, accès, voix, trunk
vlan 10
 name V10_Host
vlan 50
 name V50_VoIP
vlan 999
 name Native                          ! VLAN natif inutilisé : rien n'y circule
interface range fa0/1-20
 switchport mode access
 switchport access vlan 10
 switchport voice vlan 50             ! le téléphone marque sa voix en VLAN 50, le PC derrière reste en 10
 spanning-tree portfast
interface gi0/1
 switchport mode trunk
 switchport trunk native vlan 999
 switchport trunk allowed vlan 10,20,30,40,50,60,70,80,90,99,100,110,120
 switchport nonegotiate               ! pas de DTP : le trunk est voulu, pas négocié

Le VLAN natif

Sur un trunk 802.1Q, les trames du VLAN natif passent sans étiquette. Par défaut c'est le VLAN 1. On le déplace vers un VLAN vide (ici 999), identique des deux côtés : un désaccord est signalé par CDP (NATIVE_VLAN_MISMATCH) et mélange deux VLAN.

La liste autorisée

allowed vlan limite ce qui traverse le trunk. Attention : switchport trunk allowed vlan 30 remplace la liste ; pour ajouter, c'est allowed vlan add 30. Une erreur classique qui coupe tous les autres VLAN.

Vérifier

Chaque port est-il dans le bon VLAN, et le trunk transporte-t-il tout ?

Cisco IOS
SW1# show vlan brief
SW1# show interfaces trunk

Sortie attendue

Port        Mode         Encapsulation  Status        Native vlan
Gi0/1       on           802.1q         trunking      999

Port        Vlans allowed and active in management domain
Gi0/1       10,20,30,40,50,60,70,80,90,99,100,110,120

Un VLAN absent de allowed and active : il n'existe pas sur ce switch (vlan 30) ou n'est pas dans la liste autorisée. Un port qui n'apparaît pas dans show vlan brief est un trunk — normal.

À toi de taper

Le trunk gi0/1 transporte déjà les VLAN 10 et 20. Ajoute le VLAN 30 sans retirer les autres (tu es dans interface gi0/1).

Voir la solution

switchport trunk allowed vlan add 30. Sans add, la liste deviendrait « 30 » seul, et les VLAN 10 et 20 seraient coupés sur ce lien.

À retenir

Port access : un VLAN (+ un VLAN voix éventuel). Port trunk : VLAN natif inutilisé et identique des deux côtés, liste autorisée explicite, DTP coupé. Et toujours add pour compléter une liste.

04

Routage inter-VLAN : router-on-a-stick et SVI

Deux VLAN ne se parlent pas sans routeur. Deux méthodes : découper une interface de routeur en sous-interfaces (le router-on-a-stick du cours), ou faire router un switch de niveau 3 avec des interfaces VLAN (SVI).

Cisco IOS — R-EDGE1 : une sous-interface par VLAN
interface g0/0
 no ip address
 no shutdown                          ! l'interface physique porte les sous-interfaces
interface g0/0.10
 description V10-Host
 encapsulation dot1q 10               ! lie la sous-interface au VLAN 10
 ip address 10.2.112.1 255.255.248.0
interface g0/0.999
 encapsulation dot1q 999 native       ! le VLAN natif du trunk, côté routeur
Cisco IOS — la même chose sur un switch de niveau 3 (SVI)
ip routing                           ! sans elle, le switch L3 ne route pas
interface vlan 10
 ip address 10.2.112.1 255.255.248.0
 no shutdown
interface vlan 20
 ip address 10.2.129.1 255.255.255.128
 no shutdown

Router-on-a-stick

Simple, un seul lien suffit. Mais tout le trafic entre VLAN monte et redescend par ce lien : il devient le goulot. Idéal en labo et en petite agence.

Switch de niveau 3

Le routage se fait dans le switch, à la vitesse du matériel. C'est la norme en entreprise. Une SVI n'est up que si son VLAN existe et a au moins un port actif.

Vérifier

Les sous-interfaces sont-elles montées, et le routeur connaît-il les réseaux ?

Cisco IOS
R-EDGE1# show ip interface brief | exclude unassigned
R-EDGE1# show ip route connected

Sortie attendue

GigabitEthernet0/0.10  10.2.112.1  YES manual up  up
GigabitEthernet0/0.20  10.2.129.1  YES manual up  up
C    10.2.112.0/21 is directly connected, GigabitEthernet0/0.10

Le PC ne joint pas sa passerelle : vérifier que le port du switch vers le routeur est bien en trunk, que le VLAN y est autorisé, et que encapsulation dot1q porte le bon numéro.

À retenir

La passerelle d'un VLAN, c'est l'adresse de sa sous-interface (encapsulation dot1q N) ou de sa SVI (interface vlan N + ip routing). Le lien vers le routeur doit être un trunk qui transporte ce VLAN.

05

DHCP sur Cisco, et le relais

Un routeur Cisco peut distribuer les adresses de chaque VLAN. La règle d'or : exclure d'abord tout ce qui est fixe. Et quand le serveur DHCP est ailleurs, l'interface relaie avec ip helper-address.

Cisco IOS — VLAN 10, comme dans l'exercice final
ip dhcp excluded-address 10.2.112.1 10.2.112.50   ! routeurs, serveurs, imprimantes en fixe
ip dhcp excluded-address 10.2.119.254             ! l'adresse virtuelle HSRP (chapitre 10)
ip dhcp pool V10_Host
 network 10.2.112.0 255.255.248.0
 default-router 10.2.119.254          ! la passerelle = l'adresse virtuelle, pas celle d'un routeur
 dns-server 10.2.120.10                ! serveur DNS du VLAN Serveurs
 domain-name host.marsu2.local
 lease 7                              ! bail de 7 jours

Avec un serveur DHCP central (par exemple un Windows Server dans le VLAN 70), on ne crée pas de pool sur le routeur : on pose un relais sur chaque sous-interface, qui transforme le broadcast DHCP en unicast vers le serveur.

Cisco IOS — relais vers un serveur DHCP Windows
interface g0/0.10
ip helper-address 10.2.120.10

Vérifier

Les baux sont-ils distribués ?

Cisco IOS
R-EDGE1# show ip dhcp binding
R-EDGE1# show ip dhcp pool V10_Host

Sortie attendue

IP address       Client-ID/              Lease expiration        Type
                 Hardware address
10.2.112.51      0100.50a1.2b3c.4d       Oct 13 2026 09:12 AM    Automatic

Aucun bail : le PC est-il dans le bon VLAN, le trunk transporte-t-il ce VLAN, la sous-interface est-elle up ? Un poste qui reçoit une adresse d'un autre réseau : un second serveur DHCP répond sur ce VLAN (une box branchée par erreur).

À toi de taper

Exclus du DHCP les adresses 10.2.120.1 à 10.2.120.50.

Voir la solution

ip dhcp excluded-address 10.2.120.1 10.2.120.50 — en mode configuration globale, avant de créer le pool, pour qu'aucune adresse fixe ne soit distribuée entre-temps.

À retenir

Exclusions d'abord, pool ensuite ; default-router = l'adresse virtuelle HSRP quand il y en a une. Serveur DHCP ailleurs : ip helper-address sur l'interface du VLAN.

07

Routes statiques, par défaut et flottantes

Un routeur ne connaît que ses réseaux directement connectés. Le reste, on le lui apprend : à la main (statique) ou par un protocole (chapitre suivant). Une route statique bien choisie reste la meilleure réponse pour la sortie vers Internet.

Cisco IOS — R-EDGE1 et R-INTERNET
! Sur R-EDGE1 : tout ce qui n'est pas connu part vers le FAI
ip route 0.0.0.0 0.0.0.0 203.0.113.1 name DEFAULT-ISP
! Route flottante : distance 200, n'apparaît que si la première disparaît
ip route 0.0.0.0 0.0.0.0 10.2.104.2 200

! Sur R-INTERNET : le chemin du retour vers le LAN, avec un secours
ip route 10.2.0.0 255.255.0.0 203.0.113.2 name LAN-VIA-REDGE1
ip route 10.2.0.0 255.255.0.0 203.0.113.6 10 name LAN-VIA-REDGE2-BACKUP

La distance administrative

Quand deux sources proposent le même réseau avec le même préfixe, le routeur garde celle en qui il a le plus confiance : la plus petite distance administrative (AD).

SourceAD
Directement connecté0

Route « flottante » de secourschoisie : 10, 200…

Une route flottante est une statique dont on a monté exprès la distance : elle reste cachée tant que la route principale existe, et n'entre dans la table que si celle-ci disparaît (interface tombée).

Vérifier

Quelle route par défaut est active ?

Cisco IOS
R-EDGE1# show ip route static

Sortie attendue

Gateway of last resort is 203.0.113.1 to network 0.0.0.0
S*    0.0.0.0/0 [1/0] via 203.0.113.1

La flottante ([200/0]) ne doit apparaître que lorsque g0/2 est coupée — teste-le avec shutdown sur l'interface WAN, puis no shutdown.

À toi de taper

Crée une route par défaut vers 203.0.113.1.

Voir la solution

ip route 0.0.0.0 0.0.0.0 203.0.113.1 : réseau 0.0.0.0, masque 0.0.0.0 = « n'importe quelle destination ».

À retenir

Statique : ip route réseau masque prochain-saut [distance]. Route par défaut : 0.0.0.0 0.0.0.0. Une distance plus haute fait une route de secours flottante. Et chaque aller a besoin de son retour.

08

OSPF : le routage dynamique

Avec plus de quelques routeurs, les routes statiques deviennent ingérables. OSPF (RFC 2328) fait se découvrir les routeurs, s'échanger l'état de leurs liens, et recalculer seul les chemins quand un lien tombe.

Comment OSPF travaille

1
Voisinage

Les routeurs s'envoient des Hello (toutes les 10 s sur Ethernet ; voisin déclaré mort après 40 s). Pour devenir voisins, ils doivent avoir la même aire, le même réseau et masque, les mêmes minuteurs, la même authentification — et des MTU identiques.

2
Synchronisation

Ils échangent leurs bases d'état de liens (LSA) jusqu'à avoir tous la même carte de l'aire : état FULL.

3
Calcul

Chacun calcule le plus court chemin (algorithme de Dijkstra) d'après le coût : bande passante de référence ÷ bande passante du lien.

Cisco IOS — R-EDGE1
router ospf 1
router-id 1.1.1.1                    ! identité fixe, sinon IOS la choisit seul
auto-cost reference-bandwidth 10000  ! en Mb/s : 10 Gb/s, pour distinguer 1G de 10G
passive-interface default            ! pas de Hello partout…
no passive-interface g0/2            ! …seulement là où il y a un voisin
network 10.2.0.0 0.0.255.255 area 0  ! masque générique (wildcard)
network 203.0.113.0 0.0.0.3 area 0
default-information originate        ! annonce la route par défaut aux autres

Le masque générique

network utilise un masque générique (wildcard) : l'inverse du masque. 255.255.255.252 → 0.0.0.3 ; 255.255.0.0 → 0.0.255.255. Calcul : 255 − chaque octet du masque. Les mêmes masques servent dans les ACL.

État du voisinCe que ça veut dire
FULLBases synchronisées : tout va bien
2WAY/DROTHERNormal sur un réseau Ethernet à plusieurs routeurs : seuls DR et BDR deviennent FULL avec tout le monde
INITHello reçu, mais le voisin ne nous voit pas : souvent un filtrage dans un sens
EXSTART / EXCHANGE bloquéMTU différent des deux côtés
Aucun voisinInterface passive, aire, masque, minuteurs ou authentification différents

Les voisins sont-ils là, et les routes apprises ?

R-EDGE1# show ip route ospf

Pas de voisin : comparer show ip ospf interface g0/0.99 des deux côtés (aire, Hello/Dead, réseau) et vérifier que l'interface n'est pas passive.

Exercice — masques génériques

Écris l'instruction network qui met dans l'aire 0 : (a) le lien 10.0.0.0/30 ; (b) le réseau 172.16.32.0/20 ; (c) uniquement l'interface 192.168.1.1.

Afficher la correction

(a) network 10.0.0.0 0.0.0.3 area 0. (b) /20 = 255.255.240.0 → wildcard 0.0.15.255 : network 172.16.32.0 0.0.15.255 area 0. (c) network 192.168.1.1 0.0.0.0 area 0 — un masque générique nul vise exactement une adresse.

À retenir

OSPF : router-id fixe, network … wildcard area 0, interfaces passives par défaut, et show ip ospf neighbor doit afficher FULL (ou 2WAY/DROTHER). Pas de voisin = aire, masque, minuteurs, MTU ou interface passive.

09

Spanning tree et EtherChannel

Deux switchs de cœur reliés par deux câbles, c'est de la redondance… et une boucle. Le spanning tree bloque les liens en trop ; l'EtherChannel fait des deux câbles un seul lien logique, plus large, sans rien bloquer.

Choisir la racine, ne pas la subir

Le spanning tree élit un switch racine (le plus petit identifiant : priorité, puis MAC) et bloque les ports qui créeraient une boucle. Laissé par défaut, c'est le switch à la plus petite MAC qui gagne — souvent le plus vieux. On désigne donc la racine et sa remplaçante. Le détail de l'élection, PortFast et BPDU Guard sont dans Cisco sécurité.

Cisco IOS — SW-CORE1 (racine) et SW-CORE2 (secours)
spanning-tree mode rapid-pvst        ! RSTP, un arbre par VLAN, convergence en secondes
spanning-tree vlan 10,20,30,99 root primary     ! sur SW-CORE1 : priorité 24576
spanning-tree vlan 10,20,30,99 root secondary   ! sur SW-CORE2 : priorité 28672

EtherChannel avec LACP

Cisco IOS — SW-CORE1, Po1 vers SW-CORE2
interface range fa0/23-24
 shutdown
 channel-group 1 mode active          ! LACP : négocie avec l'autre côté
 no shutdown
interface port-channel 1
 switchport mode trunk                ! on configure le lien logique, pas les ports
 switchport trunk native vlan 999
 switchport trunk allowed vlan 10,20,30,40,50,60,70,80,90,99,100,110,120
ModeProtocoleForme un canal avec
activeLACP (IEEE 802.3ad, standard)active ou passive
passiveLACPactive seulement
desirable / autoPAgP (Cisco)desirable ou auto / desirable
onaucunon seulement — sans contrôle, risqué

Les ports d'un même canal doivent être identiques : vitesse, duplex, mode (access/trunk), VLAN autorisés et natif. Sinon le port reste à l'écart (s = suspendu).

Vérifier

Le canal est-il formé, et qui est la racine ?

SW-CORE1# show spanning-tree vlan 10

(SD) = canal en panne ; un port en (I) ou (s) n'a pas pu rejoindre le canal : comparer les configurations des ports des deux côtés.

À retenir

On désigne la racine (root primary / secondary) au lieu de la subir. EtherChannel LACP en active, configuration sur le port-channel, ports membres identiques, et show etherchannel summary doit afficher SU et des ports P.

10

HSRP : une passerelle qui ne tombe pas

Si l'unique routeur d'un VLAN tombe, tous les postes perdent leur passerelle. HSRP (protocole Cisco) fait partager à deux routeurs une adresse IP virtuelle : les postes l'utilisent comme passerelle, et le routeur de secours la reprend en quelques secondes.

Cisco IOS — R-EDGE1 (actif), VLAN 10
interface g0/0.10
 ip address 10.2.112.1 255.255.248.0
 standby version 2
 standby 10 ip 10.2.119.254           ! l'adresse virtuelle = passerelle des postes
 standby 10 priority 110              ! 100 par défaut : la plus haute devient active
 standby 10 preempt                   ! reprend la main quand il revient
 standby 10 track 1 decrement 20      ! perd 20 de priorité si le lien WAN tombe
track 1 interface g0/2 line-protocol

R-EDGE2 porte la même configuration avec 10.2.112.2 et la priorité par défaut (100). Le jeu du suivi (track) : si la fibre de R-EDGE1 tombe, sa priorité passe à 90 ; avec preempt configuré des deux côtés, R-EDGE2 (100) devient actif — les postes sortent par la fibre qui marche.

RéglagePar défautPourquoi le changer
Priorité100Choisir lequel est actif

Exercice — la bascule

R-EDGE1 (priorité 110, preempt, track −20 sur g0/2) et R-EDGE2 (priorité 100, preempt). La fibre de R-EDGE1 tombe, puis revient. Qui est actif à chaque moment ?

Afficher la correction

Au départ : R-EDGE1 (110 > 100). Fibre coupée : R-EDGE1 passe à 90, R-EDGE2 (100) prend la main grâce à son preempt. Fibre rétablie : R-EDGE1 remonte à 110 et, avec son propre preempt, redevient actif (après le délai de preempt delay s'il est configuré).

À retenir

HSRP : une adresse virtuelle comme passerelle (celle que distribue le DHCP), une priorité pour choisir l'actif, preempt pour reprendre la main, track pour basculer quand le lien de sortie tombe.

NAT : PAT et publication d'un serveur

Le plan 10.2.0.0/16 est privé. Pour sortir, R-EDGE1 traduit toutes ces adresses en son adresse publique (PAT) ; pour publier le serveur web de la DMZ, il redirige les ports 80 et 443 vers lui (NAT statique).

Cisco IOS — R-EDGE1
interface g0/0.10
 ip nat inside                        ! côté LAN (à poser sur chaque sous-interface)
interface g0/2
 ip nat outside                       ! côté Internet
ip access-list standard ACL-NAT
 permit 10.2.0.0 0.0.255.255          ! ce qui a le droit d'être traduit
ip nat inside source list ACL-NAT interface g0/2 overload        ! PAT
ip nat inside source static tcp 10.2.126.10 80 interface g0/2 80  ! publication
ip nat inside source static tcp 10.2.126.10 443 interface g0/2 443

Vérifier

Les traductions se font-elles ?

Cisco IOS

R-EDGE1# show ip nat statistics

À toi de taper

Écris la ligne de PAT qui traduit tout ce qu'autorise l'ACL ACL-NAT derrière l'adresse de g0/2.

Voir la solution

ip nat inside source list ACL-NAT interface g0/2 overload — overload, c'est le PAT : plusieurs adresses internes derrière une seule, distinguées par le port.

À retenir

ip nat inside / outside sur les interfaces, une ACL qui dit qui est traduit, overload pour le PAT, une ligne static tcp par port publié. show ip nat translations prouve que ça marche.

12

ACL standard et étendues

Une ACL est une liste ordonnée de règles permit/deny, lue de haut en bas : la première qui correspond décide, et un deny any invisible termine toute liste. Le module Cisco sécurité détaille le dépannage ; ici, les ACL du labo.

Standard (1–99, nommée)

Ne regarde que l'adresse source. Se place près de la destination (sinon elle bloque trop large). Usage type : qui peut se connecter en SSH (access-class).

Étendue (100–199, nommée)

Regarde source, destination, protocole et ports. Se place près de la source, pour jeter le trafic avant qu'il traverse le réseau.

Cisco IOS — les trois ACL de l'exercice final
! 1. SSH vers les équipements, depuis le VLAN Management seulement
ip access-list standard ACL-VTY-MGMT
 permit 10.2.104.0 0.0.7.255
 deny any log
line vty 0 15
 access-class ACL-VTY-MGMT in

! 2. Le VLAN Management n'ouvre que SSH et ping vers le reste du LAN
ip access-list extended ACL-MGMT-ISOL
 permit tcp 10.2.104.0 0.0.7.255 any eq 22
 permit icmp 10.2.104.0 0.0.7.255 any
 deny ip 10.2.104.0 0.0.7.255 10.2.0.0 0.0.255.255
 permit ip any any                    ! Internet reste autorisé
interface g0/0.99
 ip access-group ACL-MGMT-ISOL in

! 3. Le Wi-Fi invités ne fait ni FTP, ni SSH, ni Telnet, ni SNMP
ip access-list extended ACL-GUEST
 deny tcp any any range 20 23
 deny udp any any range 161 162
 permit ip any any
interface g0/0.40
 ip access-group ACL-GUEST in

in ou out ?

Le sens se lit depuis le routeur : in = le trafic qui entre dans le routeur par cette interface. Une ACL posée in sur la sous-interface du VLAN 40 filtre donc ce que les invités envoient.

Vérifier

L'ACL fait-elle ce qu'on croit ?

Cisco IOS
R-EDGE1# show access-lists ACL-GUEST

Sortie attendue

Extended IP access list ACL-GUEST
10 deny tcp any any range ftp-data telnet (12 matches)
20 deny udp any any range snmp snmptrap
30 permit ip any any (5821 matches)

Le compteur d'une règle ne bouge pas pendant le test : elle n'est jamais atteinte (une règle plus haute répond avant, ou l'ACL est posée sur la mauvaise interface ou dans le mauvais sens). Les numéros de ligne (10, 20…) permettent d'insérer une règle entre deux : 15 deny ….

Exercice — écrire une ACL étendue

Les invités (VLAN 40, 10.2.124.0/23) ne doivent joindre aucun réseau interne 10.2.0.0/16, mais garder Internet, et le DNS public. Écris l'ACL nommée et dis où la poser.

Afficher la correction

ip access-list extended ACL-GUEST-ISOL, puis deny ip 10.2.124.0 0.0.1.255 10.2.0.0 0.0.255.255 et permit ip any any. Posée in sur g0/0.40 (près de la source). Le DNS public passe par la dernière ligne ; si le DNS était interne, il faudrait une ligne permit udp 10.2.124.0 0.0.1.255 host 10.2.120.10 eq 53 avant le deny.

À retenir

Lue de haut en bas, première correspondance gagnante, deny any implicite. Standard près de la destination, étendue près de la source ; in/out vus du routeur ; les compteurs de show access-lists pour prouver.

Les services d'administration : NTP, Syslog, CDP, SNMP

Un réseau en production doit avoir l'heure juste, garder ses journaux ailleurs que dans la mémoire des équipements, et se laisser cartographier et superviser.

Cisco IOS — R-EDGE1
ntp server 10.2.104.10                       ! heure commune à tout le réseau
service timestamps log datetime msec         ! horodater les journaux
logging host 10.2.120.100                    ! envoyer les journaux à un serveur Syslog
logging trap informational                   ! niveau 6 et plus grave
lldp run                                     ! LLDP (standard) en plus de CDP (Cisco, actif par défaut)
Niveau SyslogNomExemple
0–2emergencies, alerts, criticalL'équipement est inutilisable
3errorsErreur sur une interface
4warningsCDP : VLAN natif différent
5notificationsInterface qui monte ou descend (%LINEPROTO-5-UPDOWN)
6informationalACL avec log
7debuggingSortie des commandes debug

Pourquoi l'heure compte : sans NTP, les journaux de deux équipements ne se comparent pas, les certificats et Kerberos échouent. Et SNMP (UDP 161, traps 162) permet à un superviseur comme Zabbix (module Supervision) d'interroger les compteurs ; en production on préfère SNMPv3, authentifié et chiffré.

Clock is unsynchronized : le serveur NTP n'est pas joignable (route, ACL) ou n'est pas lui-même synchronisé. Patience aussi : la première synchronisation prend quelques minutes.

À retenir

NTP pour une heure commune, horodatage et Syslog pour des journaux exploitables hors de l'équipement, CDP/LLDP pour voir le câblage réel, SNMP (v3 de préférence) pour la supervision.

IPv6 sur Cisco

Les bases d'IPv6 sont dans Réseau : les bases. Sur un routeur Cisco, il faut d'abord autoriser le routage IPv6, puis donner une adresse à chaque interface ; les postes s'autoconfigurent à partir de l'annonce du routeur.

Cisco IOS — R-EDGE1, VLAN 30 en DHCPv6 sans état (comme dans le labo)
ipv6 unicast-routing                 ! sans elle, le routeur ne route ni n'annonce rien
ipv6 dhcp pool VLAN30-V6
 dns-server 2001:db8:cafe:70::10
 domain-name ccna.lab
interface g0/0.30
 ipv6 address 2001:db8:cafe:30::1/64
 ipv6 nd other-config-flag            ! « adresse par SLAAC, le reste (DNS) par DHCPv6 »
 ipv6 dhcp server VLAN30-V6
ipv6 route ::/0 2001:db8:ffff::1     ! route par défaut IPv6
Mode de configuration des postesAnnonce du routeurAdresseDNS
SLAAC seuldrapeaux M=0, O=0SLAACoption RDNSS de l'annonce (si supportée)
DHCPv6 sans étatO=1 (other-config-flag)SLAACDHCPv6
DHCPv6 avec étatM=1 (managed-config-flag)DHCPv6DHCPv6

Les interfaces ont-elles leurs adresses IPv6 ?

À retenir

Exercice final : la topologie d'entreprise

Le capstone du cours : tout ce qui précède, sur six équipements, à refaire de zéro dans Packet Tracer. L'ordre compte : chaque étape s'appuie sur la précédente et se vérifie avant de passer à la suite.

Lab guidé

Monter la topologie complète dans Packet Tracer

Objectif : un réseau d'entreprise redondant, segmenté, qui sort sur Internet et se vérifie point par pointPoint de départ : Packet Tracer, 2 routeurs ISR 2911 (+1 pour le FAI), 4 switchs 2960, des PC, un serveur ; le plan VLSM du chapitre 06Durée : 4 à 6 h

  1. Câblage et plan : poser les équipements, câbler (EtherChannel entre les deux cœurs), écrire le tableau d'adressage. Vérifier : show cdp neighbors sur chaque équipement correspond au schéma.

  2. Base et SSH sur les six équipements (chapitre 02). Vérifier : show ip ssh, et une connexion SSH depuis un PC du VLAN 99.

  3. VLAN et trunks sur les quatre switchs, VLAN natif 999, EtherChannel LACP entre les cœurs (chapitres 03 et 09). Vérifier : show vlan brief, show interfaces trunk, show etherchannel summary en SU.

  4. Spanning tree : SW-CORE1 racine, SW-CORE2 secours, PortFast et BPDU Guard sur les ports d'accès. Vérifier : show spanning-tree vlan 10 sur SW1 montre la racine sur SW-CORE1.

  5. Sous-interfaces et HSRP sur R-EDGE1 et R-EDGE2 (chapitres 04 et 10). Vérifier : show standby brief — R-EDGE1 Active, R-EDGE2 Standby sur chaque VLAN.

  6. DHCP : exclusions puis pools, passerelle = adresse virtuelle (chapitre 05). Vérifier : un PC de chaque VLAN obtient une adresse, show ip dhcp binding.

  7. Routage : routes par défaut et flottantes, OSPF entre les deux routeurs de bordure (chapitres 07 et 08). Vérifier : show ip ospf neighbor en FULL, show ip route avec une Gateway of last resort.

  8. NAT : PAT et publication du serveur web (chapitre 11). Vérifier : un PC joint 203.0.113.10, show ip nat translations montre la traduction.

  9. ACL : VTY, Management, invités (chapitre 12). Vérifier : SSH refusé depuis le VLAN 10, accepté depuis le 99 ; compteurs de show access-lists.

  10. Test de panne : shutdown sur g0/2 de R-EDGE1. Vérifier : R-EDGE2 devient Active, les PC sortent toujours sur Internet. no shutdown : R-EDGE1 reprend la main.

  11. Sauvegarde : write sur les six équipements, et enregistrer le fichier .pkt.

La configuration complète de référence se trouve dans le cours : ccna-cisco/exercices/exo-final/ (configuration commentée de chaque équipement et liste des commandes de vérification). Ne la regarde qu'après avoir essayé : c'est en bloquant qu'on apprend.

À retenir

Adressage → base et SSH → VLAN et trunks → spanning tree → routage inter-VLAN et HSRP → DHCP → routage → NAT → ACL → test de panne → sauvegarde. Chaque étape se vérifie avant la suivante : c'est ce qui rend la panne, quand elle arrive, facile à trouver.
