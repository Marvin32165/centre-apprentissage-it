01

Choisir son édition & préparer la VM

SQL Server est le SGBDR de Microsoft : un moteur de bases de données relationnelles qui s'installe comme un service Windows. Avant de lancer l'assistant, une décision compte vraiment — l'édition.

ÉditionCe qu'elle vautCadre d'usage
DeveloperGratuite, avec toutes les fonctionnalités de l'édition EnterpriseDéveloppement, tests, formation. Interdite en production.
ExpressGratuite mais bridée (taille de base, RAM, CPU)Petites applications, production légère
Standard / EnterprisePayantes, sous licenceProduction

Pourquoi Developer en labo

C'est la seule édition gratuite qui expose l'intégralité des fonctionnalités : on apprend sur le même moteur qu'en production, sans licence. La restriction n'est pas technique mais juridique — rien n'empêche de la déployer en production, sauf le contrat.

La VM

L'instance de ce TP est installée sur une machine virtuelle Windows Server dédiée, préparée via les scripts de création et de configuration du labo. Le montage de la VM elle-même est couvert par le module Hyper-V.

02

Installer l'instance, écran par écran

L'assistant enchaîne une quinzaine d'écrans, dont la plupart se valident tels quels. Voici les sept qui demandent une vraie décision.

1
Edition

Sélectionner Developer.

2
License Terms

Cocher l'acceptation des conditions, puis Next.

3
Azure Extension for SQL Server

Décocher, puis Next. Cette extension ne sert qu'à rattacher l'instance à Azure Arc — inutile pour un labo local, et elle réclame un abonnement.

4
Feature Selection

Cocher Database Engine Services : c'est le moteur de base de données lui-même, le strict nécessaire pour créer et interroger des bases.

5
Instance Configuration

Donner un nom à l'instance. Une instance nommée s'atteint ensuite par NOM-SERVEUR\NOM-INSTANCE, alors qu'une instance par défaut répond au seul nom du serveur.

6
Server Configuration

Passer le service SQL Server Browser en démarrage Automatic.

7
Database Engine Configuration

Onglet Server Configuration : cliquer sur Add Current User pour se donner les droits sysadmin sur l'instance. Onglet Data Directories : vérifier où atterriront les fichiers de données, de journaux et de sauvegarde.

Le piège de l'instance nommée

Une instance nommée n'écoute pas sur le port fixe 1433 : elle prend un port dynamique. C'est le service SQL Server Browser qui indique aux clients quel port utiliser — s'il est arrêté, la connexion par nom d'instance échoue alors que le moteur tourne parfaitement. D'où le passage en démarrage automatique à l'étape 6.

Data Directories

Séparer les fichiers de données (.mdf), les journaux de transactions (.ldf) et les sauvegardes sur des volumes distincts est la bonne pratique dès qu'on sort du labo : les profils d'écriture sont très différents, et une sauvegarde sur le même disque que la base ne protège de rien.

03

Après l'installation : se connecter

L'instance tourne, mais rien ne s'y connecte encore. Quatre points à traiter dans la foulée.

1
Installer SSMS

SQL Server Management Studio se télécharge et s'installe séparément du moteur — c'est la console d'administration graphique.

2
Vérifier le mode d'authentification

Windows seul, ou mixte (Windows + comptes SQL). Le mode mixte est nécessaire dès qu'une application se connecte avec son propre identifiant.

3
Activer TCP/IP et ouvrir le port

Dans SQL Server Configuration Manager, activer le protocole TCP/IP, puis autoriser le port 1433 dans le pare-feu pour les connexions distantes.

4
Contrôler les services

Toujours dans le Configuration Manager : le service du moteur et le SQL Server Browser doivent être démarrés.

Auto-évaluation

Teste-toi

Réponds de tête — à voix haute si possible — avant de déplier la correction. Une question qui bloque désigne le chapitre à relire : son numéro est rappelé avec la réponse.

  1. Pourquoi l'édition Developer en labo, et qu'est-ce qui l'interdit en production ?

    Voir la réponse

    C'est la seule édition gratuite avec toutes les fonctionnalités Enterprise : on apprend sur le même moteur qu'en production. La restriction n'est pas technique mais juridique — rien n'empêche techniquement de la déployer, sauf le contrat. Chapitre 01.

  2. Une instance nommée écoute-t-elle sur le port 1433 ?

    Voir la réponse

    Non : elle prend un port dynamique. C'est le service SQL Server Browser qui indique aux clients quel port utiliser — s'il est arrêté, la connexion par nom d'instance échoue alors que le moteur tourne parfaitement. Chapitre 02.

  3. Que fait « Add Current User » à l'écran Database Engine Configuration ?

    Voir la réponse

    Il donne au compte connecté les droits sysadmin sur l'instance. Sans cela, on installe un moteur auquel on ne peut pas s'administrer. Chapitre 02.

  4. Pourquoi décocher l'extension Azure pendant l'installation d'un labo local ?

    Voir la réponse

    Elle ne sert qu'à rattacher l'instance à Azure Arc et réclame un abonnement — inutile hors ligne, et bloquante si on la laisse cochée. Chapitre 02.

  5. Pourquoi séparer fichiers de données, journaux de transactions et sauvegardes sur des volumes distincts ?

    Voir la réponse

    Leurs profils d'écriture sont très différents (I/O). Et surtout : une sauvegarde posée sur le même disque que la base ne protège de rien. Chapitre 02.

  6. SSMS s'installe-t-il en même temps que le moteur ?

    Voir la réponse

    Non — SQL Server Management Studio se télécharge et s'installe séparément. C'est la console d'administration graphique, pas un composant du moteur. Chapitre 03.
