Dépannage à distance

Une bonne partie du dépannage se fait sans se déplacer : on voit l'écran de l'utilisateur, on le guide ou on prend la main avec son accord. Ce module prolonge le jour 8 : choisir le bon outil, maîtriser Assistance rapide et le Bureau à distance, agir sans prendre la main, reconnaître un faux support, et conduire une session de bout en bout.

À la fin de ce module, tu sauras

  • choisir entre Assistance rapide, Bureau à distance et l'outil de l'organisation selon la situation ;
  • ouvrir, conduire et fermer une session Assistance rapide, du code de sécurité à la fin du contrôle ;
  • activer le Bureau à distance sur un poste compatible et t'y connecter avec mstsc ;
  • expliquer ce que fait PowerShell à distance et quand il évite de prendre la main ;
  • reconnaître le scénario du faux support et protéger l'utilisateur ;
  • tracer une session dans le ticket, et savoir quand passer sur place.

L'outil de prise en main utilisé par la DSI (Assistance rapide, Remote Help ou un autre), qui a le droit de s'en servir et sur quels postes : à demander à ton tuteur. Ce module décrit les outils intégrés à Windows ; la procédure de la maison passe avant.

Je montre

1. Choisir l'outil

Trois familles d'outils, pour trois situations différentes :

OutilQuandCe qu'il faut
Assistance rapide (Quick Assist)L'utilisateur est devant son poste et accepte de partager son écran.Côté support : un compte Microsoft ou Microsoft Entra ID. Côté utilisateur : aucune authentification, il saisit un code. Passe par Internet (port 443).
Bureau à distance (RDP, mstsc)Se connecter à un poste ou un serveur avec un compte autorisé, par exemple pour administrer.Un poste hôte en édition Pro, Entreprise ou Éducation (pas Famille), le Bureau à distance activé, un compte autorisé, le port TCP 3389 joignable.
Outil de l'organisation (par exemple Remote Help d'Intune)C'est souvent l'outil prévu en entreprise : contrôle d'accès, rôles, journal des sessions.À vérifier sur place.

Microsoft recommande aux organisations qui utilisent un autre outil, comme Remote Help, de désactiver ou de retirer Assistance rapide. Ne sois donc pas surpris s'il est absent des postes de l'UMONS.

La commande mstsc a une option /noConsentPrompt qui permet d'observer la session d'un utilisateur sans son accord. Qu'elle existe ne veut pas dire qu'on peut s'en servir : au service desk, on obtient toujours le consentement de l'utilisateur avant de voir son écran, sauf procédure écrite contraire.

Microsoft Learn : Use Quick Assist to help users (comptes, réseau, Remote Help) ; Microsoft Support : How to use Remote Desktop ; Microsoft Learn : Enable Remote Desktop on your PC (éditions) ; Microsoft Learn : mstsc, port d'écoute du Bureau à distance (3389 par défaut).

2. Assistance rapide pas à pas

Les libellés ci-dessous sont ceux de la documentation anglaise ; l'interface française peut les traduire.

Toi (le support, helper)L'utilisateur (sharer)
1. Ouvre Assistance rapide et choisis Help someone. Un code de sécurité à 6 chiffres, valable un temps limité, s'affiche.
2. Donne-lui le code au téléphone.3. Ouvre Assistance rapide (raccourci Ctrl + Windows + Q), saisit le code dans Code from assistant, puis Submit.
4. Clique sur Allow pour autoriser la connexion et le partage d'écran.
5. Tu vois l'écran : pointeur laser, annotation et conversation sont disponibles. Si tu dois agir, clique sur Request control.6. Accepte (Allow) ou refuse. Il peut reprendre la main à tout moment avec Cancel control.
7. À la fin : Leave.Ou lui-même : Leave.

Ce qu'il faut savoir

  • Avec le contrôle, tu as les mêmes droits que l'utilisateur, pas plus. Certaines invites (contrôle de compte d'utilisateur, UAC) demandent que l'utilisateur réponde lui-même.
  • Aucun journal n'est créé sur ton poste ni sur celui de l'utilisateur. Microsoft garde seulement des données minimales (heures, erreurs, fonctions utilisées), au plus trois jours. La trace de la session, c'est donc ton ticket.
  • Assistance rapide se trouve dans le menu Démarrer (Windows 11 : Toutes les applications ; Windows 10 : Accessoires Windows) ; sa version actuelle s'installe et se déploie depuis le Microsoft Store, et une organisation peut l'avoir retiré. Sa présence sur un poste donné se vérifie : ne la suppose pas.

Microsoft Support : Solve PC problems remotely using Quick Assist (étapes des deux côtés) ; Microsoft Learn : Use Quick Assist to help users (UAC, journalisation, installation) ; Microsoft Security : article du 15 mai 2024 (raccourci clavier).

3. Le Bureau à distance

Côté poste distant (l'hôte)

  • Il doit être en édition Pro, Entreprise ou Éducation (ou un Windows Server) : une édition Famille ne peut pas recevoir de connexion. Le poste depuis lequel tu te connectes, lui, peut être de n'importe quelle édition, voire un autre système.
  • Activation : Paramètres → Système → Bureau à distance, activer, puis confirmer. Le nom du PC affiché sur cette page sert à la connexion.
  • Le service écoute par défaut sur le port TCP 3389 (valeur PortNumber sous HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp). Dans une organisation, on ne change pas ce réglage soi-même.

Côté support : mstsc

Test-NetConnection -ComputerName PC-LABO -Port 3389
mstsc /v:PC-LABO
mstsc /v:PC-LABO /prompt
mstsc /v:PC-LABO /w:1600 /h:900
OptionEffet
/v:nom[:port]L'ordinateur distant (et le port, s'il n'est pas le port par défaut).
/promptDemande les identifiants à la connexion.
/fPlein écran.
/w: et /h:Largeur et hauteur de la fenêtre, à utiliser ensemble.
/adminSession d'administration d'un serveur.
/shadow:ID, /controlObserver (et contrôler) une session existante : réservé aux procédures qui le prévoient.

Test-NetConnection … -Port 3389 (jour 5) dit si le port répond : s'il ne répond pas, inutile d'insister avec mstsc, la cause est le réseau, le pare-feu ou un Bureau à distance désactivé.

Microsoft Support : How to use Remote Desktop ; Microsoft Learn : Enable Remote Desktop on your PC (éditions hôtes), mstsc, Change Remote Desktop listening port, Test-NetConnection.

4. Agir sans prendre la main : PowerShell à distance

Pour lire une information sur un poste sans déranger l'utilisateur, PowerShell peut exécuter des commandes sur un autre ordinateur, si les deux machines ont été configurées pour le travail à distance (ce que décide l'organisation).

Enter-PSSession PC-LABO
Invoke-Command -ComputerName PC-LABO -ScriptBlock { Get-Culture }
  • Enter-PSSession ouvre une session interactive sur un seul ordinateur : l'invite affiche le nom de l'ordinateur distant, et chaque commande s'exécute là-bas.
  • Invoke-Command exécute un bloc de commandes sur un ou plusieurs ordinateurs et rapporte le résultat.

En stage, reste en lecture (afficher, jamais modifier) et seulement si ton tuteur te l'a montré : une commande lancée sur le mauvais poste agit pour de vrai.

Microsoft Learn : about_Remote (Enter-PSSession, Invoke-Command) ; les prérequis sont dans about_Remote_Requirements.

5. Le faux support

En mai 2024, l'équipe de renseignement sur les menaces de Microsoft a publié l'analyse d'attaques où un groupe criminel, qu'elle nomme Storm-1811, appelait des employés en se faisant passer pour le support informatique, puis envoyait des messages Teams signés « Help Desk » ou « IT Support ». Le déroulé :

  1. un appel ou un message « du support », pour une prétendue correction ;
  2. la demande d'ouvrir Assistance rapide avec Ctrl + Windows + Q et de saisir un code fourni par l'attaquant ;
  3. l'acceptation du partage d'écran, puis du contrôle total ;
  4. ensuite : téléchargement d'outils malveillants, faux formulaires qui volent des identifiants, et pour finir un rançongiciel.

Ce que Microsoft conseille aux utilisateurs : n'autoriser un aidant que si l'on a soi-même contacté le support, ne pas céder à quelqu'un qui invoque l'urgence, se déconnecter et signaler en cas de doute. Aux organisations : retirer Assistance rapide s'il n'est pas utilisé et former les utilisateurs.

Ta propre pratique doit rendre ce conseil facile à suivre : c'est l'utilisateur qui a appelé, ou tu le rappelles sur un numéro connu de l'organisation ; tu expliques qui tu es et pourquoi tu demandes l'accès ; et tu ne demandes jamais de mot de passe ni de code reçu par SMS (jour 2).

Microsoft Security : Threat actors misusing Quick Assist in social engineering attacks leading to ransomware (15 mai 2024) ; Microsoft Learn : Use Quick Assist to help users (conseils de sécurité).

6. Une session de bout en bout

Cette trame est une méthode d'exercice, qui applique le consentement et la traçabilité vus au jour 8 ; la procédure de la DSI passe avant.

MomentCe que tu fais
AvantTicket ouvert ; identité vérifiée selon la procédure ; tu expliques ce que tu vas voir et faire ; tu obtiens un accord explicite ; tu proposes de fermer les documents et messageries personnels.
PendantTu regardes d'abord, tu ne demandes le contrôle que si c'est utile ; tu annonces chaque action (« j'ouvre les paramètres réseau ») ; tu laisses l'utilisateur répondre aux invites UAC et saisir ses mots de passe.
AprèsTu quittes la session (Leave) et tu vérifies avec l'utilisateur que tout fonctionne ; tu notes dans le ticket l'outil, l'heure de début et de fin, l'accord obtenu, les actions faites et le résultat.

Quand passer sur place (ou escalader)

  • le poste n'a pas de réseau, ou ne démarre pas jusqu'à Windows ;
  • le problème est matériel (écran, câble, périphérique, bruit, odeur) ;
  • l'utilisateur refuse la prise en main, ou il n'est pas là pour donner son accord ;
  • il faut des droits que tu n'as pas, ou la procédure l'impose.

Microsoft Learn : Use Quick Assist to help users (accord de l'utilisateur, contrôle retirable, invites UAC, absence de journal sur les postes, d'où la note dans le ticket) ; Microsoft Support : Solve PC problems remotely using Quick Assist (fin de session). La trame et la liste « sur place » sont une méthode d'exercice, pas une norme : la procédure de la DSI passe avant (à vérifier sur place).

On fait ensemble

Labo guidé : ton PC et ta VM ≈ 50 min

Règles utilisées : §2 (Assistance rapide), §3 (Bureau à distance, test du port), §6 (note de ticket). Il te faut la VM Windows 11 du jour 4 (en édition Pro, Entreprise ou Éducation, pour le Bureau à distance), reliée à un commutateur virtuel qui la rend joignable depuis ton PC, et un compte Microsoft pour le rôle de support dans Assistance rapide.

  1. Bureau à distance : dans la VM, active le Bureau à distance (Paramètres → Système → Bureau à distance) et note le nom du PC.
  2. Depuis ton PC : Test-NetConnection -ComputerName <nom> -Port 3389. Note la valeur de TcpTestSucceeded.
  3. mstsc /v:<nom> /prompt, connecte-toi avec le compte de la VM, puis déconnecte-toi.
  4. Désactive le Bureau à distance dans la VM et relance l'étape 2. Que change-t-il ? Réactive-le.
  5. Assistance rapide : sur ton PC, joue le support (Help someone) ; dans la VM, joue l'utilisateur (Ctrl + Windows + Q, saisie du code).
  6. Observe chaque fenêtre d'accord. Demande le contrôle, puis, côté VM, reprends-le avec Cancel control. Termine avec Leave.
  7. Rédige la note de ticket de cette session fictive (outil, heures, accord, actions, résultat).
Voir ce que tu dois constater
  • Étape 2 : TcpTestSucceeded : True quand le Bureau à distance est actif et le réseau correct.
  • Étape 4 : le test passe à False : le port ne répond plus. C'est le signe à reconnaître avant d'accuser mstsc.
  • Étapes 5 et 6 : l'utilisateur autorise deux fois (la connexion, puis le contrôle) et peut retirer le contrôle à tout moment. Si ton compte de support n'est pas un compte Microsoft ou Entra ID, la session ne démarre pas.
  • Étape 7 : une note du type « 24/11, 10 h 05 – 10 h 20, Assistance rapide, accord oral de l'utilisateur, contrôle demandé et accordé, redémarrage du spouleur, impression de test réussie, session quittée ».
  • Avant l'étape 5, cherche Assistance rapide dans le menu Démarrer de la VM ; s'il est absent, il s'installe depuis le Microsoft Store (§2).

Prends un point de contrôle de la VM avant le labo : tu pourras recommencer.

Tu fais seul

Mises en situation

Les corrections s'appuient sur les sections sourcées : éditions et port au §3, consentement et faux support aux §5 et §6.

1. Le poste en édition Famille

Un utilisateur te demande de te connecter en Bureau à distance à son PC personnel en Windows 11 Famille pour l'aider.

Voir la correction

Une édition Famille ne peut pas recevoir de connexion Bureau à distance. Et un appareil personnel ne se dépanne que si la procédure le prévoit : vérifie d'abord ce que la DSI prend en charge. Si c'est le cas, l'outil adapté est celui où l'utilisateur partage son écran (Assistance rapide ou l'outil de l'organisation).

2. « Le support Microsoft m'a appelé »

Une secrétaire t'appelle : quelqu'un « du support informatique » vient de lui demander d'appuyer sur Ctrl + Windows + Q et de saisir un code. Elle l'a fait, puis a accepté une demande de contrôle. L'appel est terminé.

Voir la correction

C'est le scénario du faux support. Si la session est encore ouverte, elle clique sur Leave. Tu traites l'appel comme un incident de sécurité : escalade immédiate selon la procédure (le poste peut devoir être isolé, le mot de passe changé), ticket avec l'heure, ce qui a été accepté et ce qu'elle a vu à l'écran. Tu ne minimises pas et tu ne cherches pas toi-même ce que l'attaquant a fait.

3. Le port qui ne répond pas

mstsc /v:PC-ACCUEIL échoue. Test-NetConnection -ComputerName PC-ACCUEIL -Port 3389 donne TcpTestSucceeded : False, mais ping PC-ACCUEIL répond.

Voir la correction

Le poste est joignable, mais pas le port 3389 : Bureau à distance désactivé, pare-feu, ou poste non autorisé par la stratégie de l'organisation. Inutile de réessayer mstsc. Tu le notes dans le ticket et tu passes par l'outil prévu (ou sur place), ou tu escalades à l'équipe poste de travail.

4. L'invite UAC

Pendant une session Assistance rapide avec contrôle, une invite de contrôle de compte d'utilisateur apparaît et tu ne peux pas la valider.

Voir la correction

C'est prévu : dans certains cas, c'est l'utilisateur qui doit répondre à l'invite. Tu lui expliques ce qu'elle demande et pourquoi ; s'il faut des identifiants d'administrateur qu'il n'a pas, l'action dépasse ses droits (et donc les tiens dans cette session) : on escalade ou on passe par la procédure prévue, on ne lui demande pas de mot de passe.

Quiz

Fiche mémo

  • Assistance rapide : le support génère un code à 6 chiffres, l'utilisateur le saisit et autorise ; contrôle sur demande, retirable (Cancel control) ; mêmes droits que l'utilisateur ; aucun journal sur les postes.
  • Bureau à distance : hôte en édition Pro, Entreprise ou Éducation (pas Famille), activé dans Paramètres → Système, TCP 3389 ; mstsc /v:nom /prompt ; tester le port avec Test-NetConnection -Port 3389.
  • PowerShell à distance : Enter-PSSession (interactif), Invoke-Command (bloc de commandes) ; en lecture seulement en stage.
  • Faux support : appel ou message « IT Support », Ctrl+Win+Q, code, contrôle → incident de sécurité.
  • Session : identité, accord explicite, annoncer chaque action, l'utilisateur répond aux invites, Leave, tout noter dans le ticket.
  • Sur place : pas de réseau, matériel, pas d'accord, droits manquants.
  • Quel outil de prise en main la DSI utilise-t-elle, et Assistance rapide est-il autorisé ou retiré des postes ?
  • Comment l'accord de l'utilisateur est-il recueilli et noté (oral, écrit, dans le ticket) ?
  • Le Bureau à distance est-il ouvert sur les postes du personnel, et pour quels comptes ?
  • PowerShell à distance est-il configuré, et le service desk a-t-il le droit de s'en servir ?
  • Comment un utilisateur peut-il vérifier qu'un appel vient vraiment de la DSI ?
  • Que prend en charge le service desk pour les appareils personnels ?
