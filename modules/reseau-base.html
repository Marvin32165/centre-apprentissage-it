Module · Réseau

Réseau de base : du câble à la page web

Le jour 5 de la prépa apprend à dépanner le réseau côté utilisateur. Ce module donne les raisons derrière les commandes : pourquoi deux machines se parlent ou non, ce que fait la passerelle, où intervient le DNS, ce que fait le DHCP, et comment un port ferme une porte. À la fin, un message d'erreur réseau devient une piste, plus un mystère.

À la fin de ce module, tu sauras

  • décrire le trajet d'une requête (page web, partage de fichiers) et le placer sur les couches TCP/IP ;
  • dire, avec une adresse et un masque, si deux machines sont dans le même réseau, et pourquoi la passerelle compte ;
  • expliquer le rôle du DNS et du DHCP, et reconnaître leurs pannes à leurs symptômes ;
  • choisir la commande adaptée (ping, Test-NetConnection, Resolve-DnsName, tracert…) selon la couche suspectée ;
  • observer un échange DHCP et DNS dans une capture réseau.

Plan d'adressage de l'UMONS, plages DHCP, serveurs DNS, VLAN, règles du pare-feu, fonctionnement d'eduroam et du VPN : tout cela est propre à la DSI et à vérifier sur place. Les adresses de ce module sont des exemples privés.

Je montre

1. Les couches : ranger les pannes

Un échange réseau se décrit en couches empilées ; chaque couche s'appuie sur celle d'en dessous. Pour le dépannage, retiens quatre étages du modèle TCP/IP (le modèle OSI, à sept couches, sert surtout de vocabulaire) :

ÉtageRôleExemplesOutil de test
ApplicationLe service que l'on veut utiliser.HTTP/HTTPS, DNS, SMB, SMTP, RDPNavigateur, Test-NetConnection -Port
TransportConversations entre programmes, identifiées par un port.TCP, UDPTest-NetConnection -Port, netstat
Internet (réseau)Adresser et acheminer entre réseaux.IPv4, IPv6, ICMPping, tracert, route print
Accès réseauLiaison locale : câble, Wi-Fi, adresses physiques (MAC).Ethernet, Wi-Fi (802.11), VLANVoyants, Get-NetAdapter, arp -a

La logique de dépannage en découle : du bas vers le haut (le câble branché, l'adresse correcte, la passerelle joignable, un nom qui se résout, un port ouvert), en s'arrêtant à la première étape qui échoue. C'est la méthode « du plus proche au plus lointain » du jour 5.

RFC 1122 (« Requirements for Internet Hosts — Communication Layers ») pour la pile TCP/IP ; Microsoft Learn pour les cmdlets Test-NetConnection, Get-NetAdapter, Resolve-DnsName.

2. Adresses, masques et passerelle

Une adresse IPv4 s'écrit sur 32 bits, en quatre nombres de 0 à 255. Elle est toujours accompagnée d'un masque, qui dit quelle partie désigne le réseau et laquelle désigne la machine. Deux écritures du même masque : 255.255.255.0 ou /24 (24 bits à 1, notation CIDR).

Règle d'or : deux machines sont dans le même réseau si, une fois le masque appliqué, leurs adresses donnent le même numéro de réseau. Dans ce cas, sur un même lien local, elles se parlent directement. Sinon, dans le cas courant d'un poste dont la seule sortie est la route par défaut, elles passent par la passerelle par défaut (le routeur), qui doit être, elle, dans le même réseau que la machine. Une route plus précise (route print) peut passer avant.

Calculer un réseau (méthode du « bloc »)

Prenons 192.168.10.77/26. Le masque /26 laisse 6 bits pour les machines : un « bloc » de 26 = 64 adresses. Les blocs commencent à 0, 64, 128, 192. Le 77 tombe dans le bloc 64–127 :

  • adresse du réseau : 192.168.10.64 (première adresse du bloc) ;
  • adresse de diffusion (broadcast) : 192.168.10.127 (dernière) ;
  • machines utilisables : .65 à .126, soit 64 − 2 = 62.

Plages à reconnaître

PlageNomRemarque

« J'ai une adresse en 169.254.x.x » (poste en DHCP) = « je n'ai pas obtenu de bail DHCP », sans dire pourquoi. « J'ai une adresse valide mais pas d'accès hors du réseau local » = pense passerelle (absente, mauvaise, ou hors du réseau de la machine).

IETF : RFC 1918 (adressage privé), RFC 3022 (NAT), RFC 3927 (lien local IPv4), RFC 4632 (CIDR), RFC 3021 (/31), RFC 1122 § 3.3.1 (remise directe ou passerelle) ; Microsoft Learn : route. IPv6 : RFC 4291 (adressage, fe80::/10), RFC 3849 (2001:db8::/32 pour la documentation).

IPv6, en deux lignes

IPv6 utilise des adresses de 128 bits écrites en hexadécimal (par exemple 2001:db8::1, plage réservée à la documentation). Une machine possède presque toujours une adresse de lien local en fe80::/10. Le raisonnement reste le même : réseau, passerelle, DNS. Tu verras les deux versions dans ipconfig.

3. Le DNS : le répertoire des noms

On tape un nom (example.org), les machines se parlent avec des adresses. Le DNS fait la traduction. Le poste interroge son serveur DNS (donné par le DHCP ou configuré) ; celui-ci répond depuis son cache ou interroge d'autres serveurs.

TypeContenu
A / AAAAAdresse IPv4 / IPv6 d'un nom.
CNAMEAlias : un nom qui renvoie vers un autre nom.
MXServeur de messagerie d'un domaine.
PTRRésolution inverse : de l'adresse vers le nom.
TXTTexte libre (vérifications de domaine, politiques de messagerie).
SRVLocalise un service (par exemple le contrôleur de domaine : voir le module Active Directory).
nslookup example.org
Resolve-DnsName example.org -Type A
Resolve-DnsName example.org -Type MX
ipconfig /displaydns
ipconfig /flushdns

Chaque réponse porte une durée de vie (TTL) : pendant ce temps, les caches la gardent. Après un changement côté serveur, un poste peut donc encore utiliser l'ancienne réponse ; ipconfig /flushdns vide le cache du poste.

Le test qui sépare DNS et réseau : si ping d'une adresse répond mais que le nom donne « hôte introuvable », le réseau marche et la résolution échoue : vérifie le serveur DNS du poste et le suffixe. Si le nom se résout mais que le ping expire, compare l'adresse obtenue (IPv4 ou IPv6 ?) avec celle qui répond, et pense au filtrage de l'ICMP. Interroge alors un autre serveur DNS pour comparer : nslookup example.org adresse-du-serveur.

IETF : RFC 1034 et RFC 1035 (DNS), RFC 2606 (example.org, nom réservé aux exemples) ; Microsoft Learn : Resolve-DnsName, nslookup, dépannage du client DNS.

4. Le DHCP : la distribution des adresses

Le DHCP donne automatiquement à un poste : une adresse, un masque, la passerelle, les serveurs DNS, pour une durée appelée bail. Les quatre messages (« DORA ») : Discover (le poste cherche un serveur, en diffusion), Offer (offre), Request (demande), Acknowledge (confirmation). À la moitié du bail, le poste tente de le renouveler.

  • Le poste écoute sur le port UDP 68, le serveur sur le port UDP 67.
  • La première demande (Discover) est une diffusion : elle ne franchit pas un routeur sans relais DHCP, donc un réseau sans relais ni serveur local ne donne pas d'adresse. Le renouvellement d'un bail, lui, se fait normalement en direct avec le serveur.
  • Une réservation lie une adresse à l'identifiant du client, en général son adresse MAC (pratique pour une imprimante).
ipconfig /all
ipconfig /release
ipconfig /renew

Deux appareils qui reçoivent la même adresse (conflit d'adresses) : cela arrive quand quelqu'un fixe une adresse à la main dans la plage distribuée par le DHCP. Windows prévient d'un conflit ; l'issue est de chercher l'appareil qui l'utilise, pas de changer au hasard.

IETF : RFC 2131 (DHCP : diffusion, relais, renouvellement, identifiant client) ; Microsoft Learn : ipconfig.

5. Les ports : choisir la bonne porte

Une adresse désigne la machine, un port désigne le service. Un pare-feu peut laisser passer un port et en bloquer un autre : « je joins la machine mais pas le service » est un problème de port, pas d'adresse.

Test-NetConnection example.org -Port 443

Avec -Port, Test-NetConnection résout le nom si besoin, puis essaie une connexion TCP au port (TcpTestSucceeded). Une connexion TCP réussie ne prouve pas que l'application répond correctement ; un ping est un autre test. netstat -ano liste les connexions et les ports en écoute avec le numéro du processus (retrouvable dans le Gestionnaire des tâches).

Un ping qui ne répond pas ne prouve pas qu'une machine est éteinte : un pare-feu peut bloquer l'ICMP tout en laissant passer le service. Et un ping qui répond ne prouve pas que le service fonctionne : teste le port.

IANA : Service Name and Transport Protocol Port Number Registry ; Microsoft Learn : Test-NetConnection.

6. Réseau local : commutateur, VLAN, Wi-Fi

  • Un commutateur (switch) relie les machines d'un réseau local et apprend quelle adresse MAC se trouve sur quelle prise ; un concentrateur (hub) répète tout à tous et n'existe plus guère.
  • Un VLAN découpe un commutateur en plusieurs réseaux logiques séparés (norme IEEE 802.1Q) : un poste dans le mauvais VLAN obtient une mauvaise adresse ou n'accède pas aux ressources. C'est l'équipe réseau qui gère les VLAN ; toi, tu repères le symptôme (« adresse d'un autre réseau que celle des voisins »).
  • Le Wi-Fi (IEEE 802.11) est une liaison partagée par radio : signal faible, interférences, trop d'appareils. Dans une organisation, l'authentification se fait souvent par compte individuel (IEEE 802.1X), comme eduroam (voir jour 5).
Get-NetAdapter
Get-NetIPConfiguration
arp -a
route print

IEEE : 802.1Q (VLAN), 802.11 (Wi-Fi), 802.1X (authentification) ; IETF : RFC 826 (ARP) ; Microsoft Learn : Get-NetAdapter.

On fait ensemble

Labo guidé : observer DHCP, DNS et ARP chez toi ≈ 60 min

Sur ton PC, connecté à ta box. Installe Wireshark (logiciel libre, avec son pilote de capture Npcap). Le renouvellement de l'adresse coupe le réseau quelques secondes : pas pendant un appel vidéo. Sources : filtre dhcp de Wireshark, RFC 2131, RFC 826 et les encadrés des §2 à §5.

  1. Lance une capture sur ta carte réseau (Wi-Fi ou Ethernet), filtre d'affichage dhcp (bootp dans les anciennes versions). Dans une invite de commandes : ipconfig /release puis ipconfig /renew.
  2. Repère les messages DHCP. Ouvre la réponse du serveur (Offer ou ACK) et lis : adresse, masque, routeur, serveur DNS, durée du bail.
  3. Change le filtre en dns. Vide le cache (ipconfig /flushdns), puis Resolve-DnsName example.org -Type A. Repère la question et la réponse ; lis le type et le TTL.
  4. Vide la table ARP (arp -d *, invite administrateur), puis ping ta passerelle. Filtre : arp, puis icmp : que voit-on avant le premier ping ?
  5. Teste un port : Test-NetConnection example.org -Port 443, puis le même nom sur un port sans service (par exemple 8081). Compare.
Voir ce que tu dois observer
  • Après /release, en général les quatre messages Discover, Offer, Request, ACK ; le Discover part en diffusion (destination 255.255.255.255) depuis 0.0.0.0, ports 68 → 67. Selon le poste et la box, seuls Request et ACK peuvent apparaître.
  • La réponse du serveur contient les options distribuées : routeur, serveur DNS, durée du bail (souvent la box pour les trois).
  • Une requête DNS (type A) et une réponse portant l'adresse et un TTL ; en UDP, port destination 53. Si la capture reste vide, la réponse venait du cache : vide-le et recommence.
  • Avant le premier ping, des échanges ARP (« qui a cette adresse ? ») pour trouver l'adresse MAC de la passerelle.
  • Test-NetConnection : TcpTestSucceeded à True sur 443 (le site écoute) ; False sur 8081, après un délai, quand rien n'y répond.

Exercices de calcul

  1. Donne l'adresse de réseau, l'adresse de diffusion et le nombre de machines utilisables pour 10.20.30.200/27.
  2. Les machines 172.16.5.10/24 et 172.16.6.20/24 se parlent-elles sans routeur ?
  3. Un poste a l'adresse 192.168.1.50, le masque 255.255.255.0 et la passerelle 192.168.2.1. Que se passe-t-il pour Internet ?
  4. Convertis 255.255.255.192 en notation CIDR et donne la taille d'un bloc.
Voir les corrections
  1. /27 : blocs de 32 (0, 32, …, 192, 224). 200 est dans 192–223 : réseau 10.20.30.192, diffusion 10.20.30.223, utilisables .193 à .222, soit 30 machines.
  2. Non : /24 donne les réseaux 172.16.5.0 et 172.16.6.0, différents. Elles ont besoin d'un routeur entre elles.
  3. La passerelle 192.168.2.1 n'est pas dans le réseau 192.168.1.0/24 du poste : il ne peut pas l'atteindre directement. Le poste communique localement, mais pas vers l'extérieur. Corriger la passerelle (ou l'adresse).
  4. 192 = 11000000 : 2 bits à 1 de plus que 255.255.255.0, soit 26 bits : /26. Bloc de 64 adresses, 62 utilisables.

Mises en situation

1. « Je joins l'adresse mais pas le nom »

ping 192.168.50.10 répond, ping serveur répond « hôte introuvable ». Quelle couche suspectes-tu et que fais-tu ?

Voir la correction

Le réseau fonctionne (l'adresse répond) : la résolution de noms est en cause. On vérifie quel serveur DNS le poste utilise (ipconfig /all), on teste avec nslookup serveur puis avec un autre serveur DNS, on regarde le suffixe DNS (nom court contre nom complet) et on vide le cache. Si le serveur DNS ne répond pas, on escalade en donnant les tests faits.

2. Une salle sans adresse

Dans une salle, tous les postes branchés sur un nouveau commutateur affichent une adresse en 169.254.x.x ; ceux de la salle voisine sont normaux.

Voir la correction

Les postes n'obtiennent pas de réponse DHCP : trois pistes. (1) Le commutateur ou ses ports sont dans un VLAN sans accès au DHCP ; (2) le relais DHCP n'a pas été configuré pour ce réseau ; (3) un problème physique de liaison montante. Tu signales à l'équipe réseau avec les éléments : lieu, nouveau commutateur, adresses 169.254, postes voisins normaux. Tu ne mets pas d'adresses fixes « pour dépanner » : ce serait un contournement fragile et un risque de conflit.

3. Le site marche, pas le partage

Un utilisateur ouvre les pages web, mais pas \\serveur\dossier. Le nom se résout, le ping répond.

Voir la correction

Il faut tester le port des partages : Test-NetConnection serveur -Port 445. S'il échoue : pare-feu, VPN absent (hors campus), ou service arrêté côté serveur. S'il réussit : le problème est plutôt d'authentification ou de droits (compte, groupe : voir le module Active Directory).

4. Où se situe la panne ?

Ordonne ces tests du plus proche au plus lointain : ouvrir une page web ; ping de la passerelle ; ipconfig ; ping d'une adresse publique ; nslookup ; voyants de la prise.

Voir la correction

1. Voyants de la prise (liaison physique) ; 2. ipconfig (adresse, masque, passerelle, DNS) ; 3. ping de la passerelle (réseau local) ; 4. ping d'une adresse publique (sortie du réseau, sans DNS) ; 5. nslookup (résolution de noms) ; 6. page web (application). Chaque étape élimine une couche.

Quiz

Fiche mémo

  • Dépanner : liaison → adresse → passerelle → sortie → nom → port → application.
  • Même réseau ? Applique le masque aux deux adresses ; sinon, passerelle (qui doit être dans le réseau du poste).
  • Bloc : 2(32 − préfixe) adresses ; réseau = début du bloc, diffusion = fin, utilisables = bloc − 2 (jusqu'à /30 ; un /31 point à point a 2 adresses utilisables, un /32 désigne une seule adresse).
  • 169.254.x.x : pas de bail DHCP (cause à chercher). Adresse OK sans sortie : passerelle. Adresse OK, « hôte introuvable » : DNS.
  • Ports : 53 DNS, 67/68 DHCP, 80/443 web, 445 partages, 3389 RDP, 88 Kerberos, 389/636 LDAP.
  • Commandes : ipconfig /all, ping, tracert, nslookup / Resolve-DnsName, Test-NetConnection -Port, netstat -ano.
  • Quels réseaux, VLAN et plages DHCP existent (postes, salles, Wi-Fi, invités) ?
  • Quels serveurs DNS les postes utilisent-ils, et que se passe-t-il hors du campus (VPN) ?
  • Quels outils de diagnostic le service desk peut-il utiliser (capture réseau autorisée ou non) ?
  • À qui signale-t-on un problème de commutateur, de VLAN ou de relais DHCP ?
