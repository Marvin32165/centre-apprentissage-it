De la première VM à un labo Windows Server déployable en série

01

Activer Hyper-V & créer une VM

Hyper-V est déjà dans Windows — il suffit de l'allumer. C'est l'hyperviseur qui portera tout le labo Windows Server du parcours.

1
Activer la fonctionnalité

Panneau de configuration → Fonctionnalités Windows → cocher Hyper-V. Redémarrage nécessaire.

2
Ouvrir le gestionnaire

Hyper-V Manager : c'est la console qui pilote toutes les VM.

3
Créer la machine

New → Virtual Machine, puis dérouler l'assistant.

Lancer une console en administrateur

Depuis Win + R, valider avec Ctrl + Maj + Entrée au lieu de Entrée : le programme démarre directement en tant qu'administrateur.

02

Régler la VM : génération, RAM, CPU, boot

Quatre réglages décident du confort du labo. Un seul est irréversible : la génération.

Génération 1 ou 2 ?

Génération 1

Équivalent BIOS. Pour les OS anciens ou 32 bits.

Génération 2

Équivalent UEFI. Démarrage sécurisé, boot plus rapide, disques SCSI. C'est le choix par défaut ici.

Choix définitif

La génération se fixe à la création et ne peut plus être changée ensuite. Se tromper oblige à recréer la VM.

Les réglages de l'assistant

1
Mémoire

Décocher la mémoire dynamique et attribuer une valeur fixe — 8192 Mo pour un Windows Server.

2
Connexion réseau

Default Switch pour commencer (il fournit un accès Internet via NAT). On créera un commutateur dédié au chapitre 07.

3
Support d'installation

Installer un système d'exploitation à partir d'un fichier ISO.

Ajustements après création

Clic droit sur la machine → Paramètres :

RubriqueÀ fairePourquoi
MicroprogrammeC'est l'ordre de démarrage (boot order)Pour booter sur l'ISO, puis sur le disque
SécuritéDésactiver le démarrage sécurisé pour une VM LinuxSecure Boot rejette les chargeurs non signés Microsoft
MémoireNe pas activer la mémoire dynamiqueÉvite les à-coups sur un serveur
ProcesseursPasser de 12 (valeur native) à 2Laisse des cœurs à l'hôte et aux autres VM

03

Installer Windows Server dans la VM

L'installation elle-même est classique — trois détails la font rater quand on ne les connaît pas.

1
Démarrer et « spammer » une touche

Se connecter à la VM, démarrer, puis appuyer répétitivement sur une touche : la fenêtre pour booter sur le DVD virtuel ne s'affiche que quelques secondes.

2
Choisir l'édition

Windows Server 2025 Standard (Desktop Experience) — c'est la version avec interface graphique.

3
Définir le mot de passe administrateur

Un mot de passe fort, jamais versionné ni recopié dans des notes partagées.

Aucun disque proposé à l'installation ?

Sur un serveur physique, cela signifie que Windows n'a pas le pilote du contrôleur de stockage : il faut le charger depuis l'assistant. En VM Hyper-V, le disque est toujours reconnu.

Deux commandes de confort

Invite de commandes (admin)
# Réarmer la période d'évaluation (180 jours)
slmgr /rearm

Activer aussi la session étendue dans la fenêtre de connexion à la VM : l'affichage s'adapte alors dynamiquement à la taille de la fenêtre, et le presse-papiers devient partagé avec l'hôte.

04

Configurer le serveur au premier démarrage

Une check-list à dérouler dans l'ordre — le renommage en dernier, parce qu'il redémarre la machine.

1
Sortir du DHCP

Un serveur ne reste jamais en adressage automatique : son adresse doit être prévisible.

2
Fuseau horaire

Depuis Local Server dans le Gestionnaire de serveur.

3
IE Enhanced Security Configuration → OFF

Sans quoi le navigateur bloque à peu près tout, y compris les consoles web d'administration.

4
Configurer la carte réseau

Via le lien à droite d'Ethernet, ou Win+R → ncpa.cpl. Dans les propriétés : décocher IPv6, puis IPv4 en 192.168.1.1 / 255.255.255.0.

5
Autoriser le Bureau à distance

Allow remote connections to this computer — port RDP 3389.

6
Windows Update

Le passer en download updates only pour éviter un redémarrage en plein TP.

7
Renommer la machine — en dernier

Computer Name → Change → WS01. Cette opération redémarre le serveur, d'où sa position en fin de liste.

Le pare-feu en labo

Invite de commandes (admin)
# Désactiver le pare-feu sur tous les profils
netsh advfirewall set allprofiles state off

# Le réactiver — à faire dès que le TP est terminé
netsh advfirewall set allprofiles state on

Réservé au labo

Couper le pare-feu fait gagner du temps quand on débogue un TP, et uniquement dans ce cadre. Sur un serveur réel, on ouvre les ports nécessaires — on ne désarme pas la machine. Penser à le rallumer avant de faire un Sysprep : l'état est capturé dans l'image.

05

Sysprep : fabriquer une image réutilisable

Réinstaller Windows Server à chaque TP prend une demi-heure. Sysprep permet de le faire une fois, puis de repartir de cette image pour toutes les VM suivantes.

Sysprep « généralise » l'installation : il retire le SID unique de la machine, son nom et ses identifiants matériels. L'image redevient neutre, prête à être clonée.

1
Lancer l'outil

Ouvrir C:\Windows\System32\Sysprep et exécuter sysprep.exe.

2
Cocher « Generalize »

Et choisir Shutdown dans les options d'arrêt.

3
Ne pas rallumer la VM

Un seul démarrage suffirait à réattribuer un SID et à ruiner l'image.

4
Supprimer la VM dans Hyper-V Manager

Cela fusionne les fichiers de points de contrôle (.avhdx) dans le disque principal (.vhdx). Le disque virtuel, lui, reste sur le disque de l'hôte.

5
Isoler le disque

Aller dans C:\VM\WS01\Virtual Hard Disks, renommer WS01.vhdx en sysprep.vhdx, puis le copier dans un dossier parent dédié, par exemple C:\PARENT\.

6
Nettoyer

Supprimer C:\VM\WS01. Il ne reste que l'image, réutilisable indéfiniment.

À retenir

Le fichier C:\PARENT\sysprep.vhdx est désormais un disque parent en lecture seule de fait : il ne doit plus jamais être démarré ni modifié directement, sinon toutes les VM qui en dépendent deviennent inutilisables.

06

Déployer des VM en série (disque parent)

Un disque de différenciation ne stocke que les écarts par rapport au disque parent. Créer une nouvelle VM revient alors à créer un fichier quasi vide — quelques secondes au lieu d'une installation complète.

1
Créer la VM sans disque

Même démarche qu'au chapitre 01, mais choisir « Attacher un disque dur virtuel ultérieurement ».

2
Ajouter le disque

Clic droit sur la machine → Paramètres → Contrôleur SCSI → Disque dur → Ajouter → Nouveau.

3
Type : Différenciation

C'est ce choix qui garantit que le sysprep d'origine ne sera jamais modifié.

4
Nommer et placer le disque enfant

Nom TEST-WS01-DISK1, emplacement C:\VM\TEST-WS01\.

5
Désigner le parent

C:\PARENT\sysprep.vhdx, puis Appliquer.

6
Corriger l'ordre de démarrage

Rubrique Microprogramme → booter sur le disque qui vient d'être créé.

7
Répéter pour la deuxième machine

TEST-WS02, adresse 192.168.1.2. Chaque VM finit la personnalisation de Windows à son premier démarrage.

Ce que le TP a montré

Les disques de différenciation sont pratiques mais les performances ne suivent pas : chaque lecture peut devoir traverser la chaîne parent/enfant. Pour un labo durable, un disque à taille dynamique classique est un meilleur compromis — on garde la différenciation pour du jetable qu'on recrée souvent.

07

Choisir son commutateur virtuel

Le Gestionnaire de commutateur virtuel décide de qui peut parler à qui. Trois types, trois périmètres de plus en plus fermés.

TypeQui communiqueUsage
ExterneVM ↔ hôte ↔ réseau physique ↔ InternetUtilise la carte de l'hôte pour en créer une copie virtuelle. Quand les VM doivent sortir.
InterneVM ↔ hôte uniquementCarte propre à Hyper-V, permettant à la VM de dialoguer avec la machine hôte, sans accès extérieur.
PrivéVM ↔ VM uniquementLe périmètre le plus fermé. Idéal pour un labo de domaine isolé.
1
Créer le commutateur

Hyper-V Manager → Gestionnaire de commutateur virtuel → type Privé → nom LAN1 → Appliquer.

2
Le raccorder aux VM

Dans les paramètres de chaque machine, sélectionner la nouvelle carte à la place du Default Switch.

Le réflexe du labo AD

Un domaine de test se monte sur un commutateur privé : le DHCP et le DNS du labo ne risquent alors pas de répondre sur le réseau de la maison ou de l'école. Si les VM ont besoin d'Internet ponctuellement (mises à jour), on leur ajoute une seconde carte sur un commutateur externe plutôt que de tout basculer.
