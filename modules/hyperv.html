Hyper-V
De la première VM à un labo Windows Server déployable en série

Ce que tu sauras faire à la fin

  • Activer Hyper-V et créer une VM en posant dès la création les réglages qui comptent : génération, mémoire fixe, vCPU, ordre de démarrage.
  • Installer Windows Server dans une VM, puis dérouler la configuration du premier démarrage dans le bon ordre.
  • Fabriquer une image de référence avec Sysprep et l'archiver comme disque parent intouchable.
  • Déployer des VM en quelques secondes avec des disques de différenciation — et savoir dans quel cas ce n'est pas le bon choix.
  • Choisir entre commutateur externe, interne et privé selon ce que le labo doit pouvoir joindre.

Prérequis : aucun

Ce module fabrique les VM sur lesquelles tournent les modules Windows Server, SQL Server et Stockage & clustering.

01

Activer Hyper-V & créer une VM

Hyper-V est déjà dans Windows — il suffit de l'allumer. C'est l'hyperviseur qui portera tout le labo Windows Server du parcours.

1
Activer la fonctionnalité

Panneau de configuration → Fonctionnalités Windows → cocher Hyper-V. Redémarrage nécessaire.

2
Ouvrir le gestionnaire

Hyper-V Manager : c'est la console qui pilote toutes les VM.

3
Créer la machine

New → Virtual Machine, puis dérouler l'assistant.

Avant de cocher : deux prérequis

Hyper-V n'existe que dans les éditions Pro, Entreprise et Éducation de Windows (et dans Windows Server) : pas dans Windows Famille. Et la virtualisation matérielle (Intel VT-x / AMD-V) doit être activée dans le BIOS/UEFI du poste : le Gestionnaire des tâches l'indique dans Performances → Processeur → Virtualisation.

La même chose en PowerShell

PowerShell (admin) — hôte
# Activer Hyper-V (redémarrage demandé ensuite)
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All

# Créer une VM génération 2 : 8 Go de RAM au démarrage, un disque neuf de 60 Go
New-VM -Name "SRV-FILE01" -Generation 2 -MemoryStartupBytes 8GB -Path "C:\VM" `
       -NewVHDPath "C:\VM\SRV-FILE01\SRV-FILE01.vhdx" -NewVHDSizeBytes 60GB -SwitchName "Default Switch"

Vérifier

La VM existe-t-elle, avec la bonne génération ?

PowerShell — hôte
Get-VM -Name SRV-FILE01 | Select-Object Name, State, Generation

Sortie attendue

Name       State Generation
----       ----- ----------
SRV-FILE01   Off          2

Get-VM inconnu : le module PowerShell Hyper-V n'est pas installé (fonctionnalité pas activée, ou poste pas redémarré). Generation 1 : la VM est à recréer, la génération ne se change pas.

Lancer une console en administrateur

Depuis Win + R, valider avec Ctrl + Maj + Entrée au lieu de Entrée : le programme démarre directement en tant qu'administrateur.

02

Régler la VM : génération, RAM, CPU, boot

Quatre réglages décident du confort du labo. Un seul est irréversible : la génération.

Génération 1 ou 2 ?

Génération 1

Équivalent BIOS. Pour les OS anciens ou 32 bits.

Génération 2

Équivalent UEFI. Démarrage sécurisé, boot plus rapide, disques SCSI. C'est le choix par défaut ici.

Choix définitif

La génération se fixe à la création et ne peut plus être changée ensuite. Se tromper oblige à recréer la VM.

Les réglages de l'assistant

1
Mémoire

Décocher la mémoire dynamique et attribuer une valeur fixe — 8192 Mo pour un Windows Server.

2
Connexion réseau

Default Switch pour commencer (il fournit un accès Internet via NAT). On créera un commutateur dédié au chapitre 07.

3
Support d'installation

Installer un système d'exploitation à partir d'un fichier ISO.

Ajustements après création

Clic droit sur la machine → Paramètres :

RubriqueÀ fairePourquoi
MicroprogrammeC'est l'ordre de démarrage (boot order)Pour booter sur l'ISO, puis sur le disque
SécuritéPour une VM Linux : garder le démarrage sécurisé mais choisir le modèle Microsoft UEFI Certificate Authority (le désactiver seulement si la distribution n'est pas signée)Le modèle par défaut (« Microsoft Windows ») rejette les chargeurs Linux ; Debian et Ubuntu sont signés pour l'autre modèle
MémoireNe pas activer la mémoire dynamiqueÉvite les à-coups sur un serveur
ProcesseursL'assistant crée la VM avec 1 processeur virtuel : passer à 2 (le maximum proposé = le nombre de processeurs logiques de l'hôte)Un serveur à 1 vCPU rame ; trop de vCPU prive l'hôte et les autres VM
PowerShell — les mêmes réglages, VM éteinte
Set-VMMemory -VMName SRV-FILE01 -DynamicMemoryEnabled $false -StartupBytes 8GB
Set-VMProcessor -VMName SRV-FILE01 -Count 2
# VM Linux : démarrage sécurisé gardé, modèle « Microsoft UEFI Certificate Authority »
Set-VMFirmware -VMName SRV-ZBX01 -EnableSecureBoot On -SecureBootTemplate MicrosoftUEFICertificateAuthority

À retenir

Génération 2 (définitive), mémoire fixe, 2 vCPU, ordre de démarrage dans Microprogramme. Pour un invité Linux : le modèle de démarrage sécurisé Microsoft UEFI Certificate Authority.

Question éclair

Tu crées une VM génération 2 pour installer Debian depuis l'ISO officielle. Au démarrage, l'écran du microprogramme refuse de booter sur le DVD et signale que l'image n'est pas autorisée par le démarrage sécurisé. Que fais-tu ?

Le modèle par défaut (Microsoft Windows) n'accepte que les chargeurs Windows. Debian et Ubuntu sont signés via le shim par l'autorité Microsoft UEFI Certificate Authority : on choisit ce modèle et on garde le démarrage sécurisé actif. Le désactiver ne sert que pour une distribution non signée.

03

Installer Windows Server dans la VM

L'installation elle-même est classique — trois détails la font rater quand on ne les connaît pas.

1
Démarrer et « spammer » une touche

Se connecter à la VM, démarrer, puis appuyer répétitivement sur une touche : la fenêtre pour booter sur le DVD virtuel ne s'affiche que quelques secondes.

2
Choisir l'édition

Windows Server 2025 Standard (Desktop Experience) — c'est la version avec interface graphique.

3
Définir le mot de passe administrateur

Un mot de passe fort, jamais versionné ni recopié dans des notes partagées.

Aucun disque proposé à l'installation ?

Sur un serveur physique, cela signifie que Windows n'a pas le pilote du contrôleur de stockage : il faut le charger depuis l'assistant. En VM Hyper-V avec un Windows Server récent, le pilote du contrôleur virtuel est intégré : le disque apparaît d'office. S'il manque, c'est plutôt que la VM n'a pas de disque attaché.

Deux commandes de confort

Invite de commandes (admin)
# Réarmer la période d'évaluation (180 jours)
slmgr /rearm

Activer aussi la session étendue dans la fenêtre de connexion à la VM : l'affichage s'adapte alors dynamiquement à la taille de la fenêtre, et le presse-papiers devient partagé avec l'hôte.

04

Configurer le serveur au premier démarrage

Une check-list à dérouler dans l'ordre — le renommage en dernier, parce qu'il redémarre la machine.

1
Sortir du DHCP

Un serveur ne reste jamais en adressage automatique : son adresse doit être prévisible.

2
Fuseau horaire

Depuis Local Server dans le Gestionnaire de serveur.

3
IE Enhanced Security Configuration → OFF (jusqu'à 2022)

Sur Windows Server 2022 et avant, sans quoi le navigateur bloque à peu près tout. Windows Server 2025 n'embarque plus Internet Explorer : la ligne n'apparaît plus dans Local Server, on navigue avec Edge.

4
Configurer la carte réseau

Via le lien à droite d'Ethernet, ou Win+R → ncpa.cpl. Dans les propriétés : décocher IPv6, puis IPv4 en 192.168.1.1 / 255.255.255.0.

5
Autoriser le Bureau à distance

Allow remote connections to this computer — port RDP 3389.

6
Windows Update

Le passer en download updates only pour éviter un redémarrage en plein TP.

7
Renommer la machine — en dernier

Computer Name → Change → WS01. Cette opération redémarre le serveur, d'où sa position en fin de liste.

Le pare-feu en labo

Invite de commandes (admin)
# Désactiver le pare-feu sur tous les profils
netsh advfirewall set allprofiles state off

# Le réactiver — à faire dès que le TP est terminé
netsh advfirewall set allprofiles state on

Réservé au labo

Couper le pare-feu fait gagner du temps quand on débogue un TP, et uniquement dans ce cadre. Sur un serveur réel, on ouvre les ports nécessaires — on ne désarme pas la machine. Penser à le rallumer avant de faire un Sysprep : l'état est capturé dans l'image.

05

Sysprep : fabriquer une image réutilisable

Réinstaller Windows Server à chaque TP prend une demi-heure. Sysprep permet de le faire une fois, puis de repartir de cette image pour toutes les VM suivantes.

Sysprep « généralise » l'installation : il retire le SID unique de la machine, son nom et ses identifiants matériels. L'image redevient neutre, prête à être clonée.

1
Lancer l'outil

Ouvrir C:\Windows\System32\Sysprep et exécuter sysprep.exe.

2
Cocher « Generalize »

Et choisir Shutdown dans les options d'arrêt.

3
Ne pas rallumer la VM

Un seul démarrage suffirait à réattribuer un SID et à ruiner l'image.

4
Supprimer la VM dans Hyper-V Manager

Le disque virtuel reste sur le disque de l'hôte. Avant le Sysprep, la VM ne doit avoir aucun point de contrôle : sinon l'état généralisé est dans un fichier .avhdx à côté, et le .vhdx qu'on récupère n'est pas l'image finale. Supprimer les points de contrôle les fusionne dans le disque principal.

5
Isoler le disque

Aller dans C:\VM\WS01\Virtual Hard Disks, renommer WS01.vhdx en TEST-SYSPREP.vhdx, puis le copier dans un dossier parent dédié, par exemple C:\PARENT\.

6
Nettoyer

Supprimer C:\VM\WS01. Il ne reste que l'image, réutilisable indéfiniment.

À retenir

Le fichier C:\PARENT\TEST-SYSPREP.vhdx est désormais un disque parent en lecture seule de fait : il ne doit plus jamais être démarré ni modifié directement, sinon toutes les VM qui en dépendent deviennent inutilisables.

Question éclair

Sysprep vient d'éteindre la VM de référence. Un collègue la rallume « juste pour vérifier que tout va bien », puis l'éteint. Que vaut encore son disque comme image ?

Une image généralisée est faite pour un seul premier démarrage : celui de chaque VM qui en dérive. Si on l'a rallumée, on termine l'OOBE, puis on relance sysprep.exe (Generalize + Shutdown) avant d'archiver le disque.

06

Déployer des VM en série (disque parent)

Un disque de différenciation ne stocke que les écarts par rapport au disque parent. Créer une nouvelle VM revient alors à créer un fichier quasi vide — quelques secondes au lieu d'une installation complète.

1
Créer la VM sans disque

Même démarche qu'au chapitre 01, mais choisir « Attacher un disque dur virtuel ultérieurement ».

2
Ajouter le disque

Clic droit sur la machine → Paramètres → Contrôleur SCSI → Disque dur → Ajouter → Nouveau.

3
Type : Différenciation

C'est ce choix qui garantit que le sysprep d'origine ne sera jamais modifié.

4
Nommer et placer le disque enfant

Nom TEST-WS01-DISK1, emplacement C:\VM\TEST-WS01\.

5
Désigner le parent

C:\PARENT\TEST-SYSPREP.vhdx, puis Appliquer.

6
Corriger l'ordre de démarrage

Rubrique Microprogramme → booter sur le disque qui vient d'être créé.

7
Répéter pour la deuxième machine

TEST-WS02, adresse 192.168.1.2. Chaque VM finit la personnalisation de Windows à son premier démarrage.

Ce que le TP a montré

Les disques de différenciation sont pratiques mais les performances ne suivent pas : chaque lecture peut devoir traverser la chaîne parent/enfant. Pour un labo durable, un disque à taille dynamique classique est un meilleur compromis — on garde la différenciation pour du jetable qu'on recrée souvent.

Vérifier

La VM s'appuie-t-elle bien sur le disque parent ?

PowerShell — hôte
Get-VHD "C:\VM\TEST-WS01\TEST-WS01-DISK1.vhdx" | Select-Object VhdType, ParentPath

Sortie attendue

VhdType      ParentPath
-------      ----------
Differencing C:\PARENT\TEST-SYSPREP.vhdx

ParentPath introuvable : le disque parent a été déplacé ou renommé, et toutes les VM qui en dépendent refusent de démarrer. On le remet à sa place, ou on reconnecte l'enfant (Edit Disk → Reconnect).

Question éclair

Pour « mettre à jour l'image », quelqu'un a démarré une VM directement sur C:\PARENT\TEST-SYSPREP.vhdx et y a installé les correctifs. Le lendemain, TEST-WS01 et TEST-WS02 refusent de démarrer. Pourquoi ?

Un disque de différenciation enregistre des blocs par rapport à un état précis du parent. Modifier le parent casse tous ses enfants. Pour mettre l'image à jour, on crée une nouvelle image de référence (nouveau parent) et on y rattache les futures VM.

07

Choisir son commutateur virtuel

Le Gestionnaire de commutateur virtuel décide de qui peut parler à qui. Trois types, trois périmètres de plus en plus fermés.

TypeQui communiqueUsage
ExterneVM ↔ hôte ↔ réseau physique ↔ InternetLe commutateur se branche sur la carte physique de l'hôte ; l'hôte garde l'accès par une carte vEthernet (option Autoriser le système d'exploitation de gestion à partager). Quand les VM doivent être sur le réseau réel.
InterneVM ↔ VM ↔ hôteL'hôte reçoit une carte virtuelle vEthernet (nom) sur ce commutateur : VM et hôte se parlent, sans accès extérieur… sauf si l'hôte fait du NAT (lab Orion).
PrivéVM ↔ VM uniquementLe périmètre le plus fermé. Idéal pour un labo de domaine isolé.
1
Créer le commutateur

Hyper-V Manager → Gestionnaire de commutateur virtuel → type Privé → nom LAN1 → Appliquer.

2
Le raccorder aux VM

Dans les paramètres de chaque machine, sélectionner la nouvelle carte à la place du Default Switch.

Le réflexe du labo AD

Un domaine de test se monte sur un commutateur privé : le DHCP et le DNS du labo ne risquent alors pas de répondre sur le réseau de la maison ou de l'école. Si les VM ont besoin d'Internet ponctuellement (mises à jour), on leur ajoute une seconde carte sur un commutateur externe plutôt que de tout basculer. Autre solution, celle du lab Orion : un commutateur interne avec du NAT sur l'hôte (New-NetNat) — les VM sortent sur Internet, personne n'entre.

PowerShell (admin) — le réseau du lab Orion
New-VMSwitch -Name "LABOPS" -SwitchType Internal
New-NetIPAddress -InterfaceAlias "vEthernet (LABOPS)" -IPAddress 172.16.50.1 -PrefixLength 24   # l'hôte = passerelle
New-NetNat -Name "LABOPS-NAT" -InternalIPInterfaceAddressPrefix 172.16.50.0/24

À toi de taper

Crée en PowerShell un commutateur virtuel privé nommé LAN1.

Voir la solution

New-VMSwitch -Name "LAN1" -SwitchType Private. Pour un commutateur interne : -SwitchType Internal ; pour un externe, on donne la carte physique : -NetAdapterName "Ethernet".

Question éclair

Ton lab AD a son propre DHCP. Les VM doivent télécharger des mises à jour, mais le DHCP du lab ne doit en aucun cas répondre aux PC de la maison. Quel commutateur ?

Interne + New-NetNat : les VM sortent par l'hôte (traduction d'adresses), mais aucune trame du lab n'atteint le réseau physique — le DHCP reste confiné. C'est le choix du lab Orion.

08

Points de contrôle et vérifications

Un point de contrôle (checkpoint) fige l'état d'une VM pour pouvoir y revenir : c'est l'outil idéal d'un lab — tester, casser, revenir. À condition de savoir ce qu'il n'est pas : une sauvegarde.

Standard

Capture le disque et la mémoire : on revient exactement à l'instant figé, applications ouvertes. Le choix du lab, pour revenir avant une manipulation risquée.

Production (par défaut)

S'appuie sur les sauvegardes internes de l'OS invité (VSS sous Windows) : la VM revient comme après un arrêt propre, sans la mémoire. Plus sûr pour les applications et les bases de données.

PowerShell — hôte Hyper-V
Checkpoint-VM -Name SRV-FILE01 -SnapshotName "Avant DFS"          # figer
Get-VMSnapshot -VMName SRV-FILE01                                  # lister
Restore-VMSnapshot -VMName SRV-FILE01 -Name "Avant DFS" -Confirm:$false   # revenir
Remove-VMSnapshot -VMName SRV-FILE01 -Name "Avant DFS"             # supprimer = fusionner

Pas une sauvegarde

Un point de contrôle vit à côté du disque (fichier .avhdx) et sur le même stockage : si le disque de l'hôte meurt, tout part. Ce n'est pas une sauvegarde. Sur un contrôleur de domaine, Windows Server détecte le retour en arrière (identifiant de génération de la VM, depuis 2012) et se protège ; Microsoft déconseille malgré tout de s'en servir comme sauvegarde : on restaure une vraie sauvegarde de l'annuaire.

À retenir

Un point de contrôle avant chaque manipulation risquée du lab, supprimé ensuite pour ne pas allonger la chaîne de disques. Get-VHD (chapitre 06) pour vérifier qu'un disque enfant retrouve son parent.

Question éclair

SRV-FILE01 a un point de contrôle de la veille. Le SSD de l'hôte, qui porte tous les fichiers de la VM, tombe en panne. Que peux-tu récupérer grâce au point de contrôle ?

Un point de contrôle protège d'une mauvaise manipulation, pas d'une panne matérielle : il dépend du disque parent et vit sur le même stockage. Contre la panne, il faut une sauvegarde sur un autre support (module DPM).
