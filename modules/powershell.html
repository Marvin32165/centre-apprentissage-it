01

La console, l'aide et la découverte

PowerShell n'est pas un shell de texte : chaque commande renvoie des objets. Avant d'écrire du code, il faut savoir trouver seul une commande, lire son aide et inspecter ce qu'elle renvoie.

BesoinCommande
Trouver une commandeGet-Command -Verb New -Noun *VM* · Get-Command *dns*
Lire l'aide, avec exemplesGet-Help New-ADUser -Examples (une fois Update-Help passé)
Voir ce qu'un objet contientGet-Service | Get-Member
Connaître un aliasGet-Alias ls → Get-ChildItem

Les cmdlets suivent toutes le motif Verbe-Nom (Get-, New-, Set-, Remove-…) : connaître le verbe suffit souvent à deviner la commande. Deux versions cohabitent, et s'installent côte à côte sans se gêner :

Windows PowerShell 5.1PowerShell 7
LivraisonIntégré à Windows 10/11 et Windows Server, plus d'évolution (correctifs seulement)À installer (winget, MSI), versions régulières
Exécutablepowershell.exepwsh.exe
PlateformesWindows seulement (.NET Framework)Windows, Linux, macOS (.NET moderne)
Modules Windows (AD, DHCP, Hyper-V…)TousLa plupart directement, les autres via la couche de compatibilité Windows PowerShell
Nouveautés—ForEach-Object -Parallel, opérateurs ?? et ?:, && / ||

$PSVersionTable.PSVersion dit dans laquelle tu te trouves. Les scripts de ce module tournent dans les deux.

La stratégie d'exécution

Par défaut, Windows 11 refuse d'exécuter les scripts .ps1 (Restricted) ; Windows Server, lui, est en RemoteSigned. Pour ses propres scripts sur un poste : Set-ExecutionPolicy RemoteSigned -Scope CurrentUser — les scripts écrits localement tournent, ceux téléchargés d'Internet doivent être signés (ou débloqués avec Unblock-File après relecture). Get-ExecutionPolicy -List montre la stratégie de chaque portée. Ce n'est pas une barrière de sécurité, juste un garde-fou contre l'exécution accidentelle.

À toi de taper

Affiche les exemples d'utilisation de la cmdlet Get-ChildItem.

Voir la solution

Get-Help Get-ChildItem -Examples (ou help Get-ChildItem -Examples). Si l'aide est vide, lancer d'abord Update-Help en administrateur.

À retenir

Bloqué ? Get-Command pour trouver, Get-Help -Examples pour comprendre, Get-Member pour voir ce qu'un objet contient. Ces trois commandes répondent à presque tout sans quitter la console.

Question éclair

Sur ton poste Windows 11, .\Test-Lab.ps1, que tu viens d'écrire, répond « l'exécution de scripts est désactivée sur ce système ». Que fais-tu ?

Le poste est en Restricted : aucun script ne passe. RemoteSigned pour ton seul compte suffit — tes scripts tournent, ceux venus d'Internet restent contrôlés. Pas besoin d'être administrateur avec -Scope CurrentUser.

02

Variables, types et chaînes

Le premier exercice du cours déclare des variables, les affiche, les modifie et calcule avec. Trois choses à comprendre pour ne pas se faire piéger : le type, ce que renvoie Read-Host, et la différence entre guillemets doubles et simples.

PowerShell — l'essentiel de l'exercice « variables »
$ville = "Mons"                     # une chaîne
[int]$age = 23                     # un entier : le type est forcé
$taille = 183
$taille = $taille / 100            # 1.83 : la division donne un décimal
$age += 10                         # même chose que $age = $age + 10
$ville += "ville"                  # concaténation
"Tu as $age ans"                   # guillemets doubles : la variable est remplacée
'Tu as $age ans'                   # guillemets simples : texte littéral
$ville.Length                      # une chaîne est un objet : propriétés…
$ville.ToUpper()                   # …et méthodes

Le piège de Read-Host

Read-Host renvoie toujours une chaîne. Or + concatène les chaînes : "5" + "3" donne 53. Il faut convertir, soit en typant la variable ([int]$n = Read-Host "Nombre"), soit à la volée ([int]$saisie + 3). Règle utile : c'est le type de l'élément de gauche qui décide — 3 + "5" donne 8, "3" + 5 donne 35.

TypeExempleUsage
[string]"orion"Texte
[int] / [double]42 / 1.83Nombres entiers / décimaux
[bool]$true, $falseRésultat d'un test
[datetime]Get-DateDates : (Get-Date).AddDays(-7)
[array]@(1, 2, 3)Liste (chapitre 05)

Exercice — l'IMC du cours, corrigé

Avec $poids = 63 (kg) et $taille = 183 (cm), calcule l'IMC (poids ÷ taille en mètres au carré) et affiche « Ton IMC est de 18,8 » arrondi à une décimale.

Afficher la correction 
$taille = $taille / 100
$imc = $poids / ($taille * $taille)
"Ton IMC est de {0:N1}" -f $imc

L'opérateur -f formate : {0:N1} = le premier argument, une décimale. Plus propre que d'additionner des chaînes, et la virgule suit les réglages régionaux.

À retenir

Une variable a un type ; Read-Host renvoie du texte qu'il faut convertir. Guillemets doubles = interpolation, simples = littéral. -f pour formater un résultat.

Question éclair

$a = Read-Host "Nombre" (tu tapes 7), puis $a + 3. Qu'affiche PowerShell ?

Read-Host renvoie une chaîne, et c'est le type de l'élément de gauche qui décide : "7" + 3 donne "73". [int]$a + 3 ou 3 + $a donnent 10. $a.GetType().Name affiche String.

03

Comparer et décider

Les conditions du cours (pair ou impair, majeur ou mineur, année bissextile, mention d'une note) reposent sur des opérateurs de comparaison qui ne ressemblent pas à ceux des autres langages : pas de == ni de >, mais -eq et -gt.

OpérateurSensExemple
-eq / -neégal / différent$choix -eq 1
-gt / -ge / -lt / -le> / ≥ / < / ≤$age -ge 18
-likemotif avec jokers$prenom -like "A*"
-matchexpression régulière$ip -match "^172\.16\."
-in / -notinappartient à une liste$coup -in "pierre","papier","ciseaux"
-and / -or / -notet / ou / non($n % 2 -eq 0) -and ($n -gt 10)

Insensible à la casse

Par défaut, -eq, -like et -match ignorent majuscules et minuscules : "Pierre" -eq "pierre" vaut $true. Pour tenir compte de la casse : -ceq, -clike, -cmatch.

PowerShell — if, elseif, else, puis switch
[int]$note = Read-Host "Note sur 20"
if ($note -ge 16)     { "A" }
elseif ($note -ge 14) { "B" }
elseif ($note -ge 12) { "C" }
else                  { "Insuffisant" }

switch ([int](Read-Host "Mois (1-12)")) {
    2                      { "28 jours" }
    { $_ -in 4, 6, 9, 11 } { "30 jours" }
    default                { "31 jours" }
}

Exercice — année bissextile

Demande une année et affiche si elle est bissextile. Règle : divisible par 4, sauf les siècles, sauf les siècles divisibles par 400 (2000 l'est, 1900 non).

Afficher la correction 
[int]$a = Read-Host "Année"
if (($a % 4 -eq 0 -and $a % 100 -ne 0) -or ($a % 400 -eq 0)) { "$a est bissextile" }
else { "$a n'est pas bissextile" }

% donne le reste de la division : $a % 4 -eq 0 = « divisible par 4 ». Les parenthèses rendent la règle lisible.

À toi d'écrire

Écris la condition (sans if) qui vaut vrai si $n est pair et supérieur à 10.

Voir la solution

($n % 2 -eq 0) -and ($n -gt 10) — exercice 11 du cours.

À retenir

-eq -ne -gt -ge -lt -le, -like (jokers), -match (regex), -in (liste), insensibles à la casse par défaut. if/elseif/else pour quelques cas, switch pour beaucoup.

04

Les boucles

Répéter une action est la raison d'être d'un script d'administration : créer 50 comptes, vérifier 20 serveurs, parcourir un fichier. PowerShell offre quatre boucles, plus une cinquième dans le pipeline.

BoucleQuandExemple du cours
forUn compteur, un pasLes nombres pairs de 0 à 20
foreachChaque élément d'une listeChaque nom d'un fichier texte
whileTant qu'une condition est vraie (testée avant)Le menu de la calculatrice de température
do { } until ()Au moins une fois, jusqu'à une conditionRedemander une saisie invalide
ForEach-ObjectDans un pipeline, objet par objetGet-Content noms.txt | ForEach-Object { … }
PowerShell — trois boucles du cours
for ($i = 50; $i -ge 20; $i -= 2) { $i }               # pairs de 50 à 20, décroissant

$total = 0
$nombres = 1..10
foreach ($n in $nombres) { $total += $n }
$moyenne = $total / $nombres.Count                      # .Count évite un compteur à la main

foreach ($nom in Get-Content "C:\Lab\noms.txt") {      # chaque ligne d'un fichier
    Write-Host "Bonjour $nom"
}

break sort de la boucle, continue passe directement au tour suivant. Et pour un calcul comme la moyenne, PowerShell a déjà la réponse : (1..10 | Measure-Object -Average).Average.

À toi d'écrire

Écris une boucle for qui affiche les multiples de 3, de 3 à 30.

Voir la solution

for ($i = 3; $i -le 30; $i += 3) { $i } — départ, condition, pas. Variante en pipeline : 3..30 | Where-Object { $_ % 3 -eq 0 }.

À retenir

for pour compter, foreach pour parcourir, while/do-until pour attendre une condition, ForEach-Object dans un pipeline. Avant d'écrire une boucle de calcul, vérifier que Measure-Object ne le fait pas déjà.

05

Tableaux, tables de hachage et objets

Les vraies données d'administration sont des listes d'objets : des utilisateurs, des serveurs, des services. Savoir les fabriquer, les lire depuis un CSV et les réécrire, c'est l'essentiel de l'automatisation.

PowerShell — les trois structures
$serveurs = @("SRV-AD01", "SRV-AD02", "SRV-FILE01")      # tableau
$serveurs[0]; $serveurs.Count; $serveurs += "SRV-WEB01"

$ip = @{ "SRV-AD01" = "172.16.50.10"; "SRV-FILE01" = "172.16.50.20" }   # table de hachage
$ip["SRV-AD01"]

$vm = [PSCustomObject]@{ Nom = "SRV-WEB01"; IP = "172.16.50.25"; RAM = 4GB }   # objet
$vm.Nom

Le CSV, format d'échange de l'administrateur

PowerShell — lire, filtrer, écrire
$comptes = Import-Csv "C:\Lab\comptes.csv" -Delimiter ";"   # une ligne = un objet, une colonne = une propriété
$comptes | Where-Object Service -eq "Development" | Select-Object Prenom, Nom
Get-ADUser -Filter * -Properties Department |
    Select-Object Name, SamAccountName, Department |
    Export-Csv "C:\Lab\export.csv" -NoTypeInformation -Delimiter ";" -Encoding UTF8

Le point-virgule

Un CSV ouvert dans Excel en français utilise le point-virgule comme séparateur. Sans -Delimiter ";", PowerShell lit toute la ligne comme une seule colonne.

À retenir

Tableau @(), table de hachage @{}, objet [PSCustomObject]@{}. Import-Csv transforme un fichier en objets, Export-Csv fait l'inverse : c'est le pont entre un tableur et un script.

06

Le pipeline

Le pipeline | passe des objets d'une commande à la suivante, pas du texte. On filtre, on trie, on sélectionne, on regroupe, sans jamais découper de chaîne à la main.

CmdletRôleExemple
Where-ObjectFiltrerWhere-Object Status -eq Running
Select-ObjectChoisir des propriétés, ou les N premiersSelect-Object Name, Status -First 5
Sort-ObjectTrierSort-Object CPU -Descending
Group-ObjectRegrouper et compterGroup-Object Status
Measure-ObjectCompter, sommer, moyenneMeasure-Object Length -Sum
ForEach-ObjectAgir sur chaque objet ($_)ForEach-Object { $_.Name.ToUpper() }
PowerShell — trois questions d'administrateur, trois pipelines
# Les 5 processus qui consomment le plus de mémoire
Get-Process | Sort-Object WorkingSet64 -Descending | Select-Object Name, Id, WorkingSet64 -First 5
# Les services automatiques arrêtés (souvent une panne)
Get-Service | Where-Object { $_.StartType -eq 'Automatic' -and $_.Status -ne 'Running' }
# Les comptes AD qui ne se sont pas connectés depuis 90 jours
Search-ADAccount -AccountInactive -TimeSpan 90.00:00:00 -UsersOnly | Select-Object Name, LastLogonDate

Format-Table en dernier

Format-Table et Format-List transforment les objets en texte mis en page : après eux, plus rien d'utilisable. Ils ne se mettent qu'en fin de pipeline, et jamais avant Export-Csv.

À toi de taper

Affiche uniquement les services arrêtés (Status vaut Stopped).

Voir la solution

Get-Service | Where-Object Status -eq Stopped — ou, forme longue, Where-Object { $_.Status -eq 'Stopped' }. $_ (ou $PSItem) désigne l'objet en cours.

À retenir

Le pipeline transporte des objets : filtrer (Where), trier (Sort), choisir (Select), compter (Measure/Group), et ne mettre en forme qu'à la fin.

Question éclair

Get-Service | Format-Table Name, Status | Export-Csv services.csv produit un fichier plein de lignes illisibles (Microsoft.PowerShell.Commands.Internal.Format…). Pourquoi ?

Après Format-Table, le pipeline ne transporte plus des services mais des instructions d'affichage. On choisit les propriétés avec Select-Object : Get-Service | Select-Object Name, Status | Export-Csv services.csv -NoTypeInformation.

07

Fonctions, scripts et erreurs

Un bon script d'administration se relance sans danger, accepte des paramètres au lieu de valeurs écrites en dur, et s'arrête proprement quand quelque chose échoue.

PowerShell — une fonction avec paramètres et gestion d'erreur
function Test-Port {
    param(
        [Parameter(Mandatory)] [string] $Ordinateur,
        [int] $Port = 3389                       # valeur par défaut
    )
    try {
        $r = Test-NetConnection $Ordinateur -Port $Port -WarningAction SilentlyContinue -ErrorAction Stop
        [PSCustomObject]@{ Ordinateur = $Ordinateur; Port = $Port; Ouvert = $r.TcpTestSucceeded }
    }
    catch {
        Write-Warning "Test impossible vers $Ordinateur : $($_.Exception.Message)"
    }
}
"SRV-AD01", "SRV-FILE01" | ForEach-Object { Test-Port -Ordinateur $_ -Port 445 }
  • param() déclare les paramètres ; [Parameter(Mandatory)] les rend obligatoires (PowerShell les demande s'ils manquent).
  • try { } catch { } n'attrape que les erreurs bloquantes : beaucoup de cmdlets n'émettent que des erreurs non bloquantes, d'où -ErrorAction Stop.
  • Une fonction renvoie des objets (pas du texte avec Write-Host) : le résultat se trie, se filtre, s'exporte.
  • Ici, un port fermé n'est pas une erreur : Test-NetConnection renvoie simplement TcpTestSucceeded = False (avec un avertissement, masqué par -WarningAction SilentlyContinue). Le catch ne sert que pour les vraies erreurs.
  • Le même bloc param() en tête d'un fichier .ps1 en fait un script paramétrable : .\Test-Lab.ps1 -Ordinateur SRV-AD01.

À retenir

Des paramètres plutôt que des valeurs en dur, -ErrorAction Stop + try/catch pour décider quoi faire en cas d'échec, des objets en sortie. Un script qui respecte ces trois règles se réutilise.

Question éclair

Ton script fait try { Get-Item C:\Inexistant } catch { "Introuvable" }. L'erreur rouge s'affiche, mais jamais « Introuvable ». Que corriges-tu ?

Un chemin introuvable est une erreur non bloquante : la cmdlet l'affiche et continue, sans passer par catch. -ErrorAction Stop la rend bloquante pour cette commande ; $ErrorActionPreference = 'Stop' le fait pour tout le script.

08

Automatiser le lab Orion

Les scripts du cours rejouent tout le lab : création des VM, configuration réseau, annuaire. L'étape suivante est de les rendre génériques — une fonction et une liste plutôt qu'un bloc copié-collé par machine.

PowerShell — hôte Hyper-V : une fonction pour toutes les VM du lab
function New-LabVM {
    param([Parameter(Mandatory)] [string] $Nom, [int64] $Memoire = 4GB)
    $dossier = "C:\VM\LABOPS\$Nom"
    New-Item -ItemType Directory -Path $dossier -Force | Out-Null
    New-VHD -Path "$dossier\$Nom-DISK1-DIFF.vhdx" -ParentPath "C:\PARENT\TEST-SYSPREP.vhdx" -Differencing | Out-Null
    New-VM -Name $Nom -Generation 2 -MemoryStartupBytes $Memoire -VHDPath "$dossier\$Nom-DISK1-DIFF.vhdx" -Path $dossier -SwitchName "LABOPS" | Out-Null
    Set-VMMemory -VMName $Nom -DynamicMemoryEnabled $false
    Set-VMProcessor -VMName $Nom -Count 2
}
"SRV-AD01", "SRV-AD02", "SRV-FILE01" | ForEach-Object { New-LabVM -Nom $_ }

Lab guidé

Créer les comptes du domaine depuis un CSV

Objectif : remplacer dix commandes New-ADUser copiées-collées par un script qui lit un fichierPoint de départ : SRV-AD01 promu, l'arborescence ORION-DPT créée (module Windows Server)Durée : 30 min

  1. Créer C:\Lab\comptes.csv (séparateur point-virgule) :

    Prenom;Nom;Login;Service
Sacha;Somers;sso;Development
Bastien;Delmotte;bde;Accounting
Mathis;Thomas;mth;Management

  2. Le script :

    PowerShell — SRV-AD01
    $mdp = Read-Host -AsSecureString "Mot de passe initial"
Import-Csv "C:\Lab\comptes.csv" -Delimiter ";" | ForEach-Object {
    $ou = "OU=$($_.Service),OU=ORION-DPT,DC=orion,DC=local"
    New-ADUser -Name "$($_.Prenom) $($_.Nom)" -GivenName $_.Prenom -Surname $_.Nom `
        -SamAccountName $_.Login -UserPrincipalName "$($_.Login)@orion.local" `
        -Path $ou -AccountPassword $mdp -ChangePasswordAtLogon $true -Enabled $true
    Add-ADGroupMember -Identity "$(switch ($_.Service) { 'Development' {'DEV'} 'Accounting' {'ACC'} 'Management' {'MGMT'} })-GRP" -Members $_.Login
}

  3. Vérifier : Get-ADUser -Filter * -SearchBase "OU=ORION-DPT,DC=orion,DC=local" | Select-Object Name liste les trois comptes.

  4. Relancer le script : il échoue sur les comptes existants. L'améliorer pour qu'il saute un compte déjà présent (if (-not (Get-ADUser -Filter "SamAccountName -eq '$($_.Login)'")) { … }) : un script qu'on peut relancer sans danger est dit idempotent.

Le compte de service managé (gMSA), qui évite tout mot de passe de service à gérer, se crée aussi en PowerShell ; il est détaillé là où il sert, dans le module SQL Server.

À retenir

Une fonction paramétrée + une liste (ou un CSV) remplace les blocs copiés-collés. Un mot de passe se saisit avec Read-Host -AsSecureString, jamais en clair dans le script. Et un bon script se relance sans casser ce qui existe.

09

Administrer à distance

On n'ouvre pas une session graphique sur chaque serveur pour taper une commande. PowerShell exécute du code à distance par WinRM (ports 5985/5986), actif par défaut sur Windows Server (depuis 2012). 5985 = HTTP, mais le contenu reste chiffré par l'authentification Kerberos dans un domaine ; 5986 = HTTPS, avec un certificat.

CommandeCe qu'elle fait
Enter-PSSession SRV-FILE01Une session interactive à distance (l'invite devient [SRV-FILE01]: PS>)
Invoke-Command -ComputerName SRV-AD01, SRV-AD02 -ScriptBlock { … }Le même bloc sur plusieurs serveurs à la fois ; les résultats reviennent avec une propriété PSComputerName
Invoke-Command -VMName SRV-FILE01 -ScriptBlock { … }PowerShell Direct : depuis l'hôte Hyper-V vers une VM qui tourne sur cet hôte, sans réseau, avec un compte de la VM (-Credential) — idéal pour configurer une VM qui n'a pas encore d'adresse
Enable-PSRemotingActive WinRM sur une machine où il ne l'est pas (un poste Windows 11, par exemple)
PowerShell — l'état d'un service sur tous les DC
Invoke-Command -ComputerName SRV-AD01, SRV-AD02 -ScriptBlock {
    Get-Service NTDS, DNS, Netlogon | Select-Object Name, Status
} | Sort-Object PSComputerName

Vérifier

WinRM répond-il sur le serveur ?

PowerShell
Test-WSMan SRV-FILE01

Sortie attendue

wsmid           : http://schemas.dmtf.org/wbem/wsman/identity/1/wsmanidentity.xsd
ProtocolVersion : http://schemas.dmtf.org/wbem/wsman/1/wsman.xsd
ProductVendor   : Microsoft Corporation

Erreur WinRM : le pare-feu bloque 5985, le service WinRM est arrêté, ou la machine cible n'est pas dans le domaine (hors domaine, il faut configurer TrustedHosts ou passer en HTTPS).

À retenir

Invoke-Command pour plusieurs serveurs d'un coup, Enter-PSSession pour un seul en interactif, -VMName (PowerShell Direct) pour une VM sans réseau. WinRM écoute sur 5985.

Question éclair

Tu viens de créer SRV-WEB01 sur l'hôte Hyper-V : elle n'a ni adresse IP ni domaine. Comment lui passer New-NetIPAddress sans ouvrir sa console ?

PowerShell Direct (-VMName) passe par le bus de la VM, pas par le réseau. Il se lance depuis l'hôte Hyper-V, avec un compte de la VM (l'administrateur local tant qu'elle n'est pas dans le domaine).

10

Les projets du cours

L'exercice global du cours enchaîne quatre petits programmes : une calculatrice de température avec menu, une opération entre deux nombres, une table de multiplication, la suite de Fibonacci — puis un pierre-papier-ciseaux en trois manches gagnantes. Les refaire sans regarder est le meilleur test du module.

Projet 1 — la calculatrice de température

Un menu en boucle : 1 convertit des °C en °F, 2 des °F en °C, 0 quitte, tout autre choix affiche « Choix incorrect ». Formules : °F = °C × 9/5 + 32 ; °C = (°F − 32) × 5/9.

Afficher la correction 
do {
    $choix = Read-Host "1. °C vers °F`n2. °F vers °C`n0. Quitter"
    switch ($choix) {
        '1' { $c = [double](Read-Host "°C"); "$c °C = $($c * 9 / 5 + 32) °F" }
        '2' { $f = [double](Read-Host "°F"); "$f °F = $(($f - 32) * 5 / 9) °C" }
        '0' { "Au revoir" }
        default { "Choix incorrect" }
    }
} until ($choix -eq '0')

Par rapport à la version du cours : do/until évite la variable $stop, switch remplace la cascade de elseif, et [double] accepte les décimales.

Projet 2 — Fibonacci

Demande un nombre de termes N (au moins 2) et affiche les N premiers termes de la suite de Fibonacci (0, 1, 1, 2, 3, 5…).

Afficher la correction 
[int]$n = Read-Host "Nombre de termes"
$suite = [System.Collections.Generic.List[int]]@(0, 1)
while ($suite.Count -lt $n) { $suite.Add($suite[-1] + $suite[-2]) }
$suite -join ", "

$suite[-1] et $suite[-2] sont les deux derniers éléments. Une List s'agrandit sans recopier le tableau à chaque ajout, contrairement à += sur un tableau.

Projet 3 — pierre, papier, ciseaux, en mieux

La version du cours compare chaque combinaison dans un elseif (sept branches). Réécris la décision du vainqueur avec une table de hachage « ce qui bat quoi », et fais jouer le joueur 2 par l'ordinateur.

Afficher la correction 
$bat = @{ pierre = 'ciseaux'; papier = 'pierre'; ciseaux = 'papier' }
$s1 = 0; $s2 = 0
while ($s1 -lt 3 -and $s2 -lt 3) {
    $j1 = Read-Host "pierre, papier ou ciseaux"
    if ($j1 -notin $bat.Keys) { "Entrée invalide"; continue }
    $j2 = $bat.Keys | Get-Random
    if ($j1 -eq $j2)           { "Égalité ($j2)" }
    elseif ($bat[$j1] -eq $j2) { $s1++; "Gagné : $j1 bat $j2" }
    else                       { $s2++; "Perdu : $j2 bat $j1" }
    "Score $s1 - $s2"
}

La règle tient en une ligne de données au lieu de sept conditions : ajouter « lézard » et « Spock » ne demanderait que de changer la table.

À retenir

Refaire ces projets sans regarder la correction valide les chapitres 02 à 05. Le réflexe à garder : quand une cascade de elseif s'allonge, chercher la donnée (table de hachage) ou le switch qui la remplace.
