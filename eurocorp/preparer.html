1 · Préparer

Préparer l'hôte Hyper-V

Avant la première VM de ton site : le réseau virtuel, l'image parent et la façon de créer les machines. Ce qui est fait ici, on ne le refait pas vingt fois.

En bref

Une image Windows généralisée (C:\PARENT\TEST-SYSPREP.vhdx), un commutateur externe WAN et un commutateur privé par site. Les VM Windows sont des disques différentiels ; les VM Docker s'installent depuis l'ISO d'Ubuntu. Aucune mémoire dynamique.

Dans cette page Commutateurs · Image parent (réglages) · Sysprep · VM Windows · VM Linux · Ordre du jour

1Les commutateurs virtuels

Le réseau virtuel de chaque hôte : un commutateur externe vers la salle (côté WAN des pare-feu) et un commutateur privé par site (le LAN). Les VM du site ne parlent au reste du monde que par OPNsense.

Préparation

  1. Relever la carte réseau physique de l'hôte

    Get-NetAdapter : repère le nom de la carte branchée sur la salle (réseau 10.10.28.0/24). C'est elle que le commutateur externe va utiliser.

  2. Choisir les noms

    Externe : WAN. Privé : LAN-BRU, LAN-PAR, LAN-LON ou LAN-BER selon l'hôte. Les scripts du site (outil « Script Hyper-V ») utilisent ces noms.

Installation

  1. Créer le commutateur externe

    Hyper-V Manager → Virtual Switch Manager → External, ou :

    Hyper-V
    New-VMSwitch -Name "WAN" -NetAdapterName "Ethernet" -AllowManagementOS $true
  2. Créer le commutateur privé du site
    Hyper-V
    New-VMSwitch -Name "LAN-BRU" -SwitchType Private

    Un commutateur privé n'est relié ni à l'hôte ni à la salle : les VM du site s'y voient entre elles seulement.

Configuration

  1. Laisser l'hôte joignable

    -AllowManagementOS $true garde l'accès réseau de l'hôte (RDP) pendant que le commutateur externe prend la carte. Sans lui, tu te coupes de la machine.

Vérifications

  1. Lister les commutateurs
    Hyper-V
    Get-VMSwitch | Format-Table Name, SwitchType

    Attendu : WAN (External) et LAN-xxx (Private).

  2. Tester l'accès à la salle

    Depuis l'hôte : ping 10.10.28.254 doit répondre.

2L'image parent (sysprep)

Une seule installation de Windows Server, configurée une fois puis généralisée, sert de modèle à toutes les VM Windows. Chaque VM n'est ensuite qu'un disque différentiel léger qui ne stocke que ses différences. Tout ce que tu règles ici avant Sysprep, les 8 serveurs Windows l'auront ; tout ce que tu oublies, tu le referas 8 fois.

Préparation

  1. Réunir l'ISO

    Windows Server 2025 Standard, édition Desktop Experience (avec interface graphique).

  2. Créer la VM modèle

    Hyper-V Manager → New → Virtual Machine : nom SYSPREP, génération 2, mémoire de démarrage 8192 Mo avec « Use Dynamic Memory » décoché, connexion au commutateur LAN-xxx de l'hôte, disque virtuel de 127 Go, installation à partir de l'ISO.

  3. Réglages de la VM avant le démarrage

    Clic droit → Settings : Processor à 2 (la valeur par défaut prend tous les cœurs de l'hôte) ; Memory : mémoire dynamique toujours décochée ; Firmware : le DVD en premier pour installer. Pas de point de contrôle (checkpoint) sur cette VM : il compliquerait la fusion du disque.

  4. Garder la VM isolée du domaine

    Le modèle ne rejoint jamais le domaine et ne reçoit aucun logiciel propre à une machine (agent Zabbix, Wazuh, SQL…). Ces éléments se mettent sur chaque VM après son déploiement.

Installation

  1. Installer Windows

    Démarrer la VM, une touche pour booter sur l'ISO. Langue et clavier, Install now, édition Windows Server 2025 Standard (Desktop Experience), Custom: Install Windows only, sélectionner le disque non alloué, Next. Si aucun disque n'apparaît (serveur physique), c'est un pilote de stockage qui manque.

  2. Premier mot de passe administrateur

    Défini à la fin de l'installation. Même mot de passe pour tout le labo ? C'est le mot de passe local de toutes les VM clonées : choisis-en un solide et note-le dans Infos.md (jamais dans une fiche). LAPS le rendra unique par machine plus tard.

  3. Se connecter et activer la session étendue

    Pour afficher l'écran plein format et copier-coller : menu View → Enhanced Session dans la fenêtre de la VM.

Configuration

  1. 1. Réseau : IP fixe provisoire et IPv6 coupé

    Ne reste pas en DHCP. Win+R → ncpa.cpl → propriétés de la carte : décocher Internet Protocol Version 6, fixer une IPv4 provisoire de ton LAN (par exemple 172.17.x.5, masque 255.255.255.0). Ou en PowerShell :

    PowerShell
    New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 172.17.10.5 -PrefixLength 24 -DefaultGateway 172.17.10.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 172.17.10.10
Disable-NetAdapterBinding -Name "Ethernet" -ComponentID ms_tcpip6
  2. 2. Fuseau horaire

    Server Manager → Local Server → Time zone, ou :

    PowerShell
    Set-TimeZone -Id "Romance Standard Time"      # Bruxelles, Paris, Berlin
Get-TimeZone
  3. 3. Sécurité renforcée d'Internet Explorer

    Server Manager → Local Server → IE Enhanced Security Configuration → Off pour les administrateurs. Sans cela, chaque page web est bloquée par une alerte.

  4. 4. Bureau à distance

    Server Manager → Local Server → Remote Desktop → « Allow remote connections to this computer » (port RDP 3389). Ou :

    PowerShell
    Set-ItemProperty -Path "HKLM:\System\CurrentControlSet\Control\Terminal Server" -Name fDenyTSConnections -Value 0
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"
  5. 5. Pare-feu Windows coupé (laboratoire seulement)
    cmd
    netsh advfirewall set allprofiles state off

    Pratique de lab : sur le terrain, on garde le pare-feu actif et on ouvre les ports nécessaires. Le filtrage du labo est fait par OPNsense.

  6. 6. Mises à jour

    Server Manager → Local Server → Windows Update → Download updates only, puis installer toutes les mises à jour disponibles et redémarrer, jusqu'à ce que plus rien ne soit en attente. Ainsi, les 8 serveurs héritent d'un système à jour. Les mises à jour sortent le 2e mardi du mois.

  7. 7. Licence d'évaluation

    Sans clé, la période d'essai est de 180 jours. slmgr /rearm la renouvelle (6 à 7 fois au plus).

    cmd
    slmgr /dlv      # affiche la durée restante
slmgr /rearm    # redémarrage demandé
  8. 8. Disque : séparer système et données (facultatif)

    Dans ton exercice : partitionner le disque de 127 Go en C: (environ 40 %) et D: pour les données. Disk Management → clic droit sur C: → Shrink Volume → clic droit sur l'espace libéré → New Simple Volume, lettre D:, NTFS.

  9. 9. Nettoyer

    Vider la corbeille et les dossiers temporaires, fermer toutes les fenêtres, ne laisser aucune mise à jour en attente de redémarrage (un redémarrage en attente fait échouer Sysprep).

  10. 10. Renommer en dernier

    Le renommage redémarre la machine : à faire une fois tout le reste réglé. Sysprep réinitialisera de toute façon le nom, mais un nom clair (SYSPREP) évite la confusion.

    PowerShell
    Rename-Computer -NewName "SYSPREP" -Restart

Vérifications

  1. Contrôle avant Sysprep
    PowerShell
    Get-TimeZone | Select-Object Id
Get-NetIPAddress -AddressFamily IPv4 | Select-Object InterfaceAlias, IPAddress
(Get-NetFirewallProfile).Enabled          # False False False
Get-ItemProperty "HKLM:\System\CurrentControlSet\Control\Terminal Server" fDenyTSConnections   # 0
Get-HotFix | Measure-Object                # des correctifs sont installés

    Rien en attente : Get-WindowsUpdate n'est pas natif ; dans Settings → Windows Update, « You're up to date » et aucun redémarrage demandé.

3Généraliser avec Sysprep et ranger le parent

Sysprep supprime tout ce qui est propre à cette machine (identifiant de sécurité SID, nom, journaux) pour que chaque clone se comporte comme une installation neuve au premier démarrage. Opération sans retour : une fois généralisée, la VM ne sert plus qu'à produire le parent.

Préparation

  1. Tout est réglé

    Les 10 réglages de la section précédente sont faits et vérifiés. Une fois Sysprep lancé, on ne corrige plus rien sur ce disque.

  2. Faire une copie de secours (recommandé)

    Arrête la VM et copie son .vhdx à part avant de généraliser : si un réglage manque, tu repars de la copie au lieu de tout réinstaller.

Installation

  1. Lancer Sysprep

    Dans la VM : C:\Windows\System32\Sysprep\sysprep.exe. Options :

    • System Cleanup Action : Enter System Out-of-Box Experience (OOBE)
    • cocher Generalize
    • Shutdown Options : Shutdown

    Ou en ligne de commande :

    cmd (administrateur)
    C:\Windows\System32\Sysprep\sysprep.exe /oobe /generalize /shutdown
  2. Attendre l'arrêt, puis ne surtout pas rallumer

    La VM s'éteint seule. Ne la redémarre pas : le premier démarrage relancerait l'OOBE et le disque ne serait plus un modèle propre.

Configuration

  1. Fusionner les disques

    Dans Hyper-V Manager, supprimer la VM (clic droit → Delete). Cela fusionne les éventuels fichiers .avhdx dans le .vhdx ; le disque lui-même est conservé.

  2. Ranger le parent

    Sur l'hôte, dans le dossier de la VM (…\Virtual Hard Disks) : renommer le disque en TEST-SYSPREP.vhdx, le copier dans C:\PARENT\, puis supprimer le dossier de la VM d'origine.

    PowerShell
    New-Item -ItemType Directory C:\PARENT -Force
Move-Item "D:\VM\SYSPREP\Virtual Hard Disks\SYSPREP.vhdx" C:\PARENT\TEST-SYSPREP.vhdx
Set-ItemProperty C:\PARENT\TEST-SYSPREP.vhdx -Name IsReadOnly -Value $true
  3. Protéger le parent

    Propriétés du fichier → Lecture seule (fait par la dernière commande). Tous les différentiels en dépendent : le modifier ou le démarrer les casserait.

Vérifications

  1. Le parent est là et protégé
    PowerShell
    Get-Item C:\PARENT\TEST-SYSPREP.vhdx | Select-Object Name, Length, IsReadOnly
  2. Un clone démarre

    Voir la section suivante : crée une VM sur un disque différentiel, démarre-la. L'assistant de première configuration (OOBE) doit demander la langue puis un mot de passe administrateur. Si oui, le parent est bon.

  3. Deux clones ne se gênent pas

    Deux VM issues du même parent ont des SID différents et peuvent rejoindre le même domaine. C'est précisément ce que Sysprep garantit.

4Créer les VM Windows depuis le parent

Une VM = un disque différentiel + une définition. Elle démarre en quelques minutes au lieu de plusieurs heures d'installation.

Préparation

  1. Relire l'inventaire

    La page Infrastructure liste chaque VM de ton site avec ses vCPU et sa RAM. La RAM totale est indicative : toutes les VM ne tournent pas en même temps.

  2. Préparer un dossier

    Un dossier par hôte pour les VM, par exemple D:\VM (il doit exister).

Installation

  1. Créer le disque différentiel et la VM
    Hyper-V — une VM
    $parent = "C:\PARENT\TEST-SYSPREP.vhdx"
New-VHD -Path "D:\VM\BRU-DC01\BRU-DC01.vhdx" -ParentPath $parent -Differencing
New-VM -Name "BRU-DC01" -Generation 2 -MemoryStartupBytes 4GB -VHDPath "D:\VM\BRU-DC01\BRU-DC01.vhdx" -Path "D:\VM" -SwitchName "LAN-BRU"
Set-VMMemory -VMName "BRU-DC01" -DynamicMemoryEnabled $false
Set-VMProcessor -VMName "BRU-DC01" -Count 2

    Pour tout un site d'un coup, l'outil « Script Hyper-V » écrit ces commandes pour chaque VM du plan.

  2. Démarrer et finir l'OOBE

    Choisir la langue, le mot de passe administrateur. La VM est un clone du modèle : même contenu, nouvel identifiant (SID).

Configuration

  1. Configurer chaque VM

    IP fixe du plan, DNS vers le contrôleur de domaine, renommage, jonction au domaine : la marche à suivre le détaille machine par machine.

  2. Remarque sur les performances

    Un disque différentiel est un peu plus lent qu'un disque dynamique. Acceptable ici ; pour une VM très sollicitée (SQL), un disque dynamique est préférable.

Vérifications

  1. Contrôler les VM créées
    Hyper-V
    Get-VM | Format-Table Name, State, MemoryStartup, ProcessorCount, @{n="Dyn";e={(Get-VMMemory $_.Name).DynamicMemoryEnabled}}

    Attendu : mémoire dynamique à False partout, vCPU conformes à l'inventaire.

5Créer les VM Linux (Docker)

Les VM Docker n'utilisent pas le parent Windows : elles s'installent depuis l'ISO d'Ubuntu Server 24.04 LTS, une fois chacune.

Préparation

  1. Créer la VM

    Génération 2 · RAM selon l'inventaire, mémoire dynamique décochée · commutateur privé du site · disque 60 Go ou plus.

  2. Désactiver le démarrage sécurisé

    Settings → Security → décocher Enable Secure Boot (ou choisir le modèle « Microsoft UEFI Certificate Authority »). Sinon l'installeur Linux ne démarre pas.

Installation

  1. Installer Ubuntu Server

    Démarrer sur l'ISO. À l'écran réseau, passer l'interface en Manual : sous-réseau du site, adresse du plan, passerelle = OPNsense du site, DNS = contrôleur de domaine, domaine de recherche eurocorp.lan. Activer OpenSSH server.

  2. Installer Docker (dépôt officiel)

    Comme dans ton cours Docker, partie 3 :

    Ubuntu
    sudo apt update
sudo apt install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

    Le paquet docker-compose-plugin apporte la commande docker compose (en deux mots). Avec docker.io, Compose n'est pas inclus.

Configuration

  1. Enregistrer le nom dans le DNS

    Un enregistrement A par VM Docker sur le contrôleur de domaine (voir Identité).

  2. Droits Docker (facultatif)
    Ubuntu
    sudo usermod -aG docker $USER   # puis se reconnecter

    Sans cela, toute commande docker passe par sudo.

Vérifications

  1. Docker répond
    Ubuntu
    sudo docker run --rm hello-world
docker compose version

    Le premier télécharge l'image depuis le Docker Hub : la VM doit sortir sur Internet (règle de sortie du pare-feu, flux F28).

  2. Le réseau est bon
    Ubuntu
    ip a
ping -c2 172.17.10.1
ping -c2 172.17.10.10
nslookup bru-dc01.eurocorp.lan
