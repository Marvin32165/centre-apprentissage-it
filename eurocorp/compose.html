Docker Compose et .env

Générer un compose et son .env à partir de quelques champs, vérifier un compose existant, et retrouver les commandes de diagnostic. Tout se passe dans le navigateur : rien n'est envoyé.

En bref

Le générateur couvre les deux applications dont tu as les notes (Zabbix et Redmine). Le vérificateur marche pour n'importe quel compose, donc aussi pour Wazuh et Greenbone. Il signale les oublis fréquents, il ne remplace pas docker compose config sur la VM.

1Comment fonctionne le .env

Dans le dossier du docker-compose.yml, docker compose lit tout seul le fichier .env. Chaque ${VARIABLE} du compose est remplacée par la valeur du .env avant que les conteneurs ne démarrent. Le compose ne contient donc plus aucun mot de passe : on peut le lire, le montrer ou le commiter sans rien dévoiler. Dans ce labo les .env sont aussi commités, ce sont des valeurs jetables.

RèglePourquoi c'est important
CLE=valeur, sans espace autour du =CLE = valeur n'est pas lue : la variable reste vide.
Pas de guillemets nécessaires, sauf valeur avec espacesLes guillemets autour d'une valeur simple sont sans effet, mais un # précédé d'un espace commence un commentaire.
Un $ dans une valeur s'écrit $$Sinon il est pris pour une variable. Le plus simple : mots de passe alphanumériques, comme ceux du générateur.
${VAR:-défaut} dans le composeDonne une valeur de secours si VAR est absente. Sans défaut, une variable absente devient vide, sans erreur.
Une variable d'environnement du shell passe avant le .envSi un export POSTGRES_PASSWORD=… traîne dans la session, c'est lui qui gagne. Voir ce qui est réellement appliqué : docker compose config.
chmod 600 .env sur la VMSeul le propriétaire (root) lit le fichier. Git ne conserve pas ce droit : à refaire après chaque git clone.
Changer un mot de passe de base après le premier démarrageSans effet sur la base : le mot de passe n'est lu qu'à la création du volume. Soit on le change dans la base, soit on supprime le volume (docker compose down -v, perte des données).
Voir ce que Compose appliquera réellement
docker compose config          # compose complet avec les variables remplacées
docker compose config -q       # silencieux : n'affiche que les erreurs de syntaxe
docker compose config | grep -i password   # vérifier qu'une variable n'est pas vide

2Générateur

Choisis l'application, ajuste les champs : le compose, le .env, la configuration nginx (Redmine) et les commandes se mettent à jour. Les mots de passe sont tirés au hasard dans ton navigateur ; Générer en tire de nouveaux. Copie ou télécharge chaque fichier.

Wazuh et Greenbone

Le compose de Greenbone est celui du projet (script fetch-compose.sh du dossier 05-Docker/greenbone) et celui de Wazuh vient du dépôt officiel : ils sont trop longs et changent trop souvent pour être générés ici. Passe-les au vérificateur ci-dessous.

3Vérificateur

Colle un docker-compose.yml et son .env. Le contrôle cherche : variables manquantes ou inutilisées, mots de passe écrits en clair, restart absent, image sans version, volumes ou réseaux non déclarés, ports en double, base de données sans volume.

4Commandes de diagnostic

Celles que le cahier des charges demande de maîtriser. Ordre habituel quand « ça ne marche pas » : docker ps, puis docker logs.

CommandeCe qu'elle montreQuand l'utiliser
docker psLes conteneurs qui tournent, leurs ports et leur âgeUn conteneur « Restarting » ou absent : il plante.
docker compose psMême vue, limitée aux services du compose du dossierVérifier que toute la pile est « Up » (-a pour voir les arrêtés).
docker logs <nom> --tail 50Les dernières lignes de sortie du conteneurPremier réflexe après une erreur (mot de passe refusé, base introuvable, PSK inconnue…).
docker inspect <nom>Configuration complète : variables, montages, réseaux, IPVérifier quel volume est monté, quelle valeur a été reçue.
docker statsCPU, mémoire, réseau de chaque conteneur en directUn service lent ou une VM qui sature.
docker volume lsLes volumes persistantsConfirmer que les données survivent à un down (volumes présents).
docker network lsLes réseaux Docker (un par compose, plus ceux par défaut)Comprendre quels conteneurs se voient ; docker network inspect <réseau> pour le détail.
docker compose up -d <service>(Re)lance un seul service sans toucher aux autresAprès modification du compose ou du .env : Compose recrée ce qui a changé.
docker compose downArrête et supprime les conteneurs et réseaux, garde les volumesRepartir propre. Avec -v : supprime aussi les volumes (données perdues).
