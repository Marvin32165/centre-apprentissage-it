Docker

Configurer les .env

Les .env du livrable sont commités (valeurs jetables). Ce que fait chaque variable, pour pouvoir les refaire en comprenant.

En bref

Dossier 05-Docker/<appli>/ : un docker-compose.yml sans secret, un .env avec les valeurs, un .env.example vide. Sur la VM : copier le dossier, chmod 600 .env, docker compose config -q, docker compose up -d.

1Zabbix — BRU-DOCKER01

VariableRôleComment la choisir
POSTGRES_DBNom de la base ZabbixLibre, ex. zabbix. Le compose l'utilise pour le serveur et la base.
POSTGRES_USERCompte applicatifLibre, ex. zabbix.
POSTGRES_PASSWORDMot de passe de ce compteAlphanumérique, 20 caractères ou plus. Lu seulement à la 1re création du volume.

2Redmine — LON-DOCKER01

VariableRôleComment la choisir
MYSQL_DATABASEBase de RedmineLibre, ex. redmine.
MYSQL_USERCompte applicatif MariaDBLibre, ex. redmine.
MYSQL_PASSWORDMot de passe de ce compteAlphanumérique, 20+.
MYSQL_ROOT_PASSWORDMot de passe root MariaDBDifférent du précédent ; pour l'administration, pas pour Redmine.
REDMINE_SECRET_KEY_BASEClé qui signe les sessionsLongue chaîne aléatoire (64 hex). La changer déconnecte tout le monde.
Piège

Changer le mot de passe dans le .env après le premier démarrage ne change pas celui de la base. Soit tu le changes dans la base, soit docker compose down -v (données perdues).

3Ordre de travail

  1. Vérifier le compose avec l'outil Compose.
  2. docker compose config -q : aucune erreur.
  3. docker compose up -d, puis docker compose ps : tout « Up ».
  4. Si un service redémarre : docker logs <nom> --tail 50.
  5. Redmine : tester https://helpdesk.eurocorp.lan (certificat auto-signé : avertissement normal).
