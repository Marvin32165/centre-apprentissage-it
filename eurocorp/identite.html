3 · Identité

Active Directory, DNS et DHCP

Le socle dont tout le reste dépend : sans annuaire ni DNS, ni Exchange, ni SharePoint, ni Redmine (LDAP) ne fonctionnent.

En bref

Un domaine eurocorp.lan, un contrôleur par site, des sites AD qui reflètent les tunnels, un DHCP en failover, des groupes AGDLP, des politiques de mots de passe et LAPS. Les noms et les UO sont des propositions à valider.

Dans cette page Forêt et BRU-DC01 · Autres DC et sites AD · DHCP failover · UO, groupes, comptes

1La forêt et le premier contrôleur (BRU-DC01)

Le premier contrôleur crée la forêt eurocorp.lan et le DNS. Tout le reste (Exchange, SharePoint, Redmine en LDAP) en dépend : il doit être stable avant d'avancer. Scripts : 02-Initialize-EuroCorpServer, 04-New-EuroCorpForest, 06-New-EuroCorpDns (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. IP fixe et DNS sur lui-même

    Adresse 172.17.10.10, masque /24, passerelle 172.17.10.1. Le DNS préféré est lui-même (127.0.0.1 ou sa propre IP) : l'AD a besoin de son DNS pour fonctionner.

    PowerShell
    New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 172.17.10.10 -PrefixLength 24 -DefaultGateway 172.17.10.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 172.17.10.10
Disable-NetAdapterBinding -Name "Ethernet" -ComponentID ms_tcpip6
Rename-Computer -NewName "BRU-DC01" -Restart
    Pas à pas.
    1. Sur la VM, ouvre PowerShell en administrateur.
    2. Attribue l'adresse du plan : New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 172.17.10.10 -PrefixLength 24 -DefaultGateway 172.17.10.1.
    3. DNS = lui-même : Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 172.17.10.10.
    4. Coupe l'IPv6 : Disable-NetAdapterBinding -Name "Ethernet" -ComponentID ms_tcpip6.
    5. Renomme et redémarre : Rename-Computer -NewName "BRU-DC01" -Restart.
    Pourquoi. Un contrôleur de domaine a une adresse stable, et il est son propre serveur DNS : l'annuaire publie ses services (enregistrements SRV) dans sa zone DNS.
    Vérifier. Après redémarrage : hostname = BRU-DC01, ipconfig /all montre l'IP du plan et le DNS sur lui-même, ping 172.17.10.1 répond.
    Piège. Si l'alias de la carte n'est pas « Ethernet », lis-le avec Get-NetAdapter avant de lancer les commandes.
  2. Choisir le nom

    eurocorp.lan (NetBIOS EUROCORP). Déjà créé le jour 1 ; la suite sert de contrôle.

    Pas à pas.
    1. Domaine DNS : eurocorp.lan. Nom NetBIOS : EUROCORP.
    2. Vérifie ce qui existe déjà (jour 1) : Get-ADDomain sur BRU-DC01.
    Pourquoi. Le nom du domaine ne se change pas facilement après création : il faut qu'il soit définitif avant d'ajouter d'autres machines.
    Vérifier. Get-ADDomain renvoie DNSRoot : eurocorp.lan et NetBIOSName : EUROCORP.
    Piège. Utiliser un nom en .lan est courant en labo ; sur le terrain on préfère un sous-domaine d'un nom DNS réellement possédé (ad.exemple.be).

Installation

  1. Installer le rôle et créer la forêt
    PowerShell
    Install-WindowsFeature AD-Domain-Services, DNS -IncludeManagementTools
Install-ADDSForest -DomainName "eurocorp.lan" -DomainNetbiosName "EUROCORP" -InstallDns

    Le mot de passe de restauration (DSRM) est demandé : à noter dans Infos.md. La machine redémarre.

    Pas à pas.
    1. Installe les rôles : Install-WindowsFeature AD-Domain-Services, DNS -IncludeManagementTools.
    2. Promeus : Install-ADDSForest -DomainName "eurocorp.lan" -DomainNetbiosName "EUROCORP" -InstallDns.
    3. Saisis le mot de passe DSRM (mode de restauration des services d'annuaire) quand il est demandé, et note-le dans Infos.md.
    4. La machine redémarre seule : reconnecte-toi avec EUROCORP\Administrator.
    Pourquoi. C'est l'acte de naissance de l'annuaire : le premier contrôleur crée la forêt, le domaine, le DNS intégré et tous les rôles FSMO.
    Vérifier. Get-ADDomain et Get-ADForest répondent ; dcdiag /q n'affiche rien.
    Piège. Si un avertissement de délégation DNS apparaît, c'est normal en labo (pas de zone parente). Ne sers pas de cette machine avant la fin du redémarrage : la promotion peut prendre plusieurs minutes.

Configuration

  1. Zones DNS

    DNS Manager : zone directe eurocorp.lan (créée avec la forêt). Ajouter une zone inverse par LAN : dans l'assistant, saisir l'ID réseau sans le dernier octet (172.17.10), idem 172.17.20, .30, .40.

    Pas à pas.
    1. DNS Manager (Server Manager → Tools → DNS) → ton serveur → Forward Lookup Zones : la zone eurocorp.lan existe déjà.
    2. Clic droit sur Reverse Lookup Zones → New Zone… → Primary zone, « Store the zone in Active Directory ».
    3. Réplication : « To all DNS servers running on domain controllers in this domain ».
    4. IPv4 Reverse Lookup Zone → Network ID : 172.17.10. Mises à jour dynamiques sécurisées. Terminer.
    5. Répète pour 172.17.20, 172.17.30 et 172.17.40.
    Pourquoi. La zone inverse permet de retrouver un nom depuis une adresse (journaux, outils de sécurité, Kerberos dans certains cas).
    Vérifier. Les quatre zones inverses sont listées ; nslookup 172.17.10.10 renvoie bru-dc01.eurocorp.lan.
  2. Enregistrements du plan

    Les noms à créer :

    PowerShell
    Add-DnsServerResourceRecordA -ZoneName "eurocorp.lan" -Name "bru-dc01" -IPv4Address 172.17.10.10 -CreatePtr
Add-DnsServerResourceRecordCName -ZoneName "eurocorp.lan" -Name "helpdesk" -HostNameAlias "lon-docker01.eurocorp.lan"

    L'outil « Enregistrements DNS » de la page Outils écrit tout le lot.

    Pas à pas.
    1. Pour chaque serveur : Add-DnsServerResourceRecordA -ZoneName "eurocorp.lan" -Name "bru-dc01" -IPv4Address 172.17.10.10 -CreatePtr (le -CreatePtr crée aussi l'enregistrement inverse).
    2. Pour les alias : Add-DnsServerResourceRecordCName -ZoneName "eurocorp.lan" -Name "helpdesk" -HostNameAlias "lon-docker01.eurocorp.lan".
    3. Pour tout le lot d'un coup, utilise l'outil « Enregistrements DNS » de la page Outils qui produit toutes les commandes.
    Pourquoi. Les noms du plan sont les seuls utilisés dans les configurations (Zabbix, Wazuh, favoris) : si le DNS est faux, tout est faux.
    Vérifier. Get-DnsServerResourceRecord -ZoneName eurocorp.lan liste les enregistrements ; nslookup intranet.eurocorp.lan renvoie l'adresse virtuelle NLB.
    Piège. Les serveurs Windows joints au domaine s'inscrivent seuls ; les machines Linux et les adresses virtuelles se créent à la main.
  3. Source d'heure

    Sur le contrôleur qui porte le rôle PDC : w32tm /config /manualpeerlist:"<source>" /syncfromflags:manual /update. Les VM Linux se synchronisent ensuite dessus (chrony). Kerberos refuse un écart de plus de 5 minutes.

    Pas à pas.
    1. Repère le PDC : netdom query fsmo (ligne « PDC »).
    2. Sur ce contrôleur : w32tm /config /manualpeerlist:"pool.ntp.org" /syncfromflags:manual /reliable:yes /update puis Restart-Service w32time (en labo sans Internet, laisse l'horloge de l'hôte comme référence).
    3. Les autres machines du domaine se synchronisent seules sur le domaine ; les VM Linux sur le DC avec chrony (script 22).
    Pourquoi. Kerberos refuse une authentification si l'écart d'heure dépasse 5 minutes. Une seule source de référence évite les dérives.
    Vérifier. w32tm /query /status montre la source ; w32tm /stripchart /computer:bru-dc01 /samples:3 depuis un membre montre un écart de quelques millisecondes.
    Piège. Les VM Hyper-V peuvent aussi se synchroniser avec l'hôte (service d'intégration « Time Synchronization ») : décide d'une seule source pour éviter qu'elles se battent.

Vérifications

  1. Contrôle de santé
    PowerShell
    dcdiag /q
Get-ADDomain | Select-Object DNSRoot, NetBIOSName, PDCEmulator
nslookup eurocorp.lan 127.0.0.1

    dcdiag /q n'affiche que les erreurs : aucune sortie = bon signe. Le script Test-EuroCorpAD.ps1 du dossier 06-PowerShell fait un contrôle plus large.

    Pas à pas.
    1. dcdiag /q : n'affiche que les erreurs.
    2. Get-ADDomain | Select DNSRoot, NetBIOSName, PDCEmulator.
    3. nslookup eurocorp.lan 127.0.0.1 : le DNS local répond.
    4. Lance Test-EuroCorpAD.ps1 du dossier 06-PowerShell pour un contrôle plus large.
    Pourquoi. Un annuaire malade se découvre mieux ici qu'au moment de joindre le dixième serveur.
    Vérifier. dcdiag /q sans sortie ; les trois autres commandes répondent correctement.
    Piège. Une seule ligne d'erreur à ce stade mérite d'être comprise avant de continuer.

2Les autres contrôleurs et les sites AD

Un contrôleur par site (Paris d'abord). Les sites AD disent à l'annuaire quels réseaux sont « proches » : les clients de Londres s'authentifient auprès d'un contrôleur de Londres plutôt que de Bruxelles via le tunnel, et la réplication entre villes suit des liens planifiés. Scripts : 05-Add-EuroCorpDomainController, 07-New-EuroCorpAdSites (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. Les tunnels sont montés

    Paris doit joindre 172.17.10.10 (DNS, LDAP, RPC, SMB : flux F02 à F06). Un Test-NetConnection 172.17.10.10 -Port 389 depuis Paris doit réussir.

    Pas à pas.
    1. Depuis PAR-DC01 (ou un serveur de Paris), teste : Test-NetConnection 172.17.10.10 -Port 53, puis 389, 445, 135 et 88.
    2. Tous doivent renvoyer TcpTestSucceeded : True.
    Pourquoi. La promotion d'un contrôleur de domaine utilise DNS, LDAP, Kerberos, SMB et RPC vers le premier : si l'un est filtré, elle échoue en cours de route.
    Vérifier. Cinq tests réussis (flux F02 à F06).
    Piège. Ne tente pas la promotion tant que le tunnel et les règles ne sont pas validés (page Réseau).
  2. DNS de la future VM

    Avant la promotion, le DNS de PAR-DC01 pointe vers 172.17.10.10 : sans lui, impossible de joindre le domaine.

    Pas à pas.
    1. Sur PAR-DC01 : Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 172.17.10.10.
    2. Contrôle : nslookup eurocorp.lan doit renvoyer l'adresse de BRU-DC01.
    Pourquoi. Une machine ne trouve le domaine que par le DNS : si elle interroge un autre serveur, la jonction échoue avec « domain could not be contacted ».
    Vérifier. nslookup _ldap._tcp.dc._msdcs.eurocorp.lan renvoie BRU-DC01.

Installation

  1. Joindre le domaine puis promouvoir
    PowerShell sur PAR-DC01
    Add-Computer -DomainName eurocorp.lan -Restart
Install-WindowsFeature AD-Domain-Services, DNS -IncludeManagementTools
Install-ADDSDomainController -DomainName eurocorp.lan -InstallDns -Credential (Get-Credential)
    Pas à pas.
    1. Add-Computer -DomainName eurocorp.lan -Credential EUROCORP\Administrator -Restart.
    2. Reconnecte-toi, puis : Install-WindowsFeature AD-Domain-Services, DNS -IncludeManagementTools.
    3. Install-ADDSDomainController -DomainName eurocorp.lan -InstallDns -Credential (Get-Credential) -SiteName PAR (le site PAR doit exister, voir plus bas ; sinon le nom par défaut est utilisé).
    4. DSRM : un mot de passe pour ce contrôleur ; redémarrage automatique.
    Pourquoi. Un second contrôleur évite que la panne d'un seul serveur arrête tout le domaine, et il porte le failover DHCP.
    Vérifier. Après redémarrage, Get-ADDomainController -Filter * liste deux contrôleurs.
    Piège. Si la jonction échoue, la cause est presque toujours le DNS (étape précédente) ou le pare-feu entre les sites.
  2. Après la promotion

    Mettre le DNS de PAR-DC01 sur lui-même, avec 172.17.10.10 en secondaire (et inversement sur BRU-DC01). Le catalogue global est activé par défaut sur un nouveau contrôleur.

    Pas à pas.
    1. Sur PAR-DC01 : DNS préféré = lui-même (172.17.20.10), secondaire = 172.17.10.10.
    2. Sur BRU-DC01 : DNS préféré = lui-même, secondaire = 172.17.20.10.
    3. Contrôle : Get-ADDomainController -Filter * | Select Name, IsGlobalCatalog : les deux sont catalogue global.
    Pourquoi. Chaque contrôleur interroge d'abord sa propre copie, et en secours l'autre : bonne tenue si un DC tombe.
    Vérifier. Les deux DNS répondent et repadmin /replsummary ne montre pas d'erreur.
    Piège. Ne mets pas 127.0.0.1 comme secondaire sur le même serveur : il faut une adresse différente.

Configuration

  1. Créer les sites et leurs sous-réseaux

    Active Directory Sites and Services (ou l'outil « Sites AD ») :

    PowerShell
    New-ADReplicationSite -Name "BRU"
New-ADReplicationSite -Name "PAR"
New-ADReplicationSite -Name "LON"
New-ADReplicationSite -Name "BER"
New-ADReplicationSubnet -Name "172.17.10.0/24" -Site "BRU"
New-ADReplicationSubnet -Name "172.17.20.0/24" -Site "PAR"
New-ADReplicationSubnet -Name "172.17.30.0/24" -Site "LON"
New-ADReplicationSubnet -Name "172.17.40.0/24" -Site "BER"
    Pas à pas.
    1. Sur BRU-DC01, lance les commandes ci-dessous (ou ouvre Active Directory Sites and Services → Sites → New Site).
    2. Quatre sites : BRU, PAR, LON, BER. Chaque sous-réseau (172.17.x.0/24) est rattaché à son site.
    3. Le site « Default-First-Site-Name » peut être renommé en BRU plutôt que d'en créer un autre.
    Pourquoi. Les sites décrivent la topologie réelle : un client choisit un contrôleur de son site, et la réplication suit les liens plutôt que de tout envoyer partout.
    Vérifier. Get-ADReplicationSite -Filter * et Get-ADReplicationSubnet -Filter * montrent 4 sites et 4 sous-réseaux.
  2. Liens de sites en étoile

    Comme les tunnels : un lien entre Bruxelles et chaque autre site, coût et intervalle de réplication au choix (par exemple 15 minutes).

    PowerShell
    New-ADReplicationSiteLink -Name "BRU-PAR" -SitesIncluded BRU,PAR -Cost 100 -ReplicationFrequencyInMinutes 15
New-ADReplicationSiteLink -Name "BRU-LON" -SitesIncluded BRU,LON -Cost 100 -ReplicationFrequencyInMinutes 15
New-ADReplicationSiteLink -Name "BRU-BER" -SitesIncluded BRU,BER -Cost 100 -ReplicationFrequencyInMinutes 15
    Pas à pas.
    1. Pour chaque spoke, un lien avec Bruxelles : commandes ci-dessous (New-ADReplicationSiteLink).
    2. Supprime ou ajuste le lien par défaut DEFAULTIPSITELINK pour éviter un lien supplémentaire inutile.
    3. Coût 100 et fréquence 15 minutes sont des valeurs de labo.
    Pourquoi. La réplication entre sites suit ces liens, comme les tunnels IPsec : une étoile centrée sur Bruxelles.
    Vérifier. Get-ADReplicationSiteLink -Filter * liste BRU-PAR, BRU-LON, BRU-BER.
  3. Placer les contrôleurs dans leur site

    Move-ADDirectoryServer -Identity PAR-DC01 -Site PAR. Les serveurs de Londres et de Berlin utilisent les contrôleurs voisins tant qu'ils n'en ont pas.

    Pas à pas.
    1. Move-ADDirectoryServer -Identity PAR-DC01 -Site PAR.
    2. Vérifie : Get-ADDomainController -Filter * | Select Name, Site.
    Pourquoi. Un contrôleur dans le mauvais site fait répondre les clients de l'autre site depuis un serveur lointain.
    Vérifier. BRU-DC01 est dans BRU, PAR-DC01 dans PAR.
    Piège. Londres et Berlin n'ont pas de contrôleur : leurs clients utilisent les contrôleurs les plus proches par le coût des liens.

Vérifications

  1. La réplication fonctionne
    PowerShell
    repadmin /replsummary
repadmin /showrepl
Get-ADReplicationFailure -Target PAR-DC01

    Aucune erreur de réplication, delta récent entre les deux contrôleurs.

    Pas à pas.
    1. repadmin /replsummary : colonne « fails » à 0.
    2. repadmin /showrepl : dernier succès récent pour chaque partition.
    3. Get-ADReplicationFailure -Target PAR-DC01 : aucune ligne.
    Pourquoi. Une réplication cassée se voit tard et coûte cher : mieux vaut la contrôler maintenant.
    Vérifier. Aucune erreur, delta de quelques minutes au plus.
    Piège. Pour forcer : repadmin /syncall /AdeP.
  2. Les deux contrôleurs répondent
    PowerShell
    Get-ADDomainController -Filter * | Format-Table Name, Site, IPv4Address, IsGlobalCatalog
    Pas à pas.
    1. Get-ADDomainController -Filter * | Format-Table Name, Site, IPv4Address, IsGlobalCatalog.
    Pourquoi. Une vue d'ensemble rapide avant d'attaquer DHCP.
    Vérifier. Deux lignes, bon site, catalogue global à True.

3DHCP avec failover

Une étendue par site, plage dynamique .100–.199. Le failover fait tenir la même étendue sur deux serveurs (BRU-DC01 et PAR-DC01, proposition) : si l'un tombe, les clients obtiennent quand même une adresse. Les sites sans serveur utilisent le relais d'OPNsense (Réseau). Script : 08-New-EuroCorpDhcp (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. Les serveurs ont une IP fixe

    Le serveur DHCP lui-même n'est jamais en DHCP. Les imprimantes et serveurs peuvent avoir des réservations par adresse MAC.

    Pas à pas.
    1. Vérifie que chaque serveur du plan est hors de la plage .100–.199 (serveurs en .10–.49).
    2. Si une machine doit toujours obtenir la même adresse tout en restant en DHCP, crée une réservation par adresse MAC dans l'étendue.
    Pourquoi. Un serveur DHCP en DHCP n'a pas de sens, et une adresse de serveur dans le pool pourrait être donnée à un client.
    Vérifier. Les adresses du plan (.10 à .49) ne chevauchent pas la plage distribuée.
  2. Choisir le mode du failover

    Équilibré (50/50, les deux répondent) ou secours (un seul répond, l'autre attend). Durée du bail : 8 jours par défaut ; plus court (quelques heures) accélère la reprise après panne.

    Pas à pas.
    1. Mode Load balance (équilibré, 50/50) : les deux serveurs répondent.
    2. Mode Hot standby : un serveur répond, l'autre prend le relais en cas de panne.
    3. Durée du bail : 8 jours par défaut. Pour une reprise plus rapide, descends à quelques heures.
    Pourquoi. Dans un labo avec deux sites, l'équilibré montre que les deux DC travaillent ; le secours est plus simple à raisonner.
    Vérifier. Tu sais dire pourquoi tu as choisi ton mode et le noter dans le rapport.

Installation

  1. Installer le rôle
    PowerShell
    Install-WindowsFeature DHCP -IncludeManagementTools

    Le serveur doit être autorisé dans l'Active Directory : sans cela, il ne distribue rien dans un domaine.

    Pas à pas.
    1. Sur BRU-DC01 : Install-WindowsFeature DHCP -IncludeManagementTools.
    2. Répète sur PAR-DC01.
    3. Sans l'assistant graphique : crée les groupes de sécurité : Add-DhcpServerSecurityGroup, puis redémarre le service : Restart-Service dhcpserver.
    Pourquoi. Le rôle DHCP est installé ; il ne distribue rien tant qu'il n'est pas autorisé dans l'AD.
    Vérifier. Get-WindowsFeature DHCP indique Installed.
  2. Autoriser dans l'AD
    PowerShell
    Add-DhcpServerInDC -DnsName bru-dc01.eurocorp.lan -IPAddress 172.17.10.10
    Pas à pas.
    1. Add-DhcpServerInDC -DnsName bru-dc01.eurocorp.lan -IPAddress 172.17.10.10.
    2. Pareil pour PAR-DC01.
    3. Vérifie : Get-DhcpServerInDC.
    Pourquoi. Un serveur DHCP non autorisé s'arrête de lui-même : c'est la protection contre un faux serveur DHCP dans le domaine.
    Vérifier. Get-DhcpServerInDC liste les deux serveurs.

Configuration

  1. Créer les étendues
    PowerShell
    Add-DhcpServerv4Scope -Name "LAN-BRU" -StartRange 172.17.10.100 -EndRange 172.17.10.199 -SubnetMask 255.255.255.0
Set-DhcpServerv4OptionValue -ScopeId 172.17.10.0 -Router 172.17.10.1 -DnsServer 172.17.10.10,172.17.20.10 -DnsDomain eurocorp.lan
Add-DhcpServerv4Scope -Name "LAN-PAR" -StartRange 172.17.20.100 -EndRange 172.17.20.199 -SubnetMask 255.255.255.0
Set-DhcpServerv4OptionValue -ScopeId 172.17.20.0 -Router 172.17.20.1 -DnsServer 172.17.20.10,172.17.10.10 -DnsDomain eurocorp.lan
    Pas à pas.
    1. Pour chaque LAN : Add-DhcpServerv4Scope avec la plage .100–.199 et le masque 255.255.255.0.
    2. Set-DhcpServerv4OptionValue : routeur (passerelle du site), DNS (les deux DC), domaine eurocorp.lan.
    3. Active l'étendue : Set-DhcpServerv4Scope -ScopeId 172.17.10.0 -State Active.
    4. Fais les quatre étendues sur le serveur principal ; ceux de Londres et Berlin servent via le relais.
    Pourquoi. L'étendue est la plage d'adresses distribuée avec les paramètres que les clients reçoivent (passerelle, DNS, domaine).
    Vérifier. Get-DhcpServerv4Scope liste quatre étendues actives.
    Piège. Contrôle les options : une passerelle ou un DNS faux ne se voit que sur le client.
  2. Monter le failover
    PowerShell
    Add-DhcpServerv4Failover -ComputerName bru-dc01.eurocorp.lan -PartnerServer par-dc01.eurocorp.lan -Name "BRU-PAR" -ScopeId 172.17.10.0,172.17.20.0,172.17.30.0,172.17.40.0 -LoadBalancePercent 50 -SharedSecret "<secret>"

    Le secret partagé va dans Infos.md. Les étendues de Londres et de Berlin sont créées de la même façon et servent par relais.

    Pas à pas.
    1. Sur BRU-DC01, lance la commande ci-dessous (Add-DhcpServerv4Failover) avec les quatre étendues et -LoadBalancePercent 50.
    2. Saisis le secret partagé (à noter dans Infos.md).
    3. Ouvre TCP 647 entre les deux serveurs si ce n'est pas fait.
    Pourquoi. Le failover copie la configuration et synchronise les baux entre les deux serveurs : si l'un tombe, l'autre sert ses clients.
    Vérifier. Get-DhcpServerv4Failover : état Normal des deux côtés.
    Piège. Le secret partagé ne doit jamais figurer dans une fiche ou un script commité.

Vérifications

  1. Voir les étendues et leur partenaire
    PowerShell
    Get-DhcpServerv4Failover
Get-DhcpServerv4Scope
    Pas à pas.
    1. Get-DhcpServerv4Failover sur chaque serveur.
    2. Get-DhcpServerv4Scope : les étendues sont les mêmes des deux côtés.
    Pourquoi. Vérifie que la synchronisation s'est faite.
    Vérifier. Même liste d'étendues et état Normal.
  2. Tester avec un client

    Un poste Windows 11 en DHCP : ipconfig /release puis ipconfig /renew, l'adresse doit être dans la plage .100–.199. Le bail apparaît dans Address Leases.

    Pas à pas.
    1. Sur un poste Windows 11 de test en DHCP : ipconfig /release puis ipconfig /renew.
    2. ipconfig /all : adresse entre .100 et .199, passerelle et DNS corrects.
    3. Sur le serveur : console DHCP → Scope → Address Leases : le bail apparaît.
    Pourquoi. Preuve de bout en bout : client, relais, serveur.
    Vérifier. Adresse attendue et bail visible.
  3. Tester la panne

    Arrêter BRU-DC01 : un autre client obtient quand même une adresse (le partenaire répond). Séquence pour diagnostiquer : DISCOVER, OFFER, REQUEST, ACK.

    Pas à pas.
    1. Arrête le principal : Stop-VM BRU-DC01 (ou Stop-Service dhcpserver).
    2. Sur un autre client : ipconfig /release puis /renew.
    3. Il obtient quand même une adresse (PAR-DC01 répond).
    4. Relance le principal et vérifie le retour à Normal.
    Pourquoi. Un failover non testé est un failover supposé. Ce test est aussi une pièce du rapport.
    Vérifier. Adresse obtenue pendant la panne ; état Normal après reprise.
    Piège. Si le client reste sans adresse, regarde le relais DHCP du pare-feu : il doit viser les deux serveurs.

4Unités d'organisation, groupes AGDLP et comptes

On range les comptes par unités d'organisation (UO) et on donne les droits uniquement à des groupes. La règle AGDLP : les Acomptes vont dans des groupes Globaux (par service) ; ceux-ci vont dans des groupes Locaux de domaine (un par droit) ; seuls ces groupes reçoivent les Permissions sur les ressources. Script : 09-New-EuroCorpOuGroups (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. Choisir la structure

    Services du plan : Direction, RH, Finance, IT, plus Commun. Une UO racine EuroCorp avec Utilisateurs, Groupes, Serveurs, Postes. Propositions à valider.

    Pas à pas.

foreach ($ou in "Utilisateurs","Groupes","Serveurs","Postes") { New-ADOrganizationalUnit -Name $ou -Path "OU=EuroCorp,DC=eurocorp,DC=lan" }
foreach ($s in "Direction","RH","Finance","IT") {

    3. Ouvre Active Directory Users and Computers pour contrôler visuellement.
    Pourquoi. La structure est automatisée : reproductible et sans oubli.
    Vérifier. Get-ADOrganizationalUnit -Filter * | Select Name et Get-ADGroup -Filter "Name -like 'GG_*'".

Configuration

  1. Politique de mots de passe et de verrouillage

    GPO Default Domain Policy : longueur minimale 12 à 16, complexité, historique ; verrouillage après quelques échecs, durée et remise à zéro du compteur. Contre le bruteforce (événement 4625 dans le journal Sécurité).

    Pas à pas.
    1. Group Policy Management → Default Domain Policy → Edit.
    2. Computer Configuration → Policies → Windows Settings → Security Settings → Account Policies → Password Policy : longueur minimale 12 à 16, complexité activée, historique 24.
    3. Account Lockout Policy : seuil de quelques échecs (par exemple 5), durée de verrouillage et remise à zéro du compteur 15 à 30 minutes.
    4. Lance gpupdate /force sur un poste de test.
    Pourquoi. Réduit les attaques par force brute (événement 4625 dans le journal Sécurité).
    Vérifier. net accounts /domain affiche les valeurs.
    Piège. Dans un domaine, la politique de mots de passe se définit au niveau du domaine (Default Domain Policy) ou via des PSO pour des groupes précis.
  2. Administrateurs

    Comptes d'administration séparés des comptes du quotidien, moindre privilège, un compte admin par service.

    Pas à pas.
    1. Crée un compte d'administration par administrateur (par exemple adm_prénom), distinct du compte de tous les jours.
    2. Ajoute-le au groupe nécessaire (Domain Admins pour le labo uniquement).
    3. N'utilise jamais le compte quotidien pour administrer.
    Pourquoi. Principe du moindre privilège : si un compte du quotidien est compromis, il n'a pas les droits d'administration.
    Vérifier. Chaque administrateur a deux comptes ; Get-ADGroupMember "Domain Admins" ne liste que des comptes d'administration.
  3. LAPS : un mot de passe administrateur local unique par machine
    PowerShell
    Update-LapsADSchema                                   # une fois pour la forêt
Set-LapsADComputerSelfPermission -Identity "OU=Serveurs,OU=EuroCorp,DC=eurocorp,DC=lan"
New-ADGroup -Name "LAPS-Readers" -GroupScope Global
Set-LapsADReadPasswordPermission -Identity "OU=Serveurs,OU=EuroCorp,DC=eurocorp,DC=lan" -AllowedPrincipals "EUROCORP\LAPS-Readers"

    Une GPO est nécessaire (Computer Configuration → Administrative Templates → System → LAPS) : réglage Configure password backup directory = Active Directory, sinon rien n'est géré. Chiffrement des mots de passe : niveau fonctionnel du domaine 2016 minimum.

    Pas à pas.
    1. Une fois par forêt : Update-LapsADSchema.
    2. Donne aux ordinateurs le droit d'écrire leur mot de passe : Set-LapsADComputerSelfPermission -Identity "OU=Serveurs,OU=EuroCorp,DC=eurocorp,DC=lan".
    3. Crée le groupe qui peut lire : New-ADGroup -Name "LAPS-Readers" -GroupScope Global, puis Set-LapsADReadPasswordPermission.
    4. Crée une GPO liée à l'UO Serveurs : Computer Configuration → Administrative Templates → System → LAPS → Configure password backup directory = Active Directory.
    5. Sur un serveur : gpupdate /force puis Invoke-LapsPolicyProcessing.
    Pourquoi. Un même mot de passe administrateur local sur toutes les VM clonées est un risque : LAPS le remplace par un mot de passe unique, renouvelé, stocké dans l'AD.
    Vérifier. Get-LapsADPassword -Identity BRU-IIS01 -AsPlainText renvoie un mot de passe.
    Piège. Sans la GPO, LAPS ne gère rien : le schéma et les droits seuls ne suffisent pas.
  4. Clé racine KDS pour les gMSA
    PowerShell
    Add-KdsRootKey -EffectiveTime ((Get-Date).AddHours(-10))

    Une seule fois par forêt. Le décalage de -10 h rend la clé utilisable tout de suite : réservé au labo. Servira à SQL Server et SharePoint (page Services).

    Pas à pas.
    1. Add-KdsRootKey -EffectiveTime ((Get-Date).AddHours(-10)) sur un contrôleur.
    2. Contrôle : Get-KdsRootKey.
    Pourquoi. Les comptes de service gérés (gMSA) tirent leurs mots de passe de cette clé. Elle sert à SQL Server et SharePoint.
    Vérifier. Une clé est listée, avec une date d'effet déjà passée.
    Piège. Le décalage de -10 h ne se fait qu'en labo : en production il faut attendre 10 heures pour la réplication.
