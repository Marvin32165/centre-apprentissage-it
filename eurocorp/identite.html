Active Directory, DNS et DHCP

Le socle dont tout le reste dépend : sans annuaire ni DNS, ni Exchange, ni SharePoint, ni Redmine (LDAP) ne fonctionnent.

En bref

Un domaine eurocorp.lan, un contrôleur par site, des sites AD qui reflètent les tunnels, un DHCP en failover, des groupes AGDLP, des politiques de mots de passe et LAPS. Les noms et les UO sont des propositions à valider.

Dans cette page Forêt et BRU-DC01 · Autres DC et sites AD · DHCP failover · UO, groupes, comptes

1La forêt et le premier contrôleur (BRU-DC01)

Le premier contrôleur crée la forêt eurocorp.lan et le DNS. Tout le reste (Exchange, SharePoint, Redmine en LDAP) en dépend : il doit être stable avant d'avancer. Scripts : 02-Initialize-EuroCorpServer, 04-New-EuroCorpForest, 06-New-EuroCorpDns (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. IP fixe et DNS sur lui-même

    Adresse 172.17.10.10, masque /24, passerelle 172.17.10.1. Le DNS préféré est lui-même (127.0.0.1 ou sa propre IP) : l'AD a besoin de son DNS pour fonctionner.

    PowerShell
    New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 172.17.10.10 -PrefixLength 24 -DefaultGateway 172.17.10.1
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 172.17.10.10
Disable-NetAdapterBinding -Name "Ethernet" -ComponentID ms_tcpip6
Rename-Computer -NewName "BRU-DC01" -Restart
  2. Choisir le nom

    eurocorp.lan (NetBIOS EUROCORP). Déjà créé le jour 1 ; la suite sert de contrôle.

Installation

  1. Installer le rôle et créer la forêt
    PowerShell
    Install-WindowsFeature AD-Domain-Services, DNS -IncludeManagementTools
Install-ADDSForest -DomainName "eurocorp.lan" -DomainNetbiosName "EUROCORP" -InstallDns

    Le mot de passe de restauration (DSRM) est demandé : à noter dans Infos.md. La machine redémarre.

Configuration

  1. Zones DNS

    DNS Manager : zone directe eurocorp.lan (créée avec la forêt). Ajouter une zone inverse par LAN : dans l'assistant, saisir l'ID réseau sans le dernier octet (172.17.10), idem 172.17.20, .30, .40.

  2. Enregistrements du plan

    Les noms à créer :

    PowerShell
    Add-DnsServerResourceRecordA -ZoneName "eurocorp.lan" -Name "bru-dc01" -IPv4Address 172.17.10.10 -CreatePtr
Add-DnsServerResourceRecordCName -ZoneName "eurocorp.lan" -Name "helpdesk" -HostNameAlias "lon-docker01.eurocorp.lan"

    L'outil « Enregistrements DNS » de la page Outils écrit tout le lot.

  3. Source d'heure

    Sur le contrôleur qui porte le rôle PDC : w32tm /config /manualpeerlist:"<source>" /syncfromflags:manual /update. Les VM Linux se synchronisent ensuite dessus (chrony). Kerberos refuse un écart de plus de 5 minutes.

Vérifications

  1. Contrôle de santé
    PowerShell
    dcdiag /q
Get-ADDomain | Select-Object DNSRoot, NetBIOSName, PDCEmulator
nslookup eurocorp.lan 127.0.0.1

    dcdiag /q n'affiche que les erreurs : aucune sortie = bon signe. Le script Test-EuroCorpAD.ps1 du dossier 06-PowerShell fait un contrôle plus large.

2Les autres contrôleurs et les sites AD

Un contrôleur par site (Paris d'abord). Les sites AD disent à l'annuaire quels réseaux sont « proches » : les clients de Londres s'authentifient auprès d'un contrôleur de Londres plutôt que de Bruxelles via le tunnel, et la réplication entre villes suit des liens planifiés. Scripts : 05-Add-EuroCorpDomainController, 07-New-EuroCorpAdSites (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. Les tunnels sont montés

    Paris doit joindre 172.17.10.10 (DNS, LDAP, RPC, SMB : flux F02 à F06). Un Test-NetConnection 172.17.10.10 -Port 389 depuis Paris doit réussir.

  2. DNS de la future VM

    Avant la promotion, le DNS de PAR-DC01 pointe vers 172.17.10.10 : sans lui, impossible de joindre le domaine.

Installation

  1. Joindre le domaine puis promouvoir
    PowerShell sur PAR-DC01
    Add-Computer -DomainName eurocorp.lan -Restart
Install-WindowsFeature AD-Domain-Services, DNS -IncludeManagementTools
Install-ADDSDomainController -DomainName eurocorp.lan -InstallDns -Credential (Get-Credential)
  2. Après la promotion

    Mettre le DNS de PAR-DC01 sur lui-même, avec 172.17.10.10 en secondaire (et inversement sur BRU-DC01). Le catalogue global est activé par défaut sur un nouveau contrôleur.

Configuration

  1. Créer les sites et leurs sous-réseaux

    Active Directory Sites and Services (ou l'outil « Sites AD ») :

    PowerShell
    New-ADReplicationSite -Name "BRU"
New-ADReplicationSite -Name "PAR"
New-ADReplicationSite -Name "LON"
New-ADReplicationSite -Name "BER"
New-ADReplicationSubnet -Name "172.17.10.0/24" -Site "BRU"
New-ADReplicationSubnet -Name "172.17.20.0/24" -Site "PAR"
New-ADReplicationSubnet -Name "172.17.30.0/24" -Site "LON"
New-ADReplicationSubnet -Name "172.17.40.0/24" -Site "BER"
  2. Liens de sites en étoile

    Comme les tunnels : un lien entre Bruxelles et chaque autre site, coût et intervalle de réplication au choix (par exemple 15 minutes).

    PowerShell
    New-ADReplicationSiteLink -Name "BRU-PAR" -SitesIncluded BRU,PAR -Cost 100 -ReplicationFrequencyInMinutes 15
New-ADReplicationSiteLink -Name "BRU-LON" -SitesIncluded BRU,LON -Cost 100 -ReplicationFrequencyInMinutes 15
New-ADReplicationSiteLink -Name "BRU-BER" -SitesIncluded BRU,BER -Cost 100 -ReplicationFrequencyInMinutes 15
  3. Placer les contrôleurs dans leur site

    Move-ADDirectoryServer -Identity PAR-DC01 -Site PAR. Les serveurs de Londres et de Berlin utilisent les contrôleurs voisins tant qu'ils n'en ont pas.

Vérifications

  1. La réplication fonctionne
    PowerShell
    repadmin /replsummary
repadmin /showrepl
Get-ADReplicationFailure -Target PAR-DC01

    Aucune erreur de réplication, delta récent entre les deux contrôleurs.

  2. Les deux contrôleurs répondent
    PowerShell
    Get-ADDomainController -Filter * | Format-Table Name, Site, IPv4Address, IsGlobalCatalog

3DHCP avec failover

Une étendue par site, plage dynamique .100–.199. Le failover fait tenir la même étendue sur deux serveurs (BRU-DC01 et PAR-DC01, proposition) : si l'un tombe, les clients obtiennent quand même une adresse. Les sites sans serveur utilisent le relais d'OPNsense (Réseau). Script : 08-New-EuroCorpDhcp (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. Les serveurs ont une IP fixe

    Le serveur DHCP lui-même n'est jamais en DHCP. Les imprimantes et serveurs peuvent avoir des réservations par adresse MAC.

  2. Choisir le mode du failover

    Équilibré (50/50, les deux répondent) ou secours (un seul répond, l'autre attend). Durée du bail : 8 jours par défaut ; plus court (quelques heures) accélère la reprise après panne.

Installation

  1. Installer le rôle
    PowerShell
    Install-WindowsFeature DHCP -IncludeManagementTools

    Le serveur doit être autorisé dans l'Active Directory : sans cela, il ne distribue rien dans un domaine.

  2. Autoriser dans l'AD
    PowerShell
    Add-DhcpServerInDC -DnsName bru-dc01.eurocorp.lan -IPAddress 172.17.10.10

Configuration

  1. Créer les étendues
    PowerShell
    Add-DhcpServerv4Scope -Name "LAN-BRU" -StartRange 172.17.10.100 -EndRange 172.17.10.199 -SubnetMask 255.255.255.0
Set-DhcpServerv4OptionValue -ScopeId 172.17.10.0 -Router 172.17.10.1 -DnsServer 172.17.10.10,172.17.20.10 -DnsDomain eurocorp.lan
Add-DhcpServerv4Scope -Name "LAN-PAR" -StartRange 172.17.20.100 -EndRange 172.17.20.199 -SubnetMask 255.255.255.0
Set-DhcpServerv4OptionValue -ScopeId 172.17.20.0 -Router 172.17.20.1 -DnsServer 172.17.20.10,172.17.10.10 -DnsDomain eurocorp.lan
  2. Monter le failover
    PowerShell
    Add-DhcpServerv4Failover -ComputerName bru-dc01.eurocorp.lan -PartnerServer par-dc01.eurocorp.lan -Name "BRU-PAR" -ScopeId 172.17.10.0,172.17.20.0,172.17.30.0,172.17.40.0 -LoadBalancePercent 50 -SharedSecret "<secret>"

    Le secret partagé va dans Infos.md. Les étendues de Londres et de Berlin sont créées de la même façon et servent par relais.

Vérifications

  1. Voir les étendues et leur partenaire
    PowerShell
    Get-DhcpServerv4Failover
Get-DhcpServerv4Scope
  2. Tester avec un client

    Un poste Windows 11 en DHCP : ipconfig /release puis ipconfig /renew, l'adresse doit être dans la plage .100–.199. Le bail apparaît dans Address Leases.

  3. Tester la panne

    Arrêter BRU-DC01 : un autre client obtient quand même une adresse (le partenaire répond). Séquence pour diagnostiquer : DISCOVER, OFFER, REQUEST, ACK.

4Unités d'organisation, groupes AGDLP et comptes

On range les comptes par unités d'organisation (UO) et on donne les droits uniquement à des groupes. La règle AGDLP : les Acomptes vont dans des groupes Globaux (par service) ; ceux-ci vont dans des groupes Locaux de domaine (un par droit) ; seuls ces groupes reçoivent les Permissions sur les ressources. Script : 09-New-EuroCorpOuGroups (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. Choisir la structure

    Services du plan : Direction, RH, Finance, IT, plus Commun. Une UO racine EuroCorp avec Utilisateurs, Groupes, Serveurs, Postes. Propositions à valider.

  2. Convention de nommage des groupes

    Globaux : GG_Finance. Locaux de domaine : DL_Finance_Modifier, DL_Commun_Lecture.

Installation

  1. Créer UO et groupes
    PowerShell
    New-ADOrganizationalUnit -Name "EuroCorp" -Path "DC=eurocorp,DC=lan"
foreach ($ou in "Utilisateurs","Groupes","Serveurs","Postes") { New-ADOrganizationalUnit -Name $ou -Path "OU=EuroCorp,DC=eurocorp,DC=lan" }
foreach ($s in "Direction","RH","Finance","IT") {
  New-ADGroup -Name "GG_$s" -GroupScope Global -Path "OU=Groupes,OU=EuroCorp,DC=eurocorp,DC=lan"
  New-ADGroup -Name "DL_${s}_Modifier" -GroupScope DomainLocal -Path "OU=Groupes,OU=EuroCorp,DC=eurocorp,DC=lan"
  Add-ADGroupMember -Identity "DL_${s}_Modifier" -Members "GG_$s"
}
  2. Créer les comptes

    L'outil « Créer des utilisateurs AD » de la page Outils génère le script New-ADUser depuis une liste « prénom;nom;service ». Le mot de passe est demandé au lancement, jamais écrit dans le script.

Configuration

  1. Politique de mots de passe et de verrouillage

    GPO Default Domain Policy : longueur minimale 12 à 16, complexité, historique ; verrouillage après quelques échecs, durée et remise à zéro du compteur. Contre le bruteforce (événement 4625 dans le journal Sécurité).

  2. Administrateurs

    Comptes d'administration séparés des comptes du quotidien, moindre privilège, un compte admin par service.

  3. LAPS : un mot de passe administrateur local unique par machine
    PowerShell
    Update-LapsADSchema                                   # une fois pour la forêt
Set-LapsADComputerSelfPermission -Identity "OU=Serveurs,OU=EuroCorp,DC=eurocorp,DC=lan"
New-ADGroup -Name "LAPS-Readers" -GroupScope Global
Set-LapsADReadPasswordPermission -Identity "OU=Serveurs,OU=EuroCorp,DC=eurocorp,DC=lan" -AllowedPrincipals "EUROCORP\LAPS-Readers"

    Une GPO est nécessaire (Computer Configuration → Administrative Templates → System → LAPS) : réglage Configure password backup directory = Active Directory, sinon rien n'est géré. Chiffrement des mots de passe : niveau fonctionnel du domaine 2016 minimum.

  4. Clé racine KDS pour les gMSA
    PowerShell
    Add-KdsRootKey -EffectiveTime ((Get-Date).AddHours(-10))

    Une seule fois par forêt. Le décalage de -10 h rend la clé utilisable tout de suite : réservé au labo. Servira à SQL Server et SharePoint (page Services).

Vérifications

  1. Les objets existent
    PowerShell
    Get-ADOrganizationalUnit -Filter * | Select-Object Name
Get-ADGroupMember DL_Finance_Modifier
Get-KdsRootKey
  2. Un compte se connecte

    Depuis un poste du domaine, ouvrir une session avec un compte créé ; whoami /groups montre ses groupes.

  3. LAPS lit un mot de passe
    PowerShell
    Invoke-LapsPolicyProcessing   # sur le serveur
Get-LapsADPassword -Identity BRU-IIS01 -AsPlainText

    Événement 10018 dans le journal LAPS = mot de passe mis à jour dans l'AD.
