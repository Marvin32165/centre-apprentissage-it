Ressources des VM (plan → réel)

  • DC-PARIS : 2 vCPU / 4 Go → 12 vCPU / 8 Go. AD-BXL : 4 vCPU / 4 Go. PAR-FW01 : 2 / 2 Go → 4 / 8 Go.
  • PAR-SP01 : 4 / 12 Go (conforme). PAR-SQL01 : 4 / 8 Go (conforme) ; disque système 127 Go (plan 100).
  • Exchange : 16 Go alloués alors qu'Exchange n'est pas installé.

Configuration

  • Fuseau horaire : PAR-FW01 et BRU-FW01 en UTC (plan : Europe/Paris) ; EXCHANGE en heure du Pacifique ; les autres machines en Europe/Paris.
  • Source d'heure : les DC (PAR-DC01, AD-BXL) prennent l'heure du service d'intégration Hyper-V ; seul LON-FS01 se synchronise sur AD-BXL.
  • Redirecteurs DNS : PAR-DC01 → 172.17.20.1, AD-BXL → 172.17.10.1 (le pare-feu local) ; pas de redirecteur commun.
  • DNS des serveurs : BER-DOCKER01 et BER-DOCKER02 ont 10.10.28.254 (passerelle de salle) comme DNS en plus des DC ; BER-DOCKER02 n'a pas PAR-DC01.
  • AD-BXL a le rôle AD CS (non listé dans les rôles imposés de Paris ; à confirmer côté Bruxelles).
  • GP-* : vides alors que la nomenclature AGDLP est exigée ; pas de GPO créée.
  • Mises à jour : Paris/Londres (octobre-novembre 2026) contre Bruxelles (novembre 2025).
  • NLB : cluster intranet.eurocorp.lan (172.17.10.20) en unicast avec deux cartes par serveur ; le guide laisse le choix unicast/multicast ouvert.

Pare-feu (écarts avec « règles limitées au strict nécessaire »)

  • PAR-FW01 : règle « TEMP - accès GUI depuis WAN » (443 depuis 10.10.28.0/24), SSH activé avec connexion root, « Default allow LAN to any » toujours présente.
  • BRU-FW01 : règle « temp ssh » (TCP 22 depuis n'importe quelle source vers le pare-feu), « Pass RPC 135 interne » (any → GRP2_FW:135), une règle sans description (LAN_SITES → 172.17.10.20:80), « Default allow LAN to any » ; mot de passe root par défaut.
  • Paris n'a pas de règles de transit F09/F19/F21 (Bruxelles les a) : tant que LAN → any existe, les flux passent ; en la retirant, il faudra les écrire.
  • Alias SRV_SQL utilisé dans les règles (adresse non vérifiée ici).

Hyper-V et infrastructure

  • Replica : exigé par l'énoncé (LON-FS01 → Paris), non configuré nulle part.
  • Routes : 3 hôtes ont des routes permanentes vers les 4 LAN (conforme au fichier d'accès) ; l'hôte de Paris n'en a pas, alors que le fichier d'accès dit que tous en ont.
  • Cartes APIPA (169.254.x.x) sur les hôtes de Bruxelles, Londres et Berlin (adresse de lien local en plus de l'IP de salle).
  • Checkpoints présents à Bruxelles et à Paris, absents à Londres et Berlin : approche non homogène ; disques différentiels là où il y a des checkpoints.
  • VM Linux : BER-DOCKER01 100 Go de disque mais volume LVM de 48 Go ; LON-DOCKER01 héberge deux piles du guide (actuelle et ancienne).

Supervision

  • Wazuh : 14 agents Active (plan : tous les serveurs) ; Sysmon absent (le guide l'exige) ; événements Docker non encore observés.
  • Zabbix : serveur en marche mais aucun agent déployé (le guide en prévoit sur tous les hôtes et serveurs) ; dashboard en HTTP seulement (port 80).
  • Pare-feu OPNsense et hôtes Hyper-V : pas d'agent Wazuh (pas de syslog distant configuré).
