07 — Sauvegarde, restauration, PRA

Rédigé d'après 05-Docker/redmine/backup-redmine.sh (lu) ; la partie Replica vient de mes connaissances générales, non vérifiée dans la documentation Microsoft. Aucune commande n'a été exécutée : tout est à valider sur les VM. Les décisions (RPO, RTO, fréquence) sont à toi.

1. Redmine (LON-DOCKER01)

Ce que sauvegarde le script (backup-redmine.sh, dossier de déploiement /opt/redmine) : la base MariaDB (mariadb-dump, compressée), les fichiers Redmine (volume redmine-files, archive tar.gz), une copie du docker-compose.yml et du .env ; il refuse une sauvegarde vide et garde 7 jours (RETENTION_DAYS).

Planifier (cron root, ex. chaque nuit à 2 h — fréquence à choisir) :

0 2 * * * /opt/redmine/backup-redmine.sh >> /var/log/redmine-backup.log 2>&1

Restaurer (à tester d'abord sur une copie) :

  1. Choisir la sauvegarde : ls /opt/redmine/backups/.
  2. Arrêter l'application, garder la base : docker compose stop redmine nginx.
  3. Base : gunzip -c <sauvegarde>/redmine-db.sql.gz | docker exec -i redmine-db mariadb --user=<MYSQL_USER> --password=<MYSQL_PASSWORD> <MYSQL_DATABASE> (valeurs du .env).
  4. Fichiers : docker run --rm --volumes-from redmine-app -v <sauvegarde>:/backup alpine tar xzf /backup/redmine-files.tar.gz -C /usr/src/redmine/files.
  5. Relancer : docker compose up -d, puis vérifier la connexion et un ticket existant.

Test de restauration obligatoire : sans lui, la sauvegarde n'est qu'une hypothèse. Noter la date et le résultat dans 09-Tests.

2. Hyper-V Replica de LON-FS01 vers Paris

À remplir par toi après décision :

Question Ta décision Pourquoi
Fréquence de réplication (30 s, 5 min, 15 min) RPO = au plus cet intervalle
RPO accepté données perdues au pire
RTO accepté temps pour repartir à Paris
Authentification (Kerberos / certificat) Kerberos si les hôtes sont dans le domaine

Étapes (à lancer à la main ou avec les cmdlets Set-VMReplicationServer, Enable-VMReplication, Start-VMInitialReplication) :

  1. Hôte de Paris : accepter les réplications entrantes et ouvrir le port (80 pour Kerberos).
  2. Hôte de Londres : activer la réplication de LON-FS01, puis lancer la réplication initiale.
  3. Vérifier : Get-VMReplication (État et Santé).
  4. Test de basculement (sans interrompre la production) : créer la VM de test à Paris, vérifier qu'elle démarre et que les partages répondent, puis la supprimer.
  5. Basculement planifié : arrêter la VM à Londres, Planned Failover, démarrer à Paris ; le retour se fait par réplication inversée puis un second basculement planifié.

4. Où est la sauvegarde

Un PRA suppose que la copie ne soit pas sur la même machine que l'original : copier backups/ vers un autre hôte (à décider : lequel).
