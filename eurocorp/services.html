4 · Services

Fichiers, web, messagerie, SharePoint

Ce que les utilisateurs voient. Chaque service dépend de l'annuaire et du DNS : ne démarre pas avant que l'identité soit stable.

En bref

Quatre services, chacun en quatre phases : fichiers à Londres, IIS en NLB à Bruxelles, Exchange à Bruxelles avec une autorité de certification interne, SQL et SharePoint à Paris avec un gMSA. Les choix (NLB unicast ou multicast, noms, tailles) sont à toi.

Dans cette page Fichiers · IIS + NLB · Exchange + AD CS · SQL + SharePoint

1Serveur de fichiers (LON-FS01)

Les dossiers des services (Direction, RH, Finance, IT, Commun) sur un serveur de Londres, avec les droits donnés uniquement par groupes (AGDLP, page Identité). Réplica Hyper-V prévue vers Paris (page Exploitation). Script : 11-New-EuroCorpFileShares (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. Disque de données

    Un second disque (VHDX) pour les données, formaté en NTFS, lettre D:. Jamais sur C:.

  2. Joindre le domaine

    IP 172.17.30.10, DNS vers les contrôleurs, Add-Computer -DomainName eurocorp.lan, puis déplacer l'objet dans l'UO Serveurs.

  3. Les groupes existent

    GG_Direction, DL_Direction_Modifier… créés à l'étape précédente.

Installation

  1. Installer les rôles
    PowerShell
    Install-WindowsFeature FS-FileServer, FS-DFS-Namespace, FS-Resource-Manager -IncludeManagementTools

    FS-Resource-Manager (FSRM) ajoute quotas de dossiers et filtres de fichiers.

Configuration

  1. Créer les dossiers et les partages
    PowerShell
    foreach ($d in "Direction","RH","Finance","IT","Commun") {
  New-Item -ItemType Directory -Path "D:\Data\$d" -Force | Out-Null
  New-SmbShare -Name $d -Path "D:\Data\$d" -FullAccess "EUROCORP\Admins du domaine" -ChangeAccess "EUROCORP\DL_${d}_Modifier"
}

    Chemin UNC : \\LON-FS01\Finance. Les permissions de partage et NTFS s'additionnent par le réseau : le droit effectif est le plus restrictif des deux. Mettre le partage large et régler finement en NTFS.

  2. Permissions NTFS par groupes
    PowerShell
    $acl = Get-Acl "D:\Data\Finance"
$acl.SetAccessRuleProtection($true,$false)      # coupe l'héritage
$r = New-Object Security.AccessControl.FileSystemAccessRule("EUROCORP\DL_Finance_Modifier","Modify","ContainerInherit,ObjectInherit","None","Allow")
$acl.AddAccessRule($r); Set-Acl "D:\Data\Finance" $acl

    Un refus explicite prime sur une autorisation ; une permission explicite prime sur une héritée.

  3. Espace de noms DFS

    Un chemin unique indépendant du serveur : \\eurocorp.lan\Files. DFS Management → New Namespace → basé sur le domaine ; un dossier par service dont la cible pointe vers le partage. Pas de réplication DFS ici : une seule cible par dossier.

  4. Quotas (facultatif)

    FSRM : modèle de quota par dossier avec seuil d'alerte. EFS chiffre des fichiers NTFS : sauvegarder le certificat et la clé privée, sinon les fichiers sont perdus.

Vérifications

  1. Lister les partages
    PowerShell
    Get-SmbShare
Get-SmbShareAccess -Name Finance
  2. Tester avec deux comptes

    Un membre de GG_Finance écrit dans Finance ; un membre de GG_RH est refusé. Le chemin DFS \\eurocorp.lan\Files\Finance s'ouvre depuis un poste.

2IIS et équilibrage de charge NLB (BRU-IIS01 / 02)

Deux serveurs web derrière une adresse virtuelle (172.17.10.20, intranet.eurocorp.lan). IIS est le serveur web de Microsoft, livré comme rôle de Windows Server ; NLB répartit les connexions entre les deux nœuds. Scripts : 12-Set-EuroCorpNlbHost, 13-New-EuroCorpNlb (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. Les deux VM sont dans le domaine

    BRU-IIS01 172.17.10.21, BRU-IIS02 172.17.10.22, DNS vers 172.17.10.10. Chaque nœud doit avoir une seule carte réseau pour simplifier.

  2. Choisir le mode NLB

    Unicast : tous les nœuds prennent la même adresse MAC ; sur Hyper-V il faut autoriser l'usurpation de MAC et les nœuds ne se parlent plus entre eux par cette carte. Multicast : MAC de groupe, nécessite que le réseau accepte ce type de trame. Décision à prendre avant de créer le cluster.

  3. Réserver l'adresse virtuelle

    172.17.10.20 est hors de la plage DHCP (.100–.199) : elle ne doit être attribuée à aucune machine.

Installation

  1. Installer IIS
    PowerShell
    Install-WindowsFeature Web-Server -IncludeManagementTools

    Ou Server Manager → Add roles and features → Role-based → Web Server (IIS). Rien d'autre à cocher : les modules (FTP, ASP.NET…) s'ajoutent après coup.

  2. Installer NLB
    PowerShell
    Install-WindowsFeature NLB -IncludeManagementTools

    Sur les deux nœuds.

Configuration

  1. Un site avec son propre nom

    Ne pas déposer le contenu dans le site par défaut (C:\inetpub\wwwroot) : mauvaise pratique. IIS Manager → clic droit Sites → Add Website : nom, chemin physique en dehors de wwwroot, host name intranet.eurocorp.lan. Le host name permet plusieurs sites sur la même IP et le même port 80 : IIS lit l'en-tête Host.

  2. Le nom dans le DNS

    Un enregistrement A intranet → 172.17.10.20 (l'adresse virtuelle). Pour les autres sites, des alias CNAME vers le nom du serveur : si l'IP change, une seule ligne est à corriger.

  3. Pool d'applications

    Un site = son pool (créé automatiquement). Identité par défaut ApplicationPoolIdentity ; un compte de domaine seulement si le site doit accéder à une ressource protégée.

  4. Contenu identique sur les deux nœuds

    Même dossier, même contenu : copie manuelle, DFS ou robocopy. NLB répartit les connexions, il ne synchronise pas les fichiers.

  5. MAC spoofing (unicast seulement)

    Settings de chaque VM → Network Adapter → Advanced Features → Enable MAC address spoofing.

  6. Créer le cluster NLB

    Network Load Balancing Manager → New Cluster : hôte BRU-IIS01, interface du LAN, adresse virtuelle 172.17.10.20, mode choisi, règle de ports 80 (et 443). Puis Add Host to Cluster pour BRU-IIS02.

  7. FTP (facultatif)

    Ajouter Web Server → FTP Server, clic droit sur le site → Add FTP Site : authentification Basic avec les comptes du domaine, autorisation EUROCORP\Domain Users en lecture/écriture. Sans SSL, identifiants et fichiers circulent en clair : labo seulement.

Vérifications

  1. Chaque nœud répond seul

    http://172.17.10.21 et http://172.17.10.22 affichent la page.

  2. L'adresse virtuelle répond

    http://intranet.eurocorp.lan depuis un poste de Paris (à travers le tunnel).

    PowerShell
    Resolve-DnsName intranet.eurocorp.lan
Invoke-WebRequest http://intranet.eurocorp.lan -UseBasicParsing | Select-Object StatusCode
  3. La bascule

    Arrêter le site (ou la VM) d'un nœud : l'adresse virtuelle reste joignable. Noter le résultat dans 09-Tests.

3Messagerie : Exchange Server et autorité de certification (BRU-EXCH01)

Exchange stocke les boîtes aux lettres dans des fichiers ESE (.edb plus journaux .log). Les certificats viennent d'une autorité interne (AD CS) installée sur un contrôleur de domaine, pas sur Exchange.

Préparation

  1. Machine et prérequis

    172.17.10.30, 16 Go de RAM, jointe au domaine. Disque séparé pour les bases (.edb) et un autre pour les journaux (.log) : jamais sur C: en production, compter 2 à 3 Go par boîte.

  2. Préparer l'annuaire

    Compte membre de Schema Admins et Enterprise Admins. Depuis le média Exchange, sur un contrôleur ou le serveur :

    cmd
    Setup.exe /IAcceptExchangeServerLicenseTerms_DiagnosticDataOFF /PrepareSchema
Setup.exe /IAcceptExchangeServerLicenseTerms_DiagnosticDataOFF /PrepareAD /OrganizationName:"EuroCorp"
  3. Installer l'autorité de certification d'abord

    Sinon, certificats auto-signés partout.

    PowerShell sur BRU-DC01
    Install-WindowsFeature AD-Certificate, ADCS-Web-Enrollment -IncludeManagementTools
Install-AdcsCertificationAuthority -CAType EnterpriseRootCA -CACommonName "EUROCORP-CA" -KeyLength 2048 -HashAlgorithmName SHA256 -Force
Install-AdcsWebEnrollment -Force

Installation

  1. Prérequis logiciels d'Exchange

    Les composants listés par l'assistant (Visual C++, .NET, URL Rewrite, rôles Windows). L'installeur les contrôle et indique ce qui manque.

  2. Installer le rôle Mailbox
    cmd
    Setup.exe /Mode:Install /Roles:Mailbox /IAcceptExchangeServerLicenseTerms_DiagnosticDataOFF

    Le serveur redémarre. Outils ensuite : EAC (https://<serveur>/ecp) et EMS (Exchange Management Shell).

Configuration

  1. Base de données et boîtes
    EMS
    New-MailboxDatabase -Name "DB01" -Server "BRU-EXCH01" -EdbFilePath "E:\Exchange\DB01\DB01.edb" -LogFolderPath "F:\Exchange\Logs\DB01"
Mount-Database -Identity "DB01"
Enable-Mailbox -Identity "jean.dupont" -Database "DB01"
New-Mailbox -Name "Support Technique" -Alias support -Shared

    Quatre types : utilisateur, partagée (sans connexion directe, par délégation), salle, équipement.

  2. Boîte partagée : droits
    EMS
    Add-MailboxPermission -Identity support -User jean.dupont -AccessRights FullAccess -InheritanceType All
Add-ADPermission -Identity support -User jean.dupont -ExtendedRights "Send As"

    Sur Exchange sur site, Add-RecipientPermission n'existe pas (c'est une cmdlet du cloud).

  3. Connecteurs

    Réception : Default Frontend (25) et Client Frontend (587) sont créés à l'installation. Envoi : à créer (absent par défaut).

    EMS
    New-SendConnector -Name "Envoi Internet" -AddressSpaces "SMTP:*;1" -DNSRoutingEnabled $true -SourceTransportServers "BRU-EXCH01"

    Un relais pour une application : limiter aux IP sources de confiance. Jamais un open relay (anonyme vers tous les domaines).

  4. DNS de la messagerie

    Enregistrements mail (A vers 172.17.10.30) et autodiscover (CNAME vers mail). Autodiscover configure Outlook tout seul.

  5. Certificat signé par l'AC interne
    EMS
    $req = New-ExchangeCertificate -GenerateRequest -SubjectName 'CN=mail.eurocorp.lan' -DomainName 'mail.eurocorp.lan','autodiscover.eurocorp.lan','BRU-EXCH01' -PrivateKeyExportable $true
Set-Content C:\Temp\exchange.csr -Value $req

    Sur http://<AC>/certsrv : Demander un certificat → avancée, coller la demande, modèle Serveur Web, attributs SAN (dns=mail…&dns=autodiscover…). Télécharger le certificat en Base 64, l'importer, puis :

    EMS
    $t = (Get-ExchangeCertificate | ? Subject -like '*mail.eurocorp.lan*').Thumbprint
Enable-ExchangeCertificate -Thumbprint $t -Services 'IIS,SMTP'
  6. Faire confiance à l'autorité

    Importer le certificat racine de l'AC dans le magasin « Autorités de certification racines de confiance » de tous les postes, par GPO : plus d'avertissement dans le navigateur. Redémarrer IIS (iisreset).

Vérifications

  1. Santé du serveur
    EMS
    Get-MailboxDatabase -Status | ft Name, Mounted, DatabaseSize, MailboxCount
Test-ServiceHealth
Get-ExchangeCertificate | ft Thumbprint, Services, Status
  2. Webmail

    https://mail.eurocorp.lan/owa avec un compte du domaine, sans avertissement de certificat sur un poste qui fait confiance à l'AC.

  3. Flux de courrier
    EMS
    Test-Mailflow -TargetEmailAddress jean.dupont@eurocorp.lan
Get-Queue | ft Identity, Status, MessageCount
Get-MessageTrackingLog -Recipients jean.dupont@eurocorp.lan -Start (Get-Date).AddHours(-1)

    Un message qui n'arrive pas : suivi (FAIL) → file d'attente (LastError) → connecteur d'envoi → MX → port 25.

4SQL Server et SharePoint (PAR-SQL01 / PAR-SP01)

SharePoint stocke tout dans SQL Server. Les services tournent sous des comptes dédiés ; le moteur SQL sous un gMSA dont l'Active Directory gère le mot de passe. Ne jamais installer SharePoint avec un compte Domain Admin. Script : 10-New-EuroCorpGmsa (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. Comptes de service

    Dans l'AD : sp_farm (compte de ferme), sp_setup (installation, administrateur local de PAR-SP01), sp_services (pools d'applications), sp_search (recherche). sp_farm et sp_setup ont besoin des droits SQL dbcreator et securityadmin.

  2. Le gMSA du moteur SQL
    PowerShell sur BRU-DC01
    # la clé KDS existe déjà (page Identité)
New-ADOrganizationalUnit -Name GMSA -Path "DC=eurocorp,DC=lan"
New-ADGroup -Name GM_GMSA_SQL -GroupScope Global -Path "OU=GMSA,DC=eurocorp,DC=lan"
Add-ADGroupMember -Identity GM_GMSA_SQL -Members (Get-ADComputer PAR-SQL01)
New-ADServiceAccount GMSA_SQL -DNSHostName gmsa_sql.eurocorp.lan -PrincipalsAllowedToRetrieveManagedPassword GM_GMSA_SQL

    Le compte ordinateur de PAR-SQL01 (pas un utilisateur) doit être membre du groupe.

  3. Sur PAR-SQL01 : prendre en compte le groupe
    PowerShell
    klist purge -li 0x3e7
gpupdate /force /target:computer
Install-WindowsFeature RSAT-AD-PowerShell
Install-ADServiceAccount GMSA_SQL
Test-ADServiceAccount GMSA_SQL        # doit répondre True

    False = le ticket Kerberos de la machine est antérieur à l'ajout au groupe : purger ou redémarrer.

  4. Disques de SQL

    Disques séparés pour les données (D:), les journaux (L:) et tempdb (T:). Un disque ajouté après l'activation de la réplication Hyper-V n'est pas répliqué : réintégrer le disque dans la réplication.

  5. Dimensionnement

    PAR-SQL01 : 8 Go ; PAR-SP01 : 12 Go (le guide SharePoint indique 12 à 16 Go pour une ferme de test).

Installation

  1. Installer SQL Server (instance nommée)

    Média SQL Server 2022, New SQL Server stand-alone installation. Édition Developer (labo). Fonctionnalités : Database Engine Services et Full-Text and Semantic Extractions for Search (indispensable à la recherche SharePoint). Instance nommée SHAREPOINT. Authentification Windows. Administrateurs SQL : sp_farm, sp_setup, ton compte.

  2. Écran critique : le classement (collation)

    Onglet Collation → Customize : Latin1_General_CI_AS_KS_WS. SharePoint refuse toute autre collation ; à régler à l'installation, pas après.

  3. Comptes de service du moteur

    Dans l'assistant, ou après (SQL Server Configuration Manager) : moteur et Agent sous EUROCORP\GMSA_SQL$ — avec le $, mot de passe vide. Le service SQL Server Browser reste en démarrage automatique (indispensable avec une instance nommée).

Configuration

  1. Protocole et port

    SQL Server Configuration Manager → Protocols for SHAREPOINT → TCP/IP : Enable. Propriétés → IP Addresses → IPAll : vider « TCP Dynamic Ports », fixer « TCP Port » à 1433. Redémarrer le service.

  2. Pare-feu
    PowerShell
    New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
New-NetFirewallRule -DisplayName "SQL Browser (UDP 1434)" -Direction Inbound -Protocol UDP -LocalPort 1434 -Action Allow
  3. Mémoire et parallélisme

    Mémoire max du serveur (par exemple 10240 Mo sur 16 Go ; adapter à 8 Go de RAM) et MAXDOP égal au nombre de cœurs. Agent SQL en démarrage automatique si des jobs sont planifiés.

  4. Installer SharePoint sur PAR-SP01

    Connecté en sp_setup : lancer prerequisiteinstaller.exe (peut redémarrer 2 à 3 fois), puis setup.exe (clé ou évaluation 180 jours). Décocher « Run the Configuration Wizard now ».

  5. Assistant de configuration de la ferme

    SharePoint Products Configuration Wizard : créer une nouvelle ferme · serveur de base de données PAR-SQL01\SHAREPOINT · base SP_Config · compte de ferme sp_farm · phrase secrète (à noter, indispensable pour ajouter des serveurs) · Administration centrale sur le port 2016 · NTLM.

  6. Comptes gérés et applications de service

    Administration centrale → Security → Configure Managed Accounts : enregistrer sp_services et sp_search. Manage Services on Server : démarrer au minimum la Foundation Web Application et SharePoint Server Search. Créer les applications de service : Managed Metadata, Search, User Profile.

  7. DNS et premier site

    Enregistrement A intranet pour SharePoint (si distinct de l'intranet IIS, prendre un autre nom, par exemple sharepoint → 172.17.20.21). Application web sur le port 80 : base de contenu SP_Content_Intranet, pool sous sp_services ; puis une Site Collection modèle Team Site, administrateur sp_setup.

Vérifications

  1. SQL accessible depuis SharePoint
    PowerShell sur PAR-SP01
    Test-NetConnection 172.17.20.20 -Port 1433
  2. Les services SQL tournent sous le gMSA

    Colonne Log On As du Configuration Manager : EUROCORP\GMSA_SQL$ pour le moteur et l'Agent ; Browser sous LOCALSERVICE (normal).

  3. Classement correct
    T-SQL
    SELECT SERVERPROPERTY('Collation');

    Doit renvoyer Latin1_General_CI_AS_KS_WS.

  4. SharePoint répond

    Administration centrale : http://PAR-SP01:2016 ; site : http://<nom du site>. Créer une bibliothèque de documents, activer le versioning, déposer un fichier et regarder l'historique des versions.
