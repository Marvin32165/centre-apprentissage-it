4 · Services

Fichiers, web, messagerie, SharePoint

Ce que les utilisateurs voient. Chaque service dépend de l'annuaire et du DNS : ne démarre pas avant que l'identité soit stable.

En bref

Quatre services, chacun en quatre phases : fichiers à Londres, IIS en NLB à Bruxelles, Exchange à Bruxelles avec une autorité de certification interne, SQL et SharePoint à Paris avec un gMSA. Les choix (NLB unicast ou multicast, noms, tailles) sont à toi.

Dans cette page Fichiers · IIS + NLB · Exchange + AD CS · SQL + SharePoint

1Serveur de fichiers (LON-FS01)

Les dossiers des services (Direction, RH, Finance, IT, Commun) sur un serveur de Londres, avec les droits donnés uniquement par groupes (AGDLP, page Identité). Réplica Hyper-V prévue vers Paris (page Exploitation). Script : 11-New-EuroCorpFileShares (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. Disque de données

    Un second disque (VHDX) pour les données, formaté en NTFS, lettre D:. Jamais sur C:.

    Pas à pas.
    1. Hyper-V Manager → Settings de LON-FS01 → SCSI Controller → Hard Drive → Add → New : disque dynamique, 60 Go ou plus. (VM arrêtée ou à chaud sur SCSI.)
    2. Dans la VM : Disk Management → le nouveau disque apparaît « Offline » ou « Not initialized » → clic droit → Online → Initialize Disk (GPT).
    3. Clic droit sur l'espace libre → New Simple Volume : lettre D:, NTFS, étiquette « Data ».
    Pourquoi. Les données utilisateurs ne vivent pas sur le disque système : on peut le restaurer, le sauvegarder et l'agrandir sans toucher à Windows.
    Vérifier. Get-Volume -DriveLetter D : NTFS, bonne taille.
    Piège. Si tu as déjà activé la réplication Hyper-V, un disque ajouté après n'est pas répliqué : réintègre-le dans la configuration de la réplication.
  2. Joindre le domaine

    IP 172.17.30.10, DNS vers les contrôleurs, Add-Computer -DomainName eurocorp.lan, puis déplacer l'objet dans l'UO Serveurs.

    Pas à pas.
    1. IP fixe : 172.17.30.10 /24, passerelle 172.17.30.1, DNS 172.17.10.10 puis 172.17.20.10.
    2. Add-Computer -DomainName eurocorp.lan -Credential EUROCORP\Administrator -Restart.
    3. Après redémarrage, sur un DC : déplace l'objet ordinateur dans l'UO Serveurs : Get-ADComputer LON-FS01 | Move-ADObject -TargetPath "OU=Serveurs,OU=EuroCorp,DC=eurocorp,DC=lan".
    Pourquoi. Les droits NTFS s'appuient sur les groupes du domaine ; sans jonction, le serveur ne connaît pas les groupes DL_*.
    Vérifier. (Get-CimInstance Win32_ComputerSystem).Domain renvoie eurocorp.lan.
    Piège. Pas de jonction possible si le tunnel Londres–Bruxelles n'est pas monté : teste d'abord Test-NetConnection 172.17.10.10 -Port 389.
  3. Les groupes existent

    GG_Direction, DL_Direction_Modifier… créés à l'étape précédente.

    Pas à pas.
    1. Sur un DC : Get-ADGroup -Filter "Name -like 'GG_*' -or Name -like 'DL_*'" | Select Name.
    2. Si la liste est vide, retourne à la page Identité (UO et groupes AGDLP).
    Pourquoi. Les partages utilisent les groupes comme source d'autorisation : ils doivent exister avant les ACL.
    Vérifier. GG_Direction, GG_RH, GG_Finance, GG_IT et leurs DL_* sont listés.

Installation

  1. Installer les rôles
    PowerShell
    Install-WindowsFeature FS-FileServer, FS-DFS-Namespace, FS-Resource-Manager -IncludeManagementTools

    FS-Resource-Manager (FSRM) ajoute quotas de dossiers et filtres de fichiers.

    Pas à pas.
    1. PowerShell en administrateur : Install-WindowsFeature FS-FileServer, FS-DFS-Namespace, FS-Resource-Manager -IncludeManagementTools.
    2. Redémarre si demandé.
    Pourquoi. File Server partage, DFS Namespace donne un chemin unique, FSRM ajoute quotas et filtres de fichiers.
    Vérifier. Get-WindowsFeature FS-* : Installed.

Configuration

  1. Créer les dossiers et les partages
    PowerShell
    foreach ($d in "Direction","RH","Finance","IT","Commun") {
  New-Item -ItemType Directory -Path "D:\Data\$d" -Force | Out-Null
  New-SmbShare -Name $d -Path "D:\Data\$d" -FullAccess "EUROCORP\Admins du domaine" -ChangeAccess "EUROCORP\DL_${d}_Modifier"
}

    Chemin UNC : \\LON-FS01\Finance. Les permissions de partage et NTFS s'additionnent par le réseau : le droit effectif est le plus restrictif des deux. Mettre le partage large et régler finement en NTFS.

    Pas à pas.
    1. Lance le bloc ci-dessous : il crée D:\Data\Direction, RH, Finance, IT, Commun et un partage SMB par dossier.
    2. Le partage donne Contrôle total aux administrateurs et Modification au groupe local DL_service_Modifier.
    3. Chemin d'accès : \\LON-FS01\Finance.
    Pourquoi. Les droits de partage et NTFS se cumulent par le réseau : le plus restrictif l'emporte. On met un partage large et on contrôle finement avec NTFS.
    Vérifier. Get-SmbShare liste les cinq partages ; Get-SmbShareAccess -Name Finance montre les droits.
    Piège. Sur Windows Server 2025, le nom du groupe administrateurs dépend de la langue du système : adapte Admins du domaine / Domain Admins.
  2. Permissions NTFS par groupes
    PowerShell
    $acl = Get-Acl "D:\Data\Finance"
$acl.SetAccessRuleProtection($true,$false)      # coupe l'héritage
$r = New-Object Security.AccessControl.FileSystemAccessRule("EUROCORP\DL_Finance_Modifier","Modify","ContainerInherit,ObjectInherit","None","Allow")
$acl.AddAccessRule($r); Set-Acl "D:\Data\Finance" $acl

    Un refus explicite prime sur une autorisation ; une permission explicite prime sur une héritée.

    Pas à pas.
    1. Pour chaque dossier : clic droit → Properties → Security → Advanced → Disable inheritance → « Convert inherited permissions into explicit ».
    2. Retire les groupes inutiles (Users) et ajoute DL_Finance_Modifier avec « Modify ».
    3. Ajoute DL_Commun_Lecture en lecture sur Commun seulement.
    4. Ou applique le script ci-dessous.
    Pourquoi. AGDLP : les utilisateurs vont dans un groupe global, qui va dans un groupe local de domaine, qui reçoit la permission. Le jour où quelqu'un change de service, on change son groupe, pas l'ACL.
    Vérifier. Onglet Effective Access : un membre de GG_Finance a Modify sur Finance, un membre de GG_RH n'a rien.
    Piège. Un refus explicite prime sur une autorisation ; une permission explicite prime sur une héritée.
  3. Espace de noms DFS

    Un chemin unique indépendant du serveur : \\eurocorp.lan\Files. DFS Management → New Namespace → basé sur le domaine ; un dossier par service dont la cible pointe vers le partage. Pas de réplication DFS ici : une seule cible par dossier.

    Pas à pas.
    1. Ouvre DFS Management → New Namespace.
    2. Serveur : LON-FS01. Nom : Files. Type : Domain-based namespace (\\eurocorp.lan\Files).
    3. Dans le namespace → New Folder : un dossier par service, cible = \\LON-FS01\Finance etc.
    Pourquoi. DFS donne un chemin stable : si le serveur change, seuls les liens de cibles changent, pas les lecteurs réseau des utilisateurs.
    Vérifier. Depuis un poste, \\eurocorp.lan\Files\Finance s'ouvre.
    Piège. Pas de réplication DFS ici : une seule cible par dossier suffit.
  4. Quotas (facultatif)

    FSRM : modèle de quota par dossier avec seuil d'alerte. EFS chiffre des fichiers NTFS : sauvegarder le certificat et la clé privée, sinon les fichiers sont perdus.

    Pas à pas.
    1. Ouvre File Server Resource Manager → Quota Management → Quota Templates.
    2. Crée un modèle (par exemple 5 Go, avec alerte à 85 %) puis applique-le au dossier voulu.
    3. EFS (chiffrement) : exporte le certificat et la clé du compte, sinon les fichiers chiffrés sont perdus.
    Pourquoi. Un quota évite qu'un service remplisse tout le disque.
    Vérifier. Get-FsrmQuota liste les quotas.

Vérifications

  1. Lister les partages
    PowerShell
    Get-SmbShare
Get-SmbShareAccess -Name Finance
    Pas à pas.
    1. Get-SmbShare.
    2. Get-SmbShareAccess -Name Finance.
    Pourquoi. Un contrôle rapide avant de tester avec des comptes.
    Vérifier. Cinq partages visibles, droits conformes.
  2. Tester avec deux comptes

    Un membre de GG_Finance écrit dans Finance ; un membre de GG_RH est refusé. Le chemin DFS \\eurocorp.lan\Files\Finance s'ouvre depuis un poste.

    Pas à pas.
    1. Sur un poste du domaine, ouvre une session avec un compte de GG_Finance : net use Z: \\eurocorp.lan\Files\Finance, crée un fichier.
    2. Avec un compte de GG_RH : le même chemin donne « Access denied ».
    3. Note les résultats dans 09-Tests.
    Pourquoi. Un test de refus est aussi important qu'un test d'accès.
    Vérifier. L'écriture réussit pour Finance et échoue pour RH.
    Piège. Un groupe ajouté à l'utilisateur ne vaut qu'après une nouvelle ouverture de session (le jeton Kerberos est mis à jour).

2IIS et équilibrage de charge NLB (BRU-IIS01 / 02)

Deux serveurs web derrière une adresse virtuelle (172.17.10.20, intranet.eurocorp.lan). IIS est le serveur web de Microsoft, livré comme rôle de Windows Server ; NLB répartit les connexions entre les deux nœuds. Scripts : 12-Set-EuroCorpNlbHost, 13-New-EuroCorpNlb (page Scripts, à lancer d'abord avec -WhatIf).

Préparation

  1. Les deux VM sont dans le domaine

    BRU-IIS01 172.17.10.21, BRU-IIS02 172.17.10.22, DNS vers 172.17.10.10. Chaque nœud doit avoir une seule carte réseau pour simplifier.

    Pas à pas.
    1. BRU-IIS01 : 172.17.10.21, BRU-IIS02 : 172.17.10.22, DNS 172.17.10.10.
    2. Joins-les au domaine : Add-Computer -DomainName eurocorp.lan -Restart.
    3. Une seule carte réseau par nœud.
    Pourquoi. Un domaine commun permet d'administrer les deux nœuds avec un seul compte et de les placer dans la même UO.
    Vérifier. Get-ADComputer -Filter "Name -like 'BRU-IIS*'" renvoie deux objets.
  2. Choisir le mode NLB

    Unicast : tous les nœuds prennent la même adresse MAC ; sur Hyper-V il faut autoriser l'usurpation de MAC et les nœuds ne se parlent plus entre eux par cette carte. Multicast : MAC de groupe, nécessite que le réseau accepte ce type de trame. Décision à prendre avant de créer le cluster.

    Pas à pas.
    1. Unicast : tous les nœuds partagent la même adresse MAC. Sur Hyper-V, autorise l'usurpation de MAC sur la carte de chaque VM (voir plus bas) ; les nœuds ne se parlent pas entre eux par cette carte.
    2. Multicast : une adresse MAC de groupe ; le réseau doit accepter ces trames (pas évident sur un commutateur virtuel).
    3. Écris ton choix dans le rapport avec la raison.
    Pourquoi. Le mode se choisit à la création du cluster ; changer ensuite oblige à le recréer.
    Vérifier. Le choix est noté dans PLAN-REPRISE.md (point 4).
  3. Réserver l'adresse virtuelle

    172.17.10.20 est hors de la plage DHCP (.100–.199) : elle ne doit être attribuée à aucune machine.

    Pas à pas.
    1. Vérifie que 172.17.10.20 n'est utilisée par aucune machine : ping 172.17.10.20 sans réponse.
    2. Note-la dans le plan IP comme « VIP NLB ».
    Pourquoi. Cette adresse n'appartient à aucune carte avant la création du cluster : elle ne doit pas être donnée à une autre machine ni distribuée par DHCP.
    Vérifier. Aucune réponse au ping avant le cluster ; la plage .100–.199 du DHCP ne l'inclut pas.

Installation

  1. Installer IIS
    PowerShell
    Install-WindowsFeature Web-Server -IncludeManagementTools

    Ou Server Manager → Add roles and features → Role-based → Web Server (IIS). Rien d'autre à cocher : les modules (FTP, ASP.NET…) s'ajoutent après coup.

    Pas à pas.
    1. Sur chacun des deux nœuds : Install-WindowsFeature Web-Server -IncludeManagementTools.
    2. Ou Server Manager → Add Roles and Features → Role-based → Web Server (IIS) → Next jusqu'à Install.
    3. Ouvre http://localhost : la page IIS par défaut s'affiche.
    Pourquoi. IIS est le serveur web de l'intranet. Les modules supplémentaires (FTP, ASP.NET) s'ajoutent à la demande.
    Vérifier. Get-WindowsFeature Web-Server : Installed ; la page par défaut répond.
  2. Installer NLB
    PowerShell
    Install-WindowsFeature NLB -IncludeManagementTools

    Sur les deux nœuds.

    Pas à pas.
    1. Sur les deux nœuds : Install-WindowsFeature NLB -IncludeManagementTools.
    2. Vérifie la présence de la console : nlbmgr.exe.
    Pourquoi. NLB (Network Load Balancing) fait partager une adresse virtuelle entre plusieurs serveurs.
    Vérifier. Get-WindowsFeature NLB : Installed.

Configuration

  1. Un site avec son propre nom

    Ne pas déposer le contenu dans le site par défaut (C:\inetpub\wwwroot) : mauvaise pratique. IIS Manager → clic droit Sites → Add Website : nom, chemin physique en dehors de wwwroot, host name intranet.eurocorp.lan. Le host name permet plusieurs sites sur la même IP et le même port 80 : IIS lit l'en-tête Host.

    Pas à pas.
    1. Crée un dossier hors de wwwroot : New-Item -ItemType Directory C:\Sites\intranet et dépose-y une page index.html.
    2. IIS Manager → clic droit sur Sites → Add Website….
    3. Site name : intranet, Physical path : C:\Sites\intranet, Binding : HTTP, port 80, Host name : intranet.eurocorp.lan.
    4. Supprime ou arrête Default Web Site si le même port le gêne.
    Pourquoi. Le contenu dans le site par défaut mélange tout et casse les mises à jour. Le nom d'hôte permet plusieurs sites sur la même IP et le même port.
    Vérifier. http://intranet.eurocorp.lan depuis un poste affiche ta page (le DNS doit être en place).
    Piège. Même dossier et mêmes bindings sur les deux nœuds.
  2. Le nom dans le DNS

    Un enregistrement A intranet → 172.17.10.20 (l'adresse virtuelle). Pour les autres sites, des alias CNAME vers le nom du serveur : si l'IP change, une seule ligne est à corriger.

    Pas à pas.
    1. Sur un DC : Add-DnsServerResourceRecordA -ZoneName eurocorp.lan -Name intranet -IPv4Address 172.17.10.20.
    2. Pour d'autres sites : Add-DnsServerResourceRecordCName -Name wiki -HostNameAlias bru-iis01.eurocorp.lan -ZoneName eurocorp.lan.
    Pourquoi. L'utilisateur tape un nom, pas une adresse : le nom pointe vers l'adresse virtuelle, pas vers un serveur précis.
    Vérifier. Resolve-DnsName intranet.eurocorp.lan renvoie 172.17.10.20.
  3. Pool d'applications

    Un site = son pool (créé automatiquement). Identité par défaut ApplicationPoolIdentity ; un compte de domaine seulement si le site doit accéder à une ressource protégée.

    Pas à pas.
    1. IIS Manager → Application Pools : un pool par site (créé automatiquement).
    2. Clic droit sur le pool → Advanced Settings → Identity : ApplicationPoolIdentity par défaut.
    3. Utilise un compte de domaine seulement si le site doit accéder à une ressource protégée (partage, base).
    Pourquoi. Chaque site tourne dans son propre processus : une panne ou un bug dans un site n'arrête pas les autres.
    Vérifier. Le pool est « Started ».
  4. Contenu identique sur les deux nœuds

    Même dossier, même contenu : copie manuelle, DFS ou robocopy. NLB répartit les connexions, il ne synchronise pas les fichiers.

    Pas à pas.
    1. Copie le dossier du site sur le deuxième nœud : robocopy \\BRU-IIS01\c$\Sites\intranet C:\Sites\intranet /MIR.
    2. Crée le même site avec les mêmes liaisons sur BRU-IIS02.
    3. Change une ligne de la page sur chaque nœud (« Nœud 1 », « Nœud 2 ») pour pouvoir identifier qui répond pendant les tests.
    Pourquoi. NLB répartit les connexions, il ne synchronise pas les fichiers : deux nœuds différents donnent des résultats différents selon le serveur qui répond.
    Vérifier. http://172.17.10.21 et http://172.17.10.22 affichent le même contenu.
    Piège. Pour la production : DFS Replication ou un partage commun.
  5. MAC spoofing (unicast seulement)

    Settings de chaque VM → Network Adapter → Advanced Features → Enable MAC address spoofing.

    Pas à pas.
    1. Hyper-V Manager → Settings de BRU-IIS01 → Network Adapter → Advanced Features.
    2. Coche Enable MAC address spoofing. OK.
    3. Fais la même chose sur BRU-IIS02.
    4. Ou en PowerShell sur l'hôte : Set-VMNetworkAdapter -VMName BRU-IIS01 -MacAddressSpoofing On.
    Pourquoi. Hyper-V ne laisse sortir une trame que si son adresse MAC source est celle de la carte virtuelle. NLB unicast change cette adresse : sans ce réglage, tout est bloqué.
    Vérifier. Get-VMNetworkAdapter -VMName BRU-IIS01 | Select MacAddressSpoofing renvoie On.
    Piège. Les deux nœuds doivent être sur le même commutateur virtuel et il faut redémarrer la VM si le cluster ne se forme pas.
  6. Créer le cluster NLB

    Network Load Balancing Manager → New Cluster : hôte BRU-IIS01, interface du LAN, adresse virtuelle 172.17.10.20, mode choisi, règle de ports 80 (et 443). Puis Add Host to Cluster pour BRU-IIS02.

    Pas à pas.
    1. Sur BRU-IIS01 : lance Network Load Balancing Manager (nlbmgr) → clic droit sur « Network Load Balancing Clusters » → New Cluster.
    2. Host : BRU-IIS01 → Connect → choisis l'interface du LAN → Next.
    3. Host Parameters : priorité 1, IP dédiée du nœud. Next.
    4. Cluster IP Addresses → Add : 172.17.10.20 / 255.255.255.0.
    5. Cluster Parameters : le nom intranet.eurocorp.lan ; Cluster operation mode : Unicast (ou ton choix).
    6. Port Rules : garde (ou crée) la règle 80 (et 443), Affinity : None ou Single selon ton choix.
    7. Fais clic droit sur le cluster → Add Host To Cluster : BRU-IIS02.
    Pourquoi. Les deux nœuds partagent une IP virtuelle et se répartissent les connexions : si l'un tombe, l'autre continue.
    Vérifier. Dans le gestionnaire, les deux hôtes sont « Converged » (vert) ; ping 172.17.10.20 répond.
    Piège. Une erreur fréquente : une seule carte réseau mal choisie ou MAC spoofing oublié empêche la convergence.
  7. FTP (facultatif)

    Ajouter Web Server → FTP Server, clic droit sur le site → Add FTP Site : authentification Basic avec les comptes du domaine, autorisation EUROCORP\Domain Users en lecture/écriture. Sans SSL, identifiants et fichiers circulent en clair : labo seulement.

    Pas à pas.
    1. Ajoute le rôle : Install-WindowsFeature Web-Ftp-Server.
    2. IIS Manager → clic droit sur le site → Add FTP Site : adresse IP, port 21, SSL = Allow ou Required.
    3. Authentification : Basic ; Authorization : Allow, EUROCORP\Domain Users, Read/Write.
    4. Ouvre le port 21 et la plage passive dans le pare-feu.
    Pourquoi. Illustre la publication de fichiers par FTP.
    Vérifier. ftp intranet.eurocorp.lan : connexion avec un compte du domaine.
    Piège. Sans SSL, identifiants et fichiers circulent en clair : labo seulement.

Vérifications

  1. Chaque nœud répond seul

    http://172.17.10.21 et http://172.17.10.22 affichent la page.

    Pas à pas.
    1. Depuis un poste : http://172.17.10.21 puis http://172.17.10.22.
    2. Chaque page doit indiquer le nœud.

  2. L'adresse virtuelle répond

    PowerShell
    Resolve-DnsName intranet.eurocorp.lan
Invoke-WebRequest http://intranet.eurocorp.lan -UseBasicParsing | Select-Object StatusCode
    Pas à pas.

  3. La bascule

    Arrêter le site (ou la VM) d'un nœud : l'adresse virtuelle reste joignable. Noter le résultat dans 09-Tests.

    Pas à pas.

    2. Recharge http://intranet.eurocorp.lan : la page vient du nœud 2.
    3. Relance le nœud et note dans 09-Tests.
    Pourquoi. C'est le but de NLB : prouver que le service survit à la panne d'un nœud.

3Messagerie : Exchange Server et autorité de certification (BRU-EXCH01)

Exchange stocke les boîtes aux lettres dans des fichiers ESE (.edb plus journaux .log). Les certificats viennent d'une autorité interne (AD CS) installée sur un contrôleur de domaine, pas sur Exchange.

Préparation

  1. Machine et prérequis

    172.17.10.30, 16 Go de RAM, jointe au domaine. Disque séparé pour les bases (.edb) et un autre pour les journaux (.log) : jamais sur C: en production, compter 2 à 3 Go par boîte.

    Pas à pas.
    1. Crée BRU-EXCH01 avec 16 Go de RAM fixes, IP 172.17.10.30, jointe au domaine.
    2. Ajoute deux disques : un pour les bases (E:) et un pour les journaux (F:).
    3. Compte une marge de 2 à 3 Go par boîte aux lettres.
    Pourquoi. Exchange est très gourmand en mémoire et en disque ; séparer bases et journaux est la règle de base.
    Vérifier. Get-Volume montre C:, E:, F:.
    Piège. Avec 16 Go le serveur est juste : ne démarre pas d'autres VM lourdes en même temps.
  2. Préparer l'annuaire

    Compte membre de Schema Admins et Enterprise Admins. Depuis le média Exchange, sur un contrôleur ou le serveur :

    cmd
    Setup.exe /IAcceptExchangeServerLicenseTerms_DiagnosticDataOFF /PrepareSchema
Setup.exe /IAcceptExchangeServerLicenseTerms_DiagnosticDataOFF /PrepareAD /OrganizationName:"EuroCorp"
    Pas à pas.
    1. Connecte-toi avec un compte membre de Schema Admins et Enterprise Admins.
    2. Monte l'ISO d'Exchange. Dans une invite administrateur, depuis la racine du média : Setup.exe /IAcceptExchangeServerLicenseTerms_DiagnosticDataOFF /PrepareSchema.
    3. Puis Setup.exe /IAcceptExchangeServerLicenseTerms_DiagnosticDataOFF /PrepareAD /OrganizationName:"EuroCorp".
    4. Laisse la réplication AD se faire (quelques minutes entre sites).
    Pourquoi. Exchange étend le schéma de l'annuaire et crée ses groupes et conteneurs : c'est irréversible, donc à faire avec méthode.
    Vérifier. Get-ADObject "CN=ms-Exch-Schema-Version-Pt,CN=Schema,CN=Configuration,DC=eurocorp,DC=lan" -Properties rangeUpper renvoie une valeur (version du schéma).
    Piège. Ces commandes modifient la forêt : fais-les après une sauvegarde de l'état système du DC (ou un point de contrôle des VM).
  3. Installer l'autorité de certification d'abord

    Sinon, certificats auto-signés partout.

    PowerShell sur BRU-DC01
    Install-WindowsFeature AD-Certificate, ADCS-Web-Enrollment -IncludeManagementTools
Install-AdcsCertificationAuthority -CAType EnterpriseRootCA -CACommonName "EUROCORP-CA" -KeyLength 2048 -HashAlgorithmName SHA256 -Force
Install-AdcsWebEnrollment -Force
    Pas à pas.
    1. Sur BRU-DC01 : Install-WindowsFeature AD-Certificate, ADCS-Web-Enrollment -IncludeManagementTools.
    2. Install-AdcsCertificationAuthority -CAType EnterpriseRootCA -CACommonName "EUROCORP-CA" -KeyLength 2048 -HashAlgorithmName SHA256 -Force.
    3. Install-AdcsWebEnrollment -Force pour l'interface web /certsrv.
    Pourquoi. Une autorité interne délivre les certificats d'Exchange et d'IIS : plus d'avertissements dans le navigateur, et le TLS fonctionne comme sur le terrain.
    Vérifier. certutil -ping répond ; http://bru-dc01/certsrv s'ouvre.
    Piège. En production on ne met pas l'AC racine sur un contrôleur de domaine ; en labo, c'est accepté.

Installation

  1. Prérequis logiciels d'Exchange
