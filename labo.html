Le plan

Un seul réseau, un seul domaine, des noms qui disent le rôle

Chaque TP du cours a été monté avec son propre domaine et son propre plan d'adressage. Pour les rejouer chez soi sans tout reconstruire à chaque fois, le site les transpose tous sur un seul lab : le domaine orion.local, sur le réseau 172.16.50.0/24. Quand un module donne une adresse ou un nom de machine, c'est celui-ci.

Ne pas tout allumer

Avec 8 Go par serveur Windows, tout le lab demande plus de 100 Go de mémoire. On n'allume que le socle (SRV-AD01, le client) et les machines du module en cours. Pour un lab qui ne sert qu'à apprendre, 4 Go par serveur suffisent dans la plupart des modules.

Le cluster du module Stockage gagne à séparer ses flux : battement de cœur sur 172.16.51.0/24, iSCSI sur 172.16.52.0/24, chacun sur son propre commutateur privé. Le lab Packet Tracer du module CCNA, lui, est un réseau simulé à part (10.2.0.0/16).

Étape 0

Le réseau du lab sur l'hôte Hyper-V

Un commutateur privé isole le lab mais lui coupe Internet (mises à jour, paquets Linux, Docker). Un commutateur interne avec du NAT sur l'hôte donne le meilleur des deux : les VM sortent sur Internet, mais personne ne peut les joindre de l'extérieur.

PowerShell (administrateur) — sur l'hôte Hyper-V, une seule fois
New-VMSwitch -Name "LABOPS" -SwitchType Internal
New-NetIPAddress -InterfaceAlias "vEthernet (LABOPS)" -IPAddress 172.16.50.1 -PrefixLength 24
New-NetNat -Name "LABOPS-NAT" -InternalIPInterfaceAddressPrefix 172.16.50.0/24
New-Item -ItemType Directory C:\PARENT, C:\VM\LABOPS

Vérifier

Le NAT est-il en place ?

PowerShell — hôte
Get-NetNat
Get-NetIPAddress -InterfaceAlias "vEthernet (LABOPS)" -AddressFamily IPv4

Sortie attendue

Name                             : LABOPS-NAT
InternalIPInterfaceAddressPrefix : 172.16.50.0/24
Active                           : True

Windows n'accepte qu'un seul réseau NAT de ce type : si New-NetNat échoue, un ancien NAT existe déjà (Get-NetNat, puis Remove-NetNat). Depuis une VM, tester ping 172.16.50.1 puis ping 1.1.1.1.

À retenir

Commutateur interne LABOPS + l'hôte en 172.16.50.1 + New-NetNat : les VM du lab sortent sur Internet par l'hôte, et restent invisibles depuis le réseau de la maison.

Construire

Monter le lab dans l'ordre

Chaque étape s'appuie sur la précédente. Les cases se cochent dans ce navigateur : c'est ta progression sur le lab, à côté de celle des modules.

Lab guidé

Le lab Orion, du disque parent au dernier service

Objectif : un environnement complet et reconstructible, qui sert de terrain à tous les modules Windows et de supervisionPoint de départ : un PC Windows 11 Pro ou Windows Server avec Hyper-V, 32 Go de mémoire conseillés, une ISO Windows Server 2025Durée : à étaler sur tout le parcours

  1. Réseau et disque parent — étape 0 ci-dessus, puis l'image Sysprep : module Hyper-V, chapitre Sysprep.

  2. SRV-AD01 — réseau, nom, forêt orion.local, OU, groupes, utilisateurs : Windows Server. Vérifier : Get-ADDomain répond.

  3. DHCP sur SRV-AD01 — étendue .100–.199, options 3, 6 et 15 ; le client obtient une adresse et joint le domaine.

  4. SRV-AD02 — second contrôleur de domaine ; vérifier la réplication (repadmin /replsummary).

  5. SRV-FILE01 — partages par service, droits NTFS, espace de noms DFS, GPO : Windows Server.

  6. SRV-WEB01 — IIS, deux sites, FTP : IIS.

  7. SRV-SQL01 — instance sous gMSA, port fixe, sauvegardes : SQL Server.

  8. Services avancés, au choix : RDS, Exchange, SharePoint, DPM, cluster — chacun dans son module.

  9. Supervision et support — SRV-ZBX01 surveille tout ce qui précède, SRV-REDMINE01 recueille les tickets : Zabbix & Windows, Redmine.

Prouver

La grille de compétences

Cocher « chapitre acquis » est une déclaration ; ces épreuves sont des preuves. Chacune se fait sur le lab, sans regarder le cours, et se vérifie par une commande dont le résultat ne ment pas. C'est aussi ce que tu pourras raconter en entretien, exemples à l'appui.

Lab guidé

Ce que le lab prouve que tu sais faire

Objectif : valider chaque compétence par un résultat observable, pas par une lecturePoint de départ : le lab Orion monté jusqu'à l'étape correspondanteDurée : au fil des modules

  1. Réseau — depuis CLIENT-WIN11, expliquer chaque ligne de ipconfig /all et prouver le chemin : Test-NetConnection srv-file01 -Port 445 → True.

  2. DNS — créer l'alias intranet vers SRV-WEB01 ; Resolve-DnsName intranet.orion.local répond avec le CNAME.

  3. Active Directory — créer en script 10 utilisateurs depuis un CSV ; (Get-ADUser -Filter * -SearchBase "OU=ORION-DPT,DC=orion,DC=local").Count les compte.

  4. GPO — une stratégie qui mappe un lecteur réseau ; sur le client, gpresult /r la liste et le lecteur apparaît.

  5. Droits — un utilisateur de Comptabilité ouvre son dossier et pas celui du Management ; expliquer le droit effectif (partage + NTFS).

  6. Dépannage — un camarade casse une chose (DNS du client, passerelle, pare-feu, service arrêté) ; la retrouver en moins de 10 minutes avec la méthode du module Dépannage réseau.

  7. Sauvegarde — supprimer un fichier sur SRV-FILE01 et le restaurer (Windows Server Backup ou DPM), chronomètre en main.

  8. Supervision — arrêter le service IIS de SRV-WEB01 : Zabbix lève l'alerte, puis le redémarre seul (module Supervision).

  9. Reconstruire — supprimer SRV-FILE01 et le recréer entièrement par script en moins de 30 minutes : les scripts sont la documentation.
